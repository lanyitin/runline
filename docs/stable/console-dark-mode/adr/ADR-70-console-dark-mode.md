# ADR-70 Console 在 token 層跟隨系統提供深色模式

狀態：已核可（2026-10-29）；第 4 點「淺色 token 的值不變」有限定例外，見 [WI-74](../work-items/WI-74-light-boundary-contrast.md)（僅邊框與焦點框兩個 token）。補充 [ADR-015](../../pipeline-engine/adr/ADR-015-console-frontend.md)；不修訂任何 stable 決策。回答：Console 如何提供深色模式，以及深色的設計方向與驗證標準。

## 背景

Console 只有淺色主題。WI-33 寫過「可選深色」但未實作。使用者要求跟隨系統設定，涵蓋所有頁面。視覺元件的顏色幾乎都引用設計 token，深色的差異可以集中在 token 層。

## 決策

1. **只跟隨系統**：作業系統或瀏覽器偏好深色時用深色，否則用淺色；系統設定改變時畫面即時跟著變，不需重新載入。不提供頁面內開關，不儲存偏好。
2. **在 token 層提供深色值**：同一組 token 名稱在深色下有另一組值；元件不為深色另寫樣式，也不自訂顏色。token 檔註明哪些值屬於哪個主題。
3. **瀏覽器內建控制項**（捲軸、表單控制項、選單等）宣告同時支援淺色與深色，使其跟著主題。
4. **深色色票方向**：
   - 表面由深藍灰組成，層級靠表面明度由低到高區分（背景最深、卡片較亮、浮層更亮），不靠大面積陰影。
   - 強調色保留藍色系，但取較亮的色階，使其在深色底上對比足夠；按鈕與徽章的底色與文字組合各自重新計算對比。
   - 狀態色（成功、危險、警告、執行中、中性）維持語意不變；淡色底（tint）改為低明度的有色底，文字用較亮色階。顏色仍不是唯一標示。
   - 淺色 token 的值不變。
5. **log 檢視的終端面板**：兩種主題都維持深色，且改為引用 token，不再寫死顏色；深色主題下與周圍表面仍有可辨識的邊界。
6. **對比度標準**：一般文字與背景至少 4.5:1，大字、圖示與元件邊界至少 3:1，焦點框在兩種主題下都清楚可見。以自動化檢查所有文字與背景 token 配對，淺色與深色各一份。
7. **驗證標準**：每個路由在深色下可讀、無明顯的淺色殘留（白底區塊、深色字落在深色底）；既有的真實瀏覽器 e2e 可以模擬系統偏好，檢查頁面實際套用了深色 token。

## 取捨

| 選項 | 優點 | 缺點 |
|---|---|---|
| 採用：只跟隨系統，token 層覆蓋 | 沒有新介面與儲存；改動集中；元件不用改 | 使用者無法在不改系統設定的情況下單獨切換 Console |
| 手動開關加記憶 | 使用者可單獨控制 | 需要偏好儲存、切換介面、初次載入閃爍處理，使用者未要求 |
| 逐元件加深色樣式 | 每個元件可細調 | 重複、易漏、與「元件不自訂顏色」的現行規則衝突 |

## 後果

- 之後新增的元件只能引用 token，不得自訂顏色，否則深色下會破版。
- 設計系統多一組深色值，新增 token 時兩種主題都要給值，並通過對比度檢查。
- 若日後需要手動切換，可在既有的 token 覆蓋機制上增加，另開 ADR。
