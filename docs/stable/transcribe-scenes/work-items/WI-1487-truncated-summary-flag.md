# WI-1487 被截斷的摘要記錄為被截斷，並在下一層的輸入中標明

本文回答：被截斷的摘要如何記錄，以及讀取它的下一層模型如何得知。狀態：已核可（2026-10-18）。相依：WI-1486。決策見 [ADR-079](../adr/ADR-079-truncated-summary-is-kept-and-flagged.md)。儲存庫：T。

## 行為與驗收條件

1. **何時算被截斷**：
   - 欄位固定的層（場景層、中間彙整）：結束原因為截斷，且（依 [WI-1486](WI-1486-scene-summary-field-block-only.md) 的解析）四個欄位沒有全部完整；
   - 散文層（片段層）：結束原因為截斷。
   - 四個欄位都完整時不算被截斷，不標示。
2. **記錄**：片段摘要與場景摘要各有「被截斷」屬性，與「是否缺少」並列；舊 run 沒有此屬性，視為未被截斷。
3. **照常保存**：被截斷的摘要採用，不重試（沿用現行規則）。
4. **告知下一層**：任何請求的輸入包含被截斷的摘要時，pipeline 在該段摘要旁加一句簡短、平實的英文，說明這段摘要被截斷、可能不完整。標示由 pipeline 加上，不依賴模型。適用：
   - 場景層以片段摘要為輸入；
   - 場景彙整與全片摘要以場景摘要為輸入；
   - 翻譯附上的場景摘要。
5. **提示的對應規範**：接收摘要的各層預設提示說明，帶有被截斷標示的輸入只可使用其中明確寫出的內容，不推測缺少的部分，也不在回答中提到截斷。
6. **可觀測**：階段結果行與 RUN SUMMARY 列出各層被截斷的摘要數；HTML 報告顯示該摘要被截斷；既有的摘要 view 含此屬性。
7. **不計入及早止損**：摘要被截斷不累計連續失敗。
8. 其餘行為不變（重試、降級、取樣參數、生成上限）。

## 架構約束

- 不改 Engine；schema 只增不改，既有資料不刪、不改；舊 run 照常讀得出來。
- 嚴格 TDD；測試以假服務重現：場景層截斷在第二個欄位（標示）、截斷但四個欄位完整（不標示）、片段層截斷（標示）、下一層請求含標示的字樣、續跑沿用被截斷的摘要時標示仍在、舊 run 沒有屬性。
- 標示的英文措辭與提示規範的措辭由 tdd-coder 擬定，回報時列出完整文字，供架構師與量測使用。
