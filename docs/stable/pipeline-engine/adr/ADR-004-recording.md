# ADR-004 錄製只用於產生 metadata 提案

狀態：已核可（2026-10-05）。回答：錄製做什麼、不做什麼，以及錄製時 metadata 的限制如何處理。

## 背景
開發人員難以手寫完整的限制；錄製實際 IO 可降低門檻。若錄製時 metadata 的限制照常生效，pipeline 在第一次嘗試未宣告的 IO 時即被拒絕而失敗，一次執行只能發現一個缺口，無法產生完整提案，也改變了 pipeline 的行為。

## 決策
- 只有開發入口提供錄製，可選擇開啟，預設關閉；Engine 上的 run 一律不錄製。
- 錄製發生在 context 層，記錄整個 run 的檔案、網路連線、外部行程動作。事件跨越 class loader 邊界時只使用 JDK 內建型別（[05](../05-ipc.md)）。
- 錄製模式暫時放寬 metadata 宣告的限制：檔案範圍與讀寫、網路範圍、外部行程範圍不受宣告限制，所有動作都被允許並記錄，使 pipeline 的行為與不受限制時相同。
- 下列邊界在錄製模式仍然生效，因為它們是隔離的底線，不屬於 metadata 宣告：
  - 檔案動作只能發生在 pipeline 共享目錄與 run 私有目錄之內；絕對路徑、相對路徑跳出範圍、符號連結逃逸一律拒絕（[ADR-009](ADR-009-file-scopes.md)）。
  - 磁碟用量上限仍然生效（[WI-11](../work-items/WI-11-workspace-directories.md)）。
  - 被拒絕的邊界違規同樣被記錄，但不納入提案。
- 錄製模式在輸出中明確標示，並說明限制已放寬、此次執行不代表一般模式下的結果。
- 事件記錄動作類別、目標、讀寫性質與發生順序：
  - 檔案：使用的是哪一種目錄（共享或私有）、相對位置與讀寫性質（讀取、列出、查詢存在為讀；寫入、刪除為寫）；不記錄主機上的絕對路徑，也不記錄檔案內容。
  - 網路：目標主機與埠號；不記錄傳輸的內容。
  - 外部行程：被執行的指令（第一個元素）；不記錄引數與輸出，因其可能含機密。
- 事件量有上限；超過上限後改以聚合方式保存，不使錄製耗盡記憶體，也不使提案遺漏任何用過的範圍。
- 錄製結果可轉換成 metadata 提案：
  - 檔案：用過的目錄範圍與讀寫（任何寫入或刪除即為可寫）。
  - 網路：實際使用過的主機名稱（依 [ADR-010](ADR-010-access-allow-list-matching.md)，不分大小寫、不含埠號）。
  - 外部行程：實際執行過的指令名稱。
  - 沒有使用過的類別，提案為「不允許」（空的允許範圍），而不是「不限制」。
- 共享資源在初始化階段依宣告取得，不由錄製推導；參數與 trigger 也不在提案內。
- 提案以人可讀、可直接對照 pipeline 宣告的文件呈現，註明其涵蓋限度；由開發人員檢視後自行採用，系統不自動修改 pipeline。
- 提案採用後，以一般模式用相同輸入再執行同一 pipeline，不因 metadata 限制而失敗。
- 錄製資料不用於重放或 mock。

## 取捨
- 得到：一次執行即可得到完整提案；錄製不改變 pipeline 的行為；貼近實際行為的限制。
- 失去：錄製模式與一般模式的限制不同，需要清楚標示；只涵蓋走過的路徑，提案可能過窄或過寬。
- 失去：錄製發生在 context 層，pipeline 直接使用 JDK 的 IO 類別時無法錄製；這類 IO 只能由靜態分析的 unsafe 判定呈現。

被否決的做法：錄製時限制照常生效（一次只能發現一個缺口，且改變行為）；另外再執行一次不受限制的路徑（同一 pipeline 執行兩次，有副作用者不適用）。

## 後果
- 事件格式保持類別、目標、讀寫性質這幾項通用語意，日後若做重放可再擴充。
- context 需要支援不受宣告限制的模式與事件輸出，且不改變 Engine 的行為；Engine 沒有任何開啟錄製的途徑。
- 提案縮小網路與外部行程的範圍後，原本因「未限制」被判 unsafe 的 pipeline 可能成為 safe（[ADR-002](ADR-002-context-and-unsafe.md)）。
