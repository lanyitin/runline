# WI-1433 Console 看得到影片摘要與送給模型的畫面依據

本文回答：使用者在 Console 如何讀到完整的影片摘要，以及如何知道送給模型核對的是哪幾張畫面、模型看到了什麼。狀態：已核可（2026-10-13）。相依：WI-1422（已完成）、WI-1432。儲存庫：T（runline-transcribe）。

## 背景與限制

- `result` view 已有影片摘要欄，但 view 機制的儲存格是純文字、換行不保留（[WI-1422](WI-1422-transcribe-views.md) 的限制），長摘要難讀。
- 現行資料模型不存圖片（[06-data-model.md](../06-data-model.md)、需求第 9 條），已存的是每張畫面的時間點與一句畫面觀察。
- view 機制只有表格，沒有圖片儲存格。顯示圖片本身需要新的儲存與 Engine／Console 能力，不在本項範圍；需要時另開 ADR 取代「不保存圖片」。

## 行為與驗收條件（不含圖片本身）

1. **摘要可讀**：新增 view `summary`，參數 `run`（必填）。摘要依段落拆成多列（一列一段，帶段序），使換行在表格中不丟失；最上方一列為整部影片摘要，其後為各 VAD-A 組的摘要（若資料庫有記錄）；沒有摘要時回空，不報錯。`runs` 的影片檔可鑽取到此 view，與鑽取到階段的方式並列。
2. **畫面依據**：新增 view `frames`，參數 `run`（必填）與選填的條目序號。每張送給模型的畫面一列：條目序號、條目起訖（時:分:秒）、畫面時間點（時:分:秒，讓使用者能在影片中跳到該處）、模型對該畫面的一句觀察、該條目核對前後的文字。
3. 兩個 view 只讀、不選取 `exchange.prompt`、`exchange.response` 與機密；資料量大的 run（數千條目）在 30 秒內完成。
4. 依 WI-1422 的驗收方式驗證：涵蓋摘要缺少、多段摘要、某條目沒有畫面、降級的條目；jar 上傳到 Engine 後每個 view 實際讀取一次；README 與 runbook 的 view 清單同步（runbook 位於 runline，回報後由文件工作項處理）。

## 架構約束

- 不新增儲存圖片或音訊；不改變既有 view 的欄位與值（穩定契約）。
- 若 group 層級的摘要目前沒有被記錄，只在 view 中呈現已記錄的內容，並回報缺口，不在本項擴充記錄。
- 薄 jar 約束、嚴格 TDD、不使用 Stub 或 Mock，與其他 T 項相同。
