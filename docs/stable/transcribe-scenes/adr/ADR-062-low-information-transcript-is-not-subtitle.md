# ADR-062 低資訊量的轉錄文字不是字幕

本文回答：轉錄模型對非語言發聲只回出重複的語助詞時，pipeline 如何判定、處理，以及如何影響來源語言與 run 的結果。狀態：已核可（2026-10-15）。補充 [ADR-059](ADR-059-truncated-chunk-is-content-not-outage.md) 與 [ADR-061](ADR-061-repetition-penalties-on-loops.md)，不取代它們。

## 背景

- 實機測試（run 17，2688 至 2868 秒，內容為呻吟聲）：帶懲罰的重試救回 4 個被截斷片段中的 2 個，救回的文字仍是「嗯、啊、啊、啊……」的重複，只是較短。
- 轉錄模型把這段標為中文，於是：
  - 來源語言被判成中文，來源 SRT 以 `.zh.srt` 寫出，與繁體中文 SRT 逐位元組相同；
  - 原本會以 NO_TRANSCRIPT 失敗的 run 變成「降級完成」，影片旁留下兩份內容是「啊啊啊」的字幕檔，掃描時該影片被標記為已處理。
- 這是 ADR-061 的副作用：懲罰重試讓模型「停得下來」，但不保證文字有資訊。
- 另有一個觀察：RUN SUMMARY 的降級括號只列潤飾、摘要、翻譯，轉錄失敗的片段不在其中，加總對不起來。

## 決策

1. **低資訊量判定**：轉錄成功（含重試救回）的文字，若幾乎全由少數幾種字元的重複構成，判為低資訊量。判定與語言無關，不依賴詞典。判定的門檻是參數，預設值由實機資料決定（見待確認問題）。
2. **處理**：低資訊量的片段與「沒有取得文字」同等對待：不送對齊、沒有條目、計入降級與 `transcribeFailed`，原因另列為低資訊量；EXCHANGE 保留原文，log 列出片段與原因。它不計入及早止損。
3. **短而真實的內容不受影響**：判定要同時考慮文字長度與重複程度；單獨一句「はい」或「うん」這類短回應不得被丟棄。
4. **全部失敗才失敗（沿用 ADR-059 決策 4）**：有語音的片段全部沒有可用文字（含低資訊量）時，run 以 NO_TRANSCRIPT 失敗，訊息含各原因的片段數。
5. **來源語言只由被採用的片段決定**：被判為低資訊量的片段不參與語言投票。
6. **可觀測**：結果行與 RUN SUMMARY 的轉錄失敗原因多一欄低資訊量；RUN SUMMARY 的降級括號納入轉錄階段，使各階段加總等於總數。

## 取捨

- 得到：呻吟、笑聲、呼吸聲等內容不再產出看似正常的垃圾字幕檔，也不污染來源語言判定；run 結果與實際情況一致。
- 失去：
  - 判定有誤判風險：以重複為主的真實台詞（例如連續的「はいはいはい」）可能被丟棄。以決策 3 與門檻參數緩解，並在成品字幕核對時抽查。
  - 沒有字幕的片段不會被補救；與 ADR-059 相同，維持「不拆半重試」。
- 不採用：以語言標示與使用者設定的語言不符來攔截。模型的語言標示在這類內容上不可靠，且 `asrLanguage` 在對話路徑無法生效。

## 後果

- 新工作項 [WI-1466](../work-items/WI-1466-low-information-transcript.md)。
- ADR-059 的決策 2 補上「低資訊量視同沒有文字」；其餘不變。

## 待確認問題

- 門檻的預設值：需要實機的正常對話片段與呻吟片段的文字樣本來定，避免誤判真實台詞。run 17 的四個片段文字與 run 13、16 的正常對話可作為樣本；其他影片的樣本由使用者在成品字幕核對時提供。影響：預設值過嚴會丟台詞，過鬆則垃圾字幕仍出現。
