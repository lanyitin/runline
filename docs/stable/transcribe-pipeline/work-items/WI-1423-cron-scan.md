# WI-1423 cron 掃描模式

本文回答：`file` 為空時，pipeline 如何找出並處理一部尚未產生字幕的影片。狀態：已核可（2026-10-12）。相依：WI-1420。儲存庫：runline-transcribe。

## 背景

見 [ADR-040](../adr/ADR-040-cron-scan-mode.md)。

## 行為與驗收條件

1. `file` 為選填；為空（或未提供）即掃描模式；有值時行為與現在完全相同（含 ADR-039 的字幕輸出）。既有的參數驗證在掃描模式照常執行，`file` 的路徑規則只套用於有值時。
2. 新增參數 `scanExtensions`（預設 `mp4,mkv,mov,m4v,webm`，以逗號分隔，不分大小寫）、`scanMinAgeSeconds`（預設 600）、`scanMaxAttempts`（預設 3）；不合法者在 `intake` 階段以既有的參數錯誤方式失敗並指出參數名稱，不含值以外的內容。
3. 候選條件（全部成立才是候選），各以真實檔案系統（暫存目錄）逐條驗證：
   1. 一般檔案；不跟隨符號連結（符號連結的檔案與目錄都不列入）；路徑中任一段不以點開頭；
   2. 副檔名在允許清單中；
   3. 修改時間距現在至少 `scanMinAgeSeconds`；
   4. 同目錄沒有名為「影片檔名_zh-TW.srt」的路徑（檔案、目錄、符號連結都算已存在）；
   5. 所在目錄可寫，不可寫者排除；
   6. 該檔案（相對路徑加上相同的檔案大小與修改時間）結果為 `failed` 的 run 少於 `scanMaxAttempts` 次；`stopped` 與被中斷的 run 不計；檔案大小或修改時間改變即重新計數。
4. 挑選：候選依修改時間由舊到新、相同時依路徑排序，取第一部；其後的階段、檔名規則與輸出與指定 `file` 的 run 完全相同，`run.file` 記錄所選的相對路徑。
5. 沒有候選時：run 立即成功結束，結果說明為專用的「無待處理」分類，不進入 `audio` 以後的階段，不寫任何檔案；run 紀錄與 log 仍存在。
6. run 紀錄新增影片檔的大小與修改時間；這是前向、冪等、於 run 開始時套用並記錄結構版本的遷移；指定 `file` 的 run 也記錄。
7. 掃描上限：最多檢視一萬個檔案（常數，不設參數）；超過時以已檢視的為準，log 標示被截斷。
8. log：每次掃描記錄檢視總數、候選數與各排除原因（副檔名、太新、已有字幕、目錄不可寫、失敗達上限、符號連結、隱藏）的計數；不在 log 中列出收件根目錄的絕對路徑。
9. 掃描只讀：除了所選影片的字幕輸出之外，不在收件根目錄寫入、刪除或改名任何檔案。
10. 序列化前提：以真實 Engine 驗證，兩個 cron run 同時被建立時，第二個在第一個完成並寫出字幕後才開始掃描，且不會選到同一部（資源容量 1）。
11. README 與 runbook 相關小節（參數表、掃描規則、無待處理、排錯）寫成最新規則；runbook 位於 runline 儲存庫，需要改動的項目回報，由 WI-1424 處理。

## 架構約束

- 候選的判定不得改變指定 `file` 時的任何行為；webhook 仍必須提供 `file`（既有的 trigger 驗證不變）。
- 不新增常駐行程、不新增寫入位置；薄 jar 約束不變。
- 測試不使用 Stub 或 Mock；用真實檔案系統與真實 SQLite；嚴格 TDD。
