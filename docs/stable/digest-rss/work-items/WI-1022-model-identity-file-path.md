# WI-1022 模型身分比對接受以檔案路徑回報的模型

狀態：已核可（2026-10-10）。回答：要達成什麼行為，使 digest-rss 能對以檔案路徑回報模型的服務（Lemonade）正常判定。依據 [ADR-028](../adr/ADR-028-model-identity-file-path.md)。

**工作的儲存庫：** 外部 pipeline 專案 `runline-digest-rss`（與 runline 同層的目錄）。runline 儲存庫只更新上線手冊的對應排錯列。

## 目標

模型呼叫的回應若把模型回報為檔案路徑，且其最後一段檔名去掉 `.gguf` 後等於 `readerModel`，視為同一個模型，run 繼續進行；其他不符的情況仍使 run 失敗。

## 驗收條件

1. 回報值與請求的 id 逐字相同：相符，行為與現在一致。
2. 回報值是檔案路徑，最後一段檔名去掉 `.gguf` 等於請求的 id：相符，run 繼續，判定與摘要都可完成。
3. 回報值是檔案路徑，但檔名（去掉 `.gguf`）不等於請求的 id：不符，run 失敗，丟棄這次 run 的數字，訊息仍列出請求值與回報值。
4. 回報值是不同的模型名稱（非路徑）：不符，行為與現在一致。
5. 回報值只是請求 id 加上 `.gguf`、沒有路徑：相符。
6. 量化版本不同（檔名中的量化標記不同）：不符。
7. 判定階段與摘要階段使用同一個規則定義，行為一致。
8. `readerModel` 的格式與長度限制不變。
9. 使用一個真的在 port 上監聽、以路徑格式回報模型的 Fake 服務，在打包的真實 Engine 上通過；Fake 同時涵蓋第 3、4 條的不符情況。
10. 對真實的 Lemonade 做一次只讀的契約檢查（只送最小請求、不標記任何文章）：回報的格式符合第 2 條。此項由使用者在其環境執行（屬 WI-1017），結果回報。
11. 上線手冊的對應排錯列說明這種格式及其被接受的條件。

## 架構約束

- 12-Factor：不新增設定項；規則是程式行為。
- 單一事實來源：比對規則只定義一處。
- 不改 Engine、core 與 devkit 的行為。
- 測試的外部服務用真的在 port 上監聽的 Fake，不用 mock 或 stub。

## 阻擋與前提

- 無相依的工作項。
- 第 10 條需要使用者的 Lemonade 環境。
