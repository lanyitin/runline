# WI-1439 兩個 VAD 的機率加權合併與分段

本文回答：pipeline 如何使用兩份 VAD 機率做分段。狀態：已取代，不派工（[WI-1440](WI-1440-denoise-before-vad.md)、[ADR-046](../adr/ADR-046-denoise-before-vad.md)；保留供日後參考）。相依：WI-1438（可行性關卡通過）、WI-1434、WI-1435。儲存庫：T（runline-transcribe）。

## 行為與驗收條件

1. **參數**：開關 `dualVad`（預設開啟）、TEN 工具的命令與模型路徑（部署層設定，比照 silero 工具）、silero 與 TEN 的權重（預設 0.3 與 0.7）、合併機率的開始門檻與結束門檻（結束門檻為獨立參數）。參數名稱由實作者提案、架構師核可，寫入入口文件與 runbook（單一寫處）。門檻預設值依離線實驗（0.3／0.7 加權、0.1 秒格子、arr 影片弱真值）起算：開始門檻 0.35、結束門檻 0.25（應涵蓋區間被涵蓋 64.7%、雜音區間被涵蓋 13.0 秒、50 段）；較保守的 0.35／0.30（57.3%、7.2 秒）與 0.45／0.40（43.2%、3.6 秒）作為管理員調整的參考，數據見 [ADR-045](../adr/ADR-045-dual-vad.md) 背景。
2. **合併**：兩份機率各自平均到 0.1 秒的格子，逐格加權相加得到一份合併機率；VAD-A、VAD-B 沿用 ADR-038 的判定，其餘分段規則（最長段、最低能量切開）不變。
3. **關閉時**：`dualVad=false` 的 run，行為與之前完全相同，不呼叫 TEN 工具。
4. **失敗**：開啟時 TEN 工具未設定、不存在或執行失敗，run 以 `CONFIGURATION` 失敗並指出原因，不靜默退回單一 silero。
5. **紀錄與 log**：RUN SUMMARY 與分段 log 增加兩個偵測器各自的區間數與合併後的區間數與涵蓋比例；資料庫的 run 層級記錄兩個工具的版本與是否啟用（使用下一個可用的結構版本；與 WI-1436 同時進行時，版本號由後完成者依序取用）。
6. **驗證**：以 `orig.wav` 與 homelab-deployer 實驗得到的兩份機率作為固定輸入資料，驗證合併後的區間與離線實驗以相同權重與門檻得到的區間一致；涵蓋雜音區間與弱真值區間的測試資料見 ADR-045 背景；另涵蓋：單一偵測器工具回空、兩者網格不對齊、`dualVad=false`、TEN 工具缺少、權重為 0 與 1 的極端值。
7. **下游**：轉錄階段對新增的段落一視同仁；`language None` 與跨語言短回答的處理沿用 [ADR-044](../adr/ADR-044-asr-coverage-sweep.md) 的幻覺過濾（WI-1436）。WI-1436 尚未完成時，`language None` 沿用現有的「無語音」處理。
8. 對真實 Engine 與 Lemonade 的驗證由 arr 上的下一次 run 完成。

## 架構約束

- 不改變條目時間不變式（ADR-038 決策 3、4）、不存放音訊。
- 薄 jar、嚴格 TDD、不使用 Stub 或 Mock。
