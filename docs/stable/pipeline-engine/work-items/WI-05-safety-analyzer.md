# WI-05 靜態分析與 safe／unsafe 判定

目標：給定 jar 與白名單，不執行程式碼即回傳安全判定、原因與依賴路徑。

狀態：已核可（2026-10-05）。相依：WI-01。判定條件納入 IO 敏感成員（[WI-21](WI-21-io-sensitive-members.md)）與類別層級白名單條目（[WI-24](WI-24-class-level-allow-list.md)）。

## 行為與驗收條件
- 輸入 jar 與白名單，輸出每個 pipeline 的 safe 或 unsafe，及所有原因。
- 分析從 pipeline 定義所在的類別出發，逐層展開被參照的類別，直到沒有新節點；範圍包含 jar 內夾帶的第三方函式庫。
- 能讀取 JDK 25 產生的類別檔；遇到無法解析的類別檔時判為 unsafe 並註明原因。
- 分析對象是編譯後的類別參照；以完整名稱直接引用的類別也要被涵蓋。
- 每個節點對照白名單：白名單條目為套件（子套件預設一併允許，條目標記為「僅此套件」時排除子套件）或完整類別（只涵蓋該類別及其巢狀類別）。
- 節點已在白名單時視為受信任，不再向下展開；pipeline 自身類別視為允許並繼續展開；core 模組視為受信任的葉節點，不向下展開。
- jar 內夾帶的 core 類別不納入分析。
- 節點不在白名單即為違規。例如樹中出現 `java.io.File` 且 `java.io` 未列入白名單，則判 unsafe。
- JVM 結束呼叫：被分析的程式碼（含展開到的第三方函式庫類別）參照 [ADR-011](../adr/ADR-011-jvm-exit-calls.md) 所列的成員時，判 unsafe 並註明原因。成員包含系統類別的 JVM 結束成員、執行期類別的結束成員與強制終止成員，以及 Kotlin 標準函式庫 `kotlin.system` 套件中的行程結束函式。此判定在成員層級，不受套件或類別白名單豁免。
- IO 敏感成員：被分析的程式碼（含展開到的第三方函式庫類別）參照 [ADR-013](../adr/ADR-013-io-sensitive-members.md) 所列的成員（啟動外部行程、載入原生程式碼、基礎套件內可直接開啟檔案或網路的成員）時，判 unsafe 並註明原因，以獨立的原因類別呈現。此判定在成員層級，不受套件或類別白名單豁免。
- 每個違規附上從起點到該節點或該參照的完整路徑；同一節點被多條路徑到達時至少回報一條。
- 參照成環時分析仍會結束。
- 判定規則見 [ADR-002](../adr/ADR-002-context-and-unsafe.md)、[ADR-011](../adr/ADR-011-jvm-exit-calls.md)、[ADR-013](../adr/ADR-013-io-sensitive-members.md) 與 [ADR-014](../adr/ADR-014-class-level-allow-list-entries.md)；任一條成立即 unsafe，原因包含：哪個 IO 類別未限制、哪些白名單外的節點及其路徑、哪些 JVM 結束呼叫及其路徑、哪些 IO 敏感成員及其路徑。
- 分析有時間與規模上限；超限時判為 unsafe 並註明原因。
- 分析過程不執行 pipeline 邏輯，也不觸發其靜態初始化。
- 結果可重現：相同輸入得到相同輸出；時間上限在高負載下可能使結果不同，規模上限與判定樹則是確定性的。
- 輸出註明「不涵蓋反射與動態載入」，並說明此限度同樣適用於 JVM 結束呼叫與 IO 敏感成員的判定，只涵蓋已列出的成員，以及白名單內的類別不被檢查。
- 判定附帶所用白名單的版本。
- 白名單變更時立即對所有既有 definition 重判（由 WI-10 以同一分析重新計算）。

## 架構約束
白名單條目由管理員維護，其內部依賴不檢查；展開規則依 [ADR-002](../adr/ADR-002-context-and-unsafe.md)。JVM 結束呼叫與 IO 敏感成員的判定依 [ADR-011](../adr/ADR-011-jvm-exit-calls.md) 與 [ADR-013](../adr/ADR-013-io-sensitive-members.md)：只做靜態判定，Runner 不加入執行期攔截。分析是 jar 與白名單的純函式，不依賴 Ktor 與 Engine 的型別。

## 待確認問題
- 「pipeline 自身的類別」的範圍：目前以 pipeline 類別所在套件及其子套件為準，其他套件的輔助類別視為第三方並需列入白名單。影響：作者拆分輔助類別的方式；預設套件只涵蓋預設套件本身。
- 探索階段無法解析的類別：目前不被視為 pipeline，不產生判定；從 pipeline 到達的無法解析類別則判 unsafe。影響：惡意 jar 可用壞掉的類別讓 pipeline 不被探索，但不會被執行。
- jar 不是有效壓縮檔時分析會失敗，上傳端（WI-06）須拒絕並回報清楚的錯誤。影響：WI-06 的錯誤處理。
