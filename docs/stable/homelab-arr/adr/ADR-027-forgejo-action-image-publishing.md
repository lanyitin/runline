# ADR-027 以 Forgejo Action 建置並推送 Engine 映像檔

狀態：已核可（2026-10-09）。補充 [ADR-026](ADR-026-homelab-arr-deployment.md) 中「建置自動化待驗證後再評估」的部分。回答：映像檔何時、由誰建置並推送，上線由誰決定。

## 背景

ADR-026 的映像檔在筆電建置並手動推送。維運者希望推送版本 tag 時由 Forgejo 的 runner 自動建置與推送，上線仍由維運者手動決定。runner 是否能建置這個映像檔（架構、容器引擎、工具、憑證）待 homelab 確認，見 [WI-1101](../work-items/WI-1101-forgejo-action.md) 的前提。

## 選項

| 選項 | 優點 | 缺點 |
|---|---|---|
| **A. 只在推送 `v*` tag 時建置並推送；上線手動（採用）** | 重的建置（含下載 Chrome）只在發版時發生；映像檔與版本 tag 一一對應；上線仍由人決定，不會因推送而重啟 arr 的整個堆疊 | 需要記得打 tag |
| B. 每次推到 main 都建置 | 映像檔總是最新 | 每次提交都跑一次重建置，吃 runner 資源；產生大量不上線的映像檔 |
| C. 建置後自動更新 arr 的 compose 並部署 | 全自動 | 每次部署重啟 arr 的整個堆疊；CI 需要有改 homelab 基礎設施的權限，擴大信任範圍 |

## 決策

採 A。工作流程只由 `v*` tag 觸發，行為與筆電的 `deploy/publish-image` 一致（`linux/amd64` 的瀏覽器版、以 commit 識別的 tag、不使用浮動 tag），並在映像檔上同時帶有觸發它的版本 tag。部署引用的仍是不可變的 tag，版本 tag 供閱讀與選用。CI 不接觸 arr，也不更新任何部署設定；上線時維運者手動更新 homelab 的映像檔 tag。筆電手動推送路徑保留為備用。

## 後果

- 建置的行為與規則（架構檢查、拒絕髒工作樹等）以 `deploy/publish-image` 為單一事實來源，不在 CI 另寫一份規則；CI 與筆電產出的映像檔必須可互換。
- CI 的推送憑證是 CI 的機密，只授與推送 packages 所需的權限，不寫進版本庫。
- 若 runner 無法建置（例如架構不符），本決策不成立，需回到手動推送或另覓建置主機。
