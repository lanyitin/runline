# WI-1461 轉錄請求的生成上限

本文回答：每個轉錄請求如何帶生成上限，讓 Lemonade 在伺服器端停止失控的生成。狀態：已核可（2026-10-14）。相依：WI-1453（已完成）。決策見 [ADR-055](../adr/ADR-055-thinking-policy-and-early-stop.md) 決策 4。儲存庫：T。

## 行為與驗收條件

1. **上限的計算**：每個轉錄請求的 `max_tokens` 為 `asrTokensPerSecond` × 該次音訊秒數 ＋ `asrTokenMargin`，無條件進位為整數。
   - 預設 `asrTokensPerSecond` 為 12，`asrTokenMargin` 為 64。
   - 依據：run 8 對白最密的 30 秒片段約 110 到 160 字，即每秒約 5 字，預設值約有 2 倍的餘裕。
   - WI-1452 的實測值出來後，由架構師另行修訂預設值，不屬於本項。
2. **範圍**：pipeline 中每一種送出音訊的轉錄請求都帶上限，包括短段、補掃、chat 端點與 transcriptions 端點。transcriptions 端點不接受生成上限時，在 README 註明，並以測試證明送出的內容。
3. **達到上限**：結束原因為長度截斷的回答視為截斷，不採用其文字。依現行規則重試、降級，並計入及早止損的連續失敗。exchange 紀錄的結束原因為截斷。
4. **量測工具**：WI-1451 與 WI-1452 的量測工具送出的轉錄請求，與 pipeline 使用同一套上限計算，並可用命令列覆寫兩個值。
   - WI-1451 工具遇到截斷或逾時的片段時，記錄該片段為轉錄失敗並繼續處理其餘片段，不中斷整次量測。報告列出這些片段。
   - WI-1452 工具的轉錄結果加記每個請求的 completion token 數與每秒音訊的 token 數，報告列出最大值與第 95 百分位，作為修訂預設值的依據。
5. **參數**：兩個新參數在 intake 驗證，錯誤訊息比照現有參數，README 的參數表更新。

## 架構約束

- 只改轉錄請求的內容與截斷的判定，不改分段、單位與階段。
- 呼叫仍經 Engine 的資源；逾時規則不變，仍只能縮短資源的逾時。
- 結構只增不改。
- 嚴格 TDD；測試不使用 Stub 或 Mock，模型服務使用既有的假服務。
