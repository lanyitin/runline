# WI-37 Console 的安全驗證

本文回答：Console 上線前，如何驗證 XSS 緩解與 token 保存規則確實成立。狀態：已核可（2026-10-05）。相依：WI-35、WI-36。決策見 [ADR-017](../adr/ADR-017-console-websocket-and-token.md)、[ADR-015](../adr/ADR-015-console-frontend.md)。

## 背景

Token 長效且無法單獨撤銷，XSS 緩解是 Console 的上線條件。本項以對抗性的內容與真實瀏覽器驗證，不新增功能；發現缺陷時修正對應畫面。

## 行為與驗收條件

- **對抗性內容**：以真實編譯並上傳的 jar 製造含標記與腳本片段的 pipeline 名稱、參數、log 行（含看似控制序列的內容）、失敗訊息與堆疊、`reasons` 的 `detail`、jar 內字串、錯誤的 `message`；在 Console 的所有相關畫面（Pipelines、Runs、log、上傳錯誤、trigger、白名單、資源）以真實瀏覽器驗證：內容只以純文字顯示，沒有腳本執行、沒有標記被解讀、沒有額外的網路請求。
- **CSP**：以真實瀏覽器驗證內容安全政策確實生效：嘗試注入內嵌腳本被阻擋、不載入任何第三方來源（檢查所有請求的網域）；安全標頭（框架嵌入禁止、`nosniff`）存在於入口頁與資源檔。
- **Token 保存**：驗證 token 不出現在任何網址、瀏覽器歷史、前端 log、錯誤回報、localStorage 與 cookie；只存在於 sessionStorage 與分頁間同步的頻道；登出後所有分頁都清除；Console 的所有請求只送往同源的 Engine。
- **log 輪詢**：確認網路請求不含 WebSocket 連線與網址中的 token。
- **靜態檢查**：禁止把字串當標記插入的規則在前端建置中啟用且無例外清單，或例外有明確理由並回報。
- **相依**：本機可執行的前端相依漏洞檢查通過（高風險項目為零，或逐項列出理由）；鎖定檔未被修改而建置通過。
- 驗證結果與發現回報；任何無法通過者停下來回報，不以放寬斷言換取通過。

**驗收方式**
- 使用真實的打包後 Engine、真實 PostgreSQL（Testcontainers）、真實編譯的 jar 與真實瀏覽器引擎；不使用 Stub 或 Mock。這些驗證納入前端測試（`check`）或明確的本機指令，並在 README 說明。

## 架構約束

- 不改變 API 契約；不降低任何既有的安全標頭或限制。
- 不新增 CI。
