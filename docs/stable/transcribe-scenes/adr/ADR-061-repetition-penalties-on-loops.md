# ADR-061 以重複懲罰參數對付生成迴圈

本文回答：轉錄與摘要的生成陷入重複迴圈時，如何用取樣參數抑制，並限制它對正常內容的影響。狀態：架構師依使用者的指示決定（2026-10-15），待使用者回顧。修改 [ADR-059](ADR-059-truncated-chunk-is-content-not-outage.md) 的決策 1（截斷後不重試）。

## 背景

- 轉錄：對非語言發聲為主的片段，Qwen3-ASR 的輸出一直到生成上限都沒有停止，溫度 0 的重試逐字相同（run 10、run 11）。已知這類模型在雜音、空白、不良切分的音訊上會重複輸出；常見緩解是重複懲罰與存在懲罰，並限制生成長度與前置 VAD（pipeline 已有生成上限與 VAD）。
- 摘要：Gemma 的回答重複同一句直到 4096 個 token（run 12），一次截斷約花 1 至 2 分鐘；上限放大 5 倍只會讓每次迴圈的代價放大 5 倍，不會讓迴圈結束。
- Engine 的 `llm` 資源允許送 `presence_penalty`、`frequency_penalty`、`repeat_penalty`（資源預設或 pipeline 逐次呼叫皆可，[08-api](../../pipeline-engine/08-api.md)），不需改 Engine。放在資源預設會套用到潤飾與翻譯，而這兩者需要忠實重複原文，所以只在 pipeline 的特定呼叫上送。
- Lemonade 後端是否套用這些欄位未驗證。

## 決策

1. **轉錄：截斷後以懲罰重試一次**。第一次嘗試不帶懲罰（正常片段不受影響）；若因生成上限被截斷，同一片段再試一次，這次帶重複懲罰與存在懲罰；仍被截斷即降級（ADR-059 決策 2 至 5 不變）。
2. **摘要：可選的逐次懲罰**。摘要三層的呼叫可帶重複懲罰、頻率懲罰、存在懲罰；預設不送（行為不變），由參數開啟後套用到所有摘要呼叫。
3. **參數**：新增
   - `asrRetryRepeatPenalty`（預設 1.1）、`asrRetryPresencePenalty`（預設 0.3）：只用於決策 1 的那一次重試；設為空值則該欄位不送，兩者皆空則等於不重試（回到 ADR-059）。
   - `summaryRepeatPenalty`、`summaryFrequencyPenalty`、`summaryPresencePenalty`：預設空值（不送）。
4. **生成上限不放大**：`summaryMaxTokens` 預設維持 4096。真正的摘要遠短於此，放大只增加迴圈的代價；使用者仍可用參數覆寫。
5. **後端不認得欄位時**：若上游以 4xx 拒絕這些欄位，視為該次嘗試失敗並記錄原因，不計入及早止損的連續失敗，pipeline 不因此中止；README 的排錯說明如何辨識。
6. **效果評估**：以真實 run 的 EXCHANGE 對照有無懲罰的結果（是否仍截斷、文字是否被改寫）；日語合理的重複（例如「はいはい」）可能被懲罰影響，所以懲罰只出現在重試上，並在成品字幕核對時抽查。

## 取捨

- 得到：被截斷的片段與摘要有機會救回；正常內容不受影響（轉錄首次不帶懲罰）。
- 失去：每個迴圈片段多一次請求（約數秒）；懲罰值是起點，未針對此模型調校；摘要若開啟懲罰，英文摘要的措辭可能略有變化。

## 後果

- 新工作項 [WI-1465](../work-items/WI-1465-repetition-penalties.md)。
- ADR-059 的決策 1 改為「首次截斷後帶懲罰重試一次」；WI-1463 條件 1 隨之調整，其餘不變。
