# ADR-025 資源角色與綁定：pipeline 註記用途與型別，管理員與開發人員選擇注入的資源

狀態：已核可（2026-10-08）。補充 [ADR-007](../../pipeline-engine/adr/ADR-007-shared-resources.md) 與 [ADR-019](../../pipeline-engine/adr/ADR-019-typed-shared-resources.md) 第 2 點「管理與宣告」，並遵守 [ADR-020](../../pipeline-engine/adr/ADR-020-per-uploader-artifact-versions.md)。回答：pipeline 如何說明它需要什麼資源，以及實際使用哪一個資源由誰、在哪裡決定。

## 背景

現行 pipeline 宣告資源的「名稱」（可另宣告型別），Engine 以同名查找資源。名稱同時是 pipeline 內的邏輯識別與 Engine 內的資源識別，因此：

- 管理員要讓 pipeline 使用另一個資源，必須建立與宣告同名的資源，或讓 pipeline 重新上傳。
- 宣告沒有用途說明，管理員與開發人員看不出一個名稱是做什麼用的。
- 沒有「在 pipeline 設定介面選擇注入哪些資源」的操作。

不同上傳者可以上傳 pipeline 名稱相同的版本（ADR-020），且彼此看不到對方；綁定若只以名稱為單位，一位上傳者的操作會改變另一位上傳者的 run，並洩漏對方的存在。

## 決策

### 角色
- pipeline 宣告「資源角色」：角色名稱（pipeline 內的邏輯識別，也是程式取用存取端的名稱）、必要的型別（封閉集合之一）、用途說明（選填的短文字，供人閱讀，不影響判定與行為）。
- 角色名稱與資源名稱是兩個不同的識別。pipeline 程式只看得到角色。

### 綁定
- 綁定是「角色 → 資源」的對應，以（上傳者，pipeline 名稱）為單位：同一位上傳者的各版本共用（跨版本沿用），不同上傳者的綁定彼此獨立、互不可見。新版本新增的角色尚未綁定，移除的角色其綁定失效但保留至被清理。
- 開發人員只能查看與修改自己的綁定；管理員可查看與修改任何上傳者的綁定，操作時以 `uploader` 指定（規則同 ADR-020：多個上傳者而未指定時回 `ambiguous_version`）。兩種角色只能從已存在的資源中選擇，不能建立資源（資源的建立與刪除仍是管理員專屬）。
- 解除綁定只能針對該版本宣告或已保存的角色；對不屬於呼叫者可見範圍的角色，回應與不存在相同。
- 綁定時資源型別必須等於角色型別。
- 沒有明確綁定的角色，綁到與角色同名的資源（既有行為）；因此只宣告名稱的既有 pipeline 與其 jar 不需要任何改動。
- 綁定不影響 safe 或 unsafe 判定。
- 綁定的操作者名稱與時間只對該綁定所屬的上傳者與管理員可見。

### 取得與容量
- 建立 run 時由 Engine 依 run 所屬版本的上傳者與 pipeline 名稱解析每個角色的實際資源，再依 ADR-007 整體取得；解析失敗（資源不存在、已停用、型別不符）沿用 `resources_unavailable`，`problem` 另可區分角色未綁定且無同名資源（`unbound`）。
- 同一個 run 內多個角色綁到同一個資源時，該資源的容量只取得一次，避免容量為 1 的資源使 run 自己等待自己。
- 並行上限與使用量以資源為單位，與角色和上傳者無關。

### 介面
- pipeline 詳情頁列出每個角色的名稱、型別、用途、目前綁定（含資源狀態），並以型別過濾的選單選擇資源；未綁定且無同名資源時明確標示。管理員在同一 pipeline 有多位上傳者時，先選擇上傳者。
- 資源頁與刪除預覽的「宣告者」改為顯示「綁定或同名引用它的 pipeline 與角色」，含上傳者（對開發人員只含自己的）。

## 取捨

- 得到：更換資源不必重新上傳；用途說明讓選擇有依據；同一份 pipeline 可在不同環境接到不同資源；上傳者之間互不影響、不洩漏。
- 失去：多一層對應與一組 API／畫面；同一位上傳者的多個版本共用綁定，改動會影響其所有版本的後續 run；開發人員可把自己的 pipeline 接到任何既有資源，沒有資源層級的授權（v1 單一團隊內部使用，接受；若日後需要，另開 ADR 加入資源可用範圍）；既有 pipeline 在「同名資源未定義」時，`resources_unavailable` 的 `problem` 由 `unknown` 變為 `unbound`（`unknown` 保留給綁定的資源已被刪除）。
