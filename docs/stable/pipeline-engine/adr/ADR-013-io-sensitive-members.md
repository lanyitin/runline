# ADR-013 IO 敏感成員在成員層級判為 unsafe，預設白名單不含提供 IO 的套件

狀態：已核可（2026-10-05）。補充 [ADR-002](ADR-002-context-and-unsafe.md) 與 [ADR-011](ADR-011-jvm-exit-calls.md)。回答：套件層級的白名單無法區分同一套件內的成員時，系統如何避免預設白名單使 context 的限制被繞過。

## 背景

ADR-002 的白名單在套件層級運作：列入白名單的套件被視為受信任，其內部不再展開。這使同一套件內性質不同的成員無法區分：

| 套件 | 同時包含 |
|---|---|
| `java.lang` | 純計算類別，以及可啟動外部行程與載入原生程式碼的成員 |
| `java.util` | 集合與工具類別，以及可直接開啟檔案的成員（例如以檔案為來源的掃描與格式化）；其子套件含壓縮檔與日誌，亦可存取檔案 |
| `java.io`、`java.nio.file`、`java.net` | 直接提供檔案與網路 IO |

pipeline 撰寫時必然使用 `java.lang` 與集合類別，預設白名單必須包含它們；但列入即等同繞過 context 對外部行程、檔案與網路的限制。ADR-011 已對 JVM 結束成員採成員層級比對，同一機制可涵蓋這些成員。

## 決策

### 成員層級的 IO 敏感成員
- 編譯後的程式碼參照下列任一類別的成員，即為 unsafe 的判定條件（與 ADR-002、ADR-011 的條件並列，任一條成立即 unsafe）：
  1. 啟動外部行程的成員（行程建立與執行）。
  2. 載入原生程式碼的成員。
  3. 位於預設受信任的基礎套件內、可直接開啟檔案或網路的成員（例如以檔名開啟檔案的建構方式）。
- 比對在成員層級，必要時帶方法描述子以區分多載（例如以檔名開檔的建構與僅在記憶體內處理的建構）；不帶描述子的條目比對該成員的所有多載。
- 比對不受套件或類別白名單豁免：即使所屬套件或類別在白名單內，參照仍判為違規。
- 違規回報從起點到該參照的完整路徑，並以獨立的原因類別呈現，使使用者能分辨是 JVM 結束、IO 敏感成員或白名單外的節點。
- 判定範圍與 ADR-002、ADR-011 相同：包含 jar 內夾帶的第三方函式庫；已在白名單的節點視為受信任、不向下展開，其內部不檢查。
- 成員清單的單一事實來源是 analyzer 的說明文件，並有測試以執行測試的 JDK 驗證清單與實際成員一致：JDK 升級使成員改變時測試失敗，提醒維護清單。清單不複製到其他文件。
- 不在執行期攔截。

### 預設白名單
- 預設白名單只包含不提供檔案與網路 IO 的基礎套件：JDK 的語言基礎、集合與並行工具、時間與數學、文字與正規表示式，以及 Kotlin 標準函式庫與其執行期輔助套件、註解套件。
- 預設白名單不包含提供檔案或網路 IO 的套件：檔案與串流 IO、檔案系統、網路與其通道、資料庫連線等。需要這些能力的 pipeline 應經由 context，直接使用者被判為 unsafe。
- 同一套件的子套件含 IO 能力時，該套件以「僅此套件」列入，並明確列入需要的子套件，使子套件不被預設涵蓋。
- 標準輸出與主控台輸入所需的少數類別，以類別條目放行（[ADR-014](ADR-014-class-level-allow-list-entries.md)），不放行其所在套件。
- 預設白名單的具體內容記錄於 [WI-10](../work-items/WI-10-allowlist-admin.md)。
- 預設白名單只是初始內容；管理員可依營運需要修改，修改即是管理員的信任決定（ADR-002）。

## 取捨

| 項目 | 優點 | 缺點 |
|---|---|---|
| 成員層級補足 | 預設白名單可含 `java.lang` 與 `java.util`，作者不會因基本類別而大量被判 unsafe；不需執行期攔截 | 成員清單需隨 JDK 演進維護；僅涵蓋已列出的成員；反射與動態載入仍可繞過 |
| 預設不含 IO 套件 | 預設即不放行直接 IO；與 context 的協作式模型一致 | 需要 IO 的 pipeline 在預設下被判 unsafe，需管理員逐一允許或改走 context |

被否決的做法：維持套件層級、在文件明說限度（預設白名單含 `java.lang` 即放行行程啟動，實質上使 unsafe 判定失效）；預設白名單不含 `java.lang`（幾乎所有 pipeline 都被判 unsafe，判定失去意義）。

## 後果

- analyzer 增加成員層級的 IO 敏感判定（[WI-21](../work-items/WI-21-io-sensitive-members.md)）。
- 預設白名單由 analyzer 提供，Engine 與開發入口共用（[WI-10](../work-items/WI-10-allowlist-admin.md)）。
- 判定規則更新後，既有已儲存的判定不自動改變；重判由白名單變更或管理員的重判操作觸發。
- 文件與 API 回應須明說：判定只涵蓋已列出的成員；反射與動態載入、白名單內類別的內部呼叫、以子類別作為呼叫接收者的呼叫，不在涵蓋範圍。
- 套件層級白名單的限度仍然存在：白名單內第三方函式庫的內部行為不被檢查，這是管理員加入條目時承擔的信任決定。
