# WI-1464 條目時間不進模型請求與回答

本文回答：潤飾與翻譯的請求與回答如何不再帶時間，以及相關的觀察資料修正。狀態：已核可（2026-10-15）。相依：WI-1457、WI-1459。決策見 [ADR-060](../adr/ADR-060-times-stay-out-of-model-answers.md)。儲存庫：T。

## 行為與驗收條件

1. **請求不帶時間**：潤飾與翻譯對每個場景片段的請求，各條目只含序號與文字（含行）；前一片段的語境同樣不含時間。可用一句文字說明本片段在影片中的位置。
2. **回答不含時間也不檢查時間**：回答只需含序號與文字（含行與換人標記）。回答若帶了時間軸，忽略，不判違反。條目的時間由 pipeline 依序號從來源補回，完成後的條目時間與來源完全相同。
3. **其餘檢查維持**：條目數、序號、每條行數上限、換人標記位置、翻譯的繁體字檢查、語境內容不得出現在回答中；違反者重試，用盡則該片段保留上一階段文字並計入降級。`TIME_CHANGED` 這個原因不再出現。
4. **提示詞**：潤飾與翻譯的預設 system prompt 改寫以反映新格式，不再要求「時間不變」逐字照抄；README 的引文同步，文件測試維持相符。覆寫提示詞的行為維持。
5. **及早止損**：契約違反仍計入連續失敗，門檻與其他原因不變。
6. **輸出**：兩份 SRT 的條目時間完全相同（沿用既有保證）。
7. **觀察資料**：失敗的 run 在 `runs` view 中顯示的降級數，要包含失敗前已累計的降級（目前顯示 0），或明確標示為未結算；階段列的降級數照實顯示。
8. **紀錄**：EXCHANGE 的請求與回答記錄新格式；舊 run 的紀錄不轉換。

## 架構約束

- 不改條目的數量、時間與換人資料的來源；不新增參數；不改對齊、場景、摘要與 view 的其他行為。
- 嚴格 TDD；測試不使用 Stub 或 Mock，以假服務重現「回答改了時間」與「回答帶了舊格式時間軸」兩種情境。
- 部署時需處理的事（新參數、環境變數、掛載）若有，回報時列出。
