# ADR-069 模型的回答能收就收：結構由 pipeline 掌握，格式問題不重試

本文回答：潤飾、摘要、翻譯如何對待不守格式的模型回答，以及重試與及早止損的角色。狀態：已核可（2026-10-15）；決策 5、7 對未翻譯條目的部分已被 [ADR-070](ADR-070-untranslated-entries-are-retried.md) 取代。修改 [ADR-055](ADR-055-thinking-policy-and-early-stop.md) 決策 6、[ADR-064](ADR-064-answer-contract-violations-are-per-segment.md) 決策 1、3、4、5、[ADR-067](ADR-067-any-chinese-is-accepted.md) 決策 3，以及 WI-1457、WI-1458、WI-1459 中對應的回答檢查；延續 [ADR-060](ADR-060-times-stay-out-of-model-answers.md) 的方向。

## 背景

- 使用者的判斷：小模型常常不遵守指令，用大量檢查加重試指望模型產出預期格式，只是浪費電與時間。
- 實機證據（翻譯，同一份輸入）：
  - Gemma Q2_K_P（run 25）：4.5 分鐘被及早止損，5 次連續截斷來自 2 個片段。
  - Qwen3.5-4B（run 26，被取消）：74 次失敗原因中，換人標記不符 34%、條目數不符 28%、未翻譯 19%；失敗的回答多數含有大量可用的條目，只是多了 `- `、`->`、原文或說明。
  - Mistral-7B-Instruct-v0.3 Q4_K_M（run 27，被取消）：25 個片段內，換人標記不符與格式不符同樣是失敗大宗。三個模型家族的失敗型態一致，問題在檢查太多，不只是某個模型。
  - 附原因的重試成功率只有 4% 至 7%；原樣回傳的片段在重試時逐字相同。
  - 檢查本身也誤判：簡體字集誤收「概」、`->` 被當成換人、短句被當成語境重複。
- 摘要同樣：整部摘要因格式、語言碼、角色表列格式而缺失；角色表把描述性稱呼（「the man」）標成有名字，使每次翻譯都被要求為它取譯名。
- 現行做法是「檢查、作廢、重試、降級」：作廢的粒度太粗，丟掉可用的部分；重試對確定性高的小模型無效。

## 決策

1. **結構由 pipeline 掌握，不要求也不檢查模型回傳**：序號、時間、條目數、換人標記、語言碼的格式。已知的資料由 pipeline 依來源補回。
2. **回答以寬鬆方式解析**：依序號逐條取出文字；序號區塊之外的內容（問候、註解、自言自語、重複的原文、程式碼框）一律忽略；重複的序號取第一個；多出的序號忽略；超過兩行時把多出的行併入第二行。
3. **取不到才降級，且以條目為單位**：回答中取不到的條目、文字為空的條目，保留上一階段文字並計入降級；其餘條目採用。回答被截斷時，截斷前已完整的條目採用，其餘降級。
4. **翻譯的換人標記由 pipeline 補回**：回答中的 `- `、`->` 等行首符號一律剝除後忽略；標記依來源資料畫出（來源條目有兩個標記而譯文有兩行時各畫一個；譯文只有一行時，任一來源行有標記則畫在這一行）。潤飾的換人標記由模型決定，位置不符時直接採用模型給的，不作廢。
5. **只留一項品質檢查**：翻譯回答的行含假名視為未翻譯（`UNTRANSLATED`），該條目降級並記錄，不觸發整個片段重試。
6. **摘要與角色表寬鬆解析**：在回答中尋找 `LANGUAGE:`、`CHARACTERS:`、`SUMMARY:` 標記，標記之外的內容忽略；語言名稱對應為語言碼，對應不到為 `und`；角色表逐列解析，格式不對的列略過，其餘列採用；過長的摘要截到上限；英文與否只記錄，不作廢。
7. **重試的角色縮小**：
   - 只有兩種情況重試：服務層失敗（逾時、5xx、連線、速率限制），以及整個回答取不到任何條目或標記；
   - 每個片段最多重試 1 次（`modelRetries` 預設由 2 改為 1，語意為每片段的重試次數）；
   - 重試的請求與第一次相同，不附原因（取消 ADR-064 決策 1）；
   - 回答被截斷不重試（與 ADR-059 的轉錄一致）。
8. **及早止損**：服務層失敗維持每次呼叫累計；內容層面只在「整個片段取不到任何內容」時累計一次，片段只要取到任何一條就歸零。`earlyStopFailures` 的門檻與預設不變。
9. **角色表只對真正的名字要求譯名**：描述性稱呼（「the woman with long dark hair」「the man」）一律是無名字，不要求譯名，也不出現在翻譯請求的待翻譯名單中。

## 取捨

- 得到：失敗點大幅減少，降級縮小到單一條目；呼叫次數與耗時預估減少一半以上；run 不會因格式雜訊被殺；不再為模型編造的譯名付出代價。
- 失去：
  - 譯文中混有原文或不佳譯文的機率上升，由使用者在成品核對時判斷。
  - 模型的格式錯誤不再被指出，只留在紀錄與計數。
  - 修改多個已核可的規則，需要修訂稿。
- 不採用：
  - 只調高 `earlyStopFailures` 或重試次數（不解決作廢粒度與重試無效）；
  - 為每個模型維護不同的檢查規則（維護成本高，且模型常換）。
