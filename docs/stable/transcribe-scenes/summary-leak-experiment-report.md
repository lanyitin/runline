# 摘要階段思考過程外洩的量測報告

本文回答：摘要回答中出現自言自語（"Wait, …"）的原因是什麼、哪些調整有效、各層摘要適合哪種做法。狀態：已核可（2026-10-18）；量測於 2026-10-17 至 18 在 arr 的 Lemonade 上進行，所用提示為 run 38 的覆寫值（[原文](run38-summary-prompts-reference.md)）；「原因」一節中「片段層的提示沒有 scene 一詞」只對程式預設成立，已由 [ADR-081](adr/ADR-081-default-summary-prompts-adopt-measured-structure.md) 更正。決策見 [ADR-077](adr/ADR-077-scene-summary-answer-opening.md)。

## 量測條件

| 項目 | 值 |
|---|---|
| 素材 | run 38（`FC2-PPV-48054.mp4`，924 MB）的 `exchange.prompt`，system 與 user 文字逐字使用（片段層的圖片註記以真實圖片取代） |
| 模型與路徑 | Gemma4-26B-A4B-Uncensored-HauhauCS-Balanced-Q2_K_P，經 llm-gateway 的 chat.completions |
| 取樣 | temperature 0.3，`max_tokens` 4096，不送 top_p 與 top_k；thinking 關閉的組別不帶 `response_format` |
| thinking 關閉 | assistant 預填已結束的空推理區塊 |
| 圖片（僅片段層） | 依 pipeline 規則抽取：每個片段每秒一張、最多 4 張、最長邊 512 像素、JPEG，以 data URI 附在請求中 |
| 外洩的判定 | `content` 含 "wait"、"Final Polish" 或 "Final version"（不分大小寫）；字幕本身含 "wait" 者（segment 53 的「あ、待って」）另行排除 |
| 範圍外 | 單一影片；品質只做目視比對；請求參數不記在 EXCHANGE，無法從資料庫還原 |

## 基準：run 38 的外洩

- 摘要階段 174 次呼叫（132 片段、39 場景、3 全片）中，只有 1 次含 "wait"：場景 30（exchange 11039）。
- 回答 15,545 字、"wait" 出現 24 次，`finish_reason` 為 `length`（用盡 4096），`reasoning_content` 為空，`SUMMARY:` 在第 4080 字。
- 該回答被存成正式的場景摘要（含推理），並出現在全片摘要第一批彙整的輸入中；全片摘要本身沒有外洩。
- 輸入：三行片段摘要（車內、車內、臥室），其中兩行寫「The scene ends with …」。

## 原因

- 外洩的回答都以相同方式開頭：先說輸入是否為「三個不同的場景」，再「Wait, looking at the input again」，重抄輸入，然後反覆修稿。第一個 "Wait" 在第 350 到 800 字之間，位於回答開頭的第一段。
- 觸發條件是輸入看起來互相矛盾：地點跳躍，以及片段摘要自己寫了「場景在此結束」。片段層的提示沒有 "scene" 一詞，這個詞由模型自行選用。
- 地點跳躍不是充分條件：39 個場景中有 9 個地點跳躍，只有場景 30 外洩；外洩的場景 18 只有一行輸入。
- 回答不以格式標記開頭：現行預填之後，模型可以自由開始。

### 預填的行為

- 服務把整段預填連同續寫回傳：`content` 以 `<think>\n\n</think>\n\n` 開頭，場景層接著是標記、換行與欄位，標記只出現一次。
- 預填沒有被忽略，也沒有被模型重複輸出。

## 片段層

帶圖片的真實請求（6 個片段各 10 次，A 與 G 各 60 次）：

| | A（現行預填） | G（預填加標記） |
|---|---|---|
| 外洩 | 0/60 | 0/60 |
| 截斷 | 0/60 | 0/60 |
| 首行為 `SUMMARY:` | 60/60 | 60/60 |
| 超過 500 字元或 3 句 | 0 | 0 |
| token 平均 | 42 | 41 |
| 平均耗時 | 0.9 秒 | 0.7 秒 |

- 片段：場景 30 的 112、113、114；場景 18 的 74；沒有對白的 1；字幕最多的 53。
- 沒有圖片的純文字重放，A 組在 60 次中有約 38 次外洩、30 次截斷（模型對空輸入評論「沒有資料可摘要」）；此條件不代表真實請求，只作說明圖片的必要性。
- 預填標記帶尾端空格時，服務保留空格，下一個字元為換行；A 組的回答標記後直接接散文。
- 片段摘要的內容目視對照圖片：多數與畫面相符；片段 1 的描述與第一張圖不符（run 38 存入的版本同樣不符）；片段 114 存入的「臥室、handjob」與最後一張圖（車內）不符。這是單張圖的目視比對。

## 場景批次彙整與全片層

- 場景批次彙整（run 38 的 exchange 11049、11050，同一份場景提示，各 10 次）：A、G 皆 0 外洩、四欄齊全、標記一次。
- 全片層（exchange 11051，各 10 次）：A、G 皆 0 外洩；A 的版面符合要求（語言碼與標記同一行、人物行、摘要）；G 以 `LANGUAGE: ` 預填時，語言碼落到下一行、第二個標記被拼成 `CHARACTS:`，10/10 版面不合規，內容正常。

## 限制

- 單一影片、單一模型與量化版本；各組 10 次，外洩率為該輸入下的觀察，不是整體機率。
- 場景層的壓力場景只有兩個（30、18）會外洩；其餘場景的 A 與 G 無差異可言。
- 預填使模型不能表達「輸入有問題」；沒有量化摘要品質（涵蓋度只做目視）。
- 調整比較與 JSON／thinking 兩節（場景 30）使用由先前輸出重建的 prompt（長度與資料庫一致，未逐字比對）；其餘各節逐字取自資料庫。
- 請求的 `response_format`、預填內容與 pipeline 版本不記在 EXCHANGE，日後比較需要這些欄位。
- 量測的腳本與結果檔在本機暫存目錄，不保存在儲存庫；重現需要依「量測條件」重新建立。
