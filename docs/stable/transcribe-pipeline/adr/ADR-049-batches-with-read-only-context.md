# ADR-049 潤飾與翻譯以批次送出並附唯讀的前後文

本文回答：潤飾與翻譯每次送出哪些條目、模型能看到哪些前後文。狀態：已核可（2026-10-13）。修訂 [ADR-038](ADR-038-segment-model-and-stage-invariants.md) 決策 4 的「潤飾與翻譯以 VAD-A 為單位送出」；ADR-038 的其餘決策（條目時間固定、回答的不變式、退回規則）不變。

## 背景

ADR-038 讓潤飾與翻譯以 VAD-A 組為單位，期望一組內有多個條目，可以互為語境。實際上 VAD-B 很少細分 VAD-A；使用者也觀察到字幕前後沒有關聯，潤飾的效果不大，並判斷全片摘要內容混亂，不適合作為翻譯的參考。

以下依據 arr 上的 run `0684dc25-550e-476a-befb-9251fb25552f`（資料庫 run 7，`FC2-PPV-47287.mp4`，3084.8 秒，日語，`success-degraded`），資料由 homelab-deployer 取回、唯讀。

| 觀察 | 數值 |
|---|---|
| 條目（VAD-B 與補掃）長度 | 250 條；中位數 1.05 秒，P10 0.41 秒，P90 8.0 秒；短於 1 秒者 123 條 |
| VAD-B 是否細分 VAD-A | 幾乎沒有：a=208、b=213、keptFromA=206。條目長度實際由 VAD-A（最小靜音 500 ms）決定 |
| 有語音的條目與文字量 | 164 條，全片約 1,500 字；相鄰語音條目的間隔中位數 4.6 秒、P75 16 秒、2 秒以內 57 處 |
| 潤飾每次看到的條目 | 有語音的 160 組中 **158 組只有一個條目**；潤飾在 164 條中只改了 2 條（其中一條只加一個逗號），核對改了 0 條 |
| 翻譯每次看到的條目 | 同上，一組一條；唯一的語境是全片摘要 |
| 補掃窗口 | 26 條 8 秒的條目，多為「うん。うん。」 |

文字樣本顯示兩類問題並存：

- 聽錯（推測）：「言語種の」「あんこチュンクンジ」「手音だった」「健康見えちゃってます」「こすけてる」（應為「透けてる」）「ランダム数値をされたいです」。
- 句子被切斷：「ちゃった私が。」「で欲しくてスケスケに…」「てしまったんです。」從句子中間開始；翻譯只能猜（「あってさいね」譯成「可以做的吧」）。

結論：

1. ASR 每次只聽約 1 秒，缺少語境。
2. 潤飾提示寫著「以前後條目為語境」，但送出單位是 VAD-A 組，而 VAD-A 組幾乎都只有一個條目，所以潤飾與翻譯實際上沒有任何前後文。提示詞怎麼改都無法補救，必須改送出單位。

## 選項

| 選項 | 優點 | 缺點 | 結論 |
|---|---|---|---|
| A. 每批附上全片文字 | 語境最完整 | 對白多的影片有數萬字，每批重送全文，成本隨長度平方成長，可能超出上下文 | 否決（使用者選 B） |
| B. 每批附前後固定範圍的條目 | 請求大小有上限，長片也穩定 | 更遠的劇情看不到 | 採用 |
| C. 維持 VAD-A 組，只改提示詞 | 改動最小 | 一組一條，沒有語境可用 | 否決 |

## 決策

1. **批次**：潤飾與翻譯各自依時間順序，把**有語音**的條目切成連續的批次，每批最多 `contextBatchEntries` 條（預設 20）。批次與 VAD-A 組無關；無語音的條目不進批次，也不進語境。批次仍逐一循序送出（並行 1）。
2. **唯讀語境**：每批附上批次之前與之後的有語音條目，各自同時受兩個上限限制：與批次邊界相距不超過 `contextSeconds`（預設 120 秒），且條數不超過 `contextMaxEntries`（預設 30 條）。影片開頭或結尾沒有語境時寫 `(none)`。
3. **語境的內容**：
   - 潤飾：前文用已潤飾的文字（前面的批次已完成；降級者用轉錄文字），後文用轉錄文字。
   - 翻譯：前後文的來源文字都用核對後文字（核對降級者用潤飾文字）。前文另外附上每條已翻好的譯文（前面的批次已完成；翻譯降級者為其保留的文字），讓前後的用詞一致；後文尚未翻譯，只有來源文字。
4. **語境的格式**：語境不是 SRT，每個條目是一行「`[時:分:秒]` 文字」；翻譯的前文在其下多一行譯文。語境與要處理的 SRT 分成不同段落，並標明只供理解、不得輸出。user 訊息依序為：前文、要處理的 SRT、後文。
5. **回答、驗證與拆開**：回答只能是批次的 SRT，驗證規則照舊（條目數、序號、時間逐字相同；違反者重試）。重試用盡時：
   - 批次多於一條：對半拆開（前半為較多的一半），兩半依序各自當成批次重新處理，重試次數完整。語境依新的範圍重新選取，所以後半的前文含前半剛完成的結果。
   - 只剩一條：該條退回前一階段的文字，記錄降級。

   生成上限依批次 SRT 的大小計算（沿用 WI-1437）。
6. **翻譯不再附全片摘要**。摘要階段保留，照常執行與記錄：它仍決定字幕檔名的語系，也供 Console 使用。
7. **預設 prompt**：潤飾與翻譯的預設 system prompt 改寫，說明前後文的用途與「不得輸出、不得把語境的字搬進條目」；仍可由 WI-1445 的參數覆寫。
8. **核對階段不變**：仍逐條目送出，附前後各一條。

## 取捨

- 得到：潤飾與翻譯能看到前後約兩分鐘的對話；請求數大幅減少（run 7 由 160 次降為約 9 次）。
- 失去：請求變長；某批反覆失敗時，拆開會使請求數增加（20 條的批次最壞情況下拆成 39 個批次）；翻譯失去全片摘要這個（品質不佳的）語境；`exchange` 對潤飾與翻譯的紀錄單位由組改為批次。

## 後果

- 參數新增 `contextBatchEntries`、`contextSeconds`、`contextMaxEntries`，潤飾與翻譯共用。
- 潤飾與翻譯的 log、STAGE 計數與 `exchange.target` 由組改為批次；舊 run 的紀錄不改寫。
