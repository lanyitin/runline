# ADR-059 轉錄片段被截斷是內容問題，不是服務中斷

本文回答：轉錄片段因生成上限被截斷時，如何重試、降級，以及是否計入及早止損。狀態：架構師依使用者的自主決策授權決定（2026-10-15），待使用者回顧；決策 1 由 [ADR-061](ADR-061-repetition-penalties-on-loops.md) 修改為「首次截斷後帶懲罰重試一次」。修改 [ADR-055](ADR-055-thinking-policy-and-early-stop.md) 決策 6 與 [WI-1461](../work-items/WI-1461-asr-generation-cap.md) 條件 3 中「截斷計入及早止損」的部分，僅限轉錄階段。

## 背景

- 實機測試（run 10）：一段以非語言發聲為主的影片，Qwen3-ASR 在片段上陷入重複輸出（例如反覆的「嗯」「啊」），直到生成上限，結束原因為長度截斷。
- 轉錄的溫度為 0，三次重試的回應逐字相同，重試沒有機會成功。
- 連續五個呼叫被截斷，觸發及早止損，整個 run 失敗，沒有任何字幕產出。這類內容在一部影片中可能大量出現，該 run 本來可以交出其餘片段的字幕。
- 及早止損的原意是偵測服務層級的故障（逾時、5xx、模型不可用、格式持續不符）；截斷是特定片段內容的結果，不代表服務故障。

## 決策

1. **轉錄片段被截斷時不重試**：相同輸入在溫度 0 下得到相同輸出；第一次截斷即放棄該片段。
2. **降級**：該片段沒有文字（與沒有語音不同），計入降級與 `transcribeFailed`，EXCHANGE 記錄結束原因為截斷，log 列出片段與原因；run 繼續。
3. **不計入及早止損**：轉錄階段的截斷不累計連續失敗。逾時、5xx、格式不符等原因的及早止損規則不變，其他階段的截斷（潤飾、摘要、翻譯）維持原規則。
4. **全部失敗才失敗**：轉錄階段結束時，若有語音的片段全部轉錄失敗（沒有任何一個片段取得文字），run 以轉錄類別失敗，訊息指出原因與數量；只要有一個片段成功，run 以降級結束。
5. **可觀測**：RUN SUMMARY 的 `transcribeFailed` 區分原因（截斷、逾時、其他）的片段數，供判斷生成上限設得是否太低。

## 取捨

- 得到：含大量非語言發聲的影片仍能產出其餘片段的字幕；不再浪費重試。
- 失去：
  - 生成上限設太低（參數錯誤）時，不會被及早止損攔下，而是大量片段降級；以決策 4 與決策 5 的數字提示。
  - 被截斷的片段沒有字幕，即使其中夾有真正的對話；拆半重試等補救辦法不採用（維持 ADR-055「截斷不拆批」的方向），待成品核對後再評估。

## 後果

- 新工作項 [WI-1463](../work-items/WI-1463-truncation-degrades-chunk.md)。
- WI-1461 條件 3 對轉錄階段的「計入及早止損」由本 ADR 取代；量測工具的行為不變。
