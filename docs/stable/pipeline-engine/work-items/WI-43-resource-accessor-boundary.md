# WI-43 資源存取端邊界與開發入口

本文回答：Engine 如何把型別化資源的受控存取端交給 run、如何回收與失效，以及開發入口如何以同一契約提供本機實作。狀態：已核可（2026-10-06）。相依：WI-40。決策見 [ADR-019](../adr/ADR-019-typed-shared-resources.md) 第 3 點與 [05](../05-ipc.md)「資源存取端」。

## 背景

`counter` 沒有存取端。有實體的型別（`file`、`jdbc-pool`、`openai-compatible`）由 Engine 持有實體與機密，run 只拿到受控的存取端。本項建立與型別無關的通用邊界與生命週期；各型別的具體操作在 WI-45、WI-46、WI-48。在這些型別存在之前，通用機制以僅存在於測試原始碼的 Fake 型別（見 WI-40）驗證。

## 行為與驗收條件

**契約與邊界**
- core 定義存取端的契約；跨越 class loader 邊界時只使用 JDK 內建型別，機密、實體與 Engine 內部型別不穿過邊界。以真實的 class loader 隔離驗證（沿用既有隔離測試方式）。
- 使用存取端的 pipeline 仍為 safe：以真實編譯的測試 jar 驗證，資源宣告與存取端使用都不改變判定。

**取用規則**
- Pipeline 只能依名稱取用「自己宣告了型別且已持有」的存取端。取用未宣告、只宣告名稱、或型別不符的資源，得到明確的失敗；沒有「執行中取得資源」的操作（沿用 WI-09）。
- 只宣告名稱的資源只取得容量，行為與現行完全相同。

**初始化與備妥**
- 取得容量成功後，Engine 為每個宣告了型別的資源備妥存取端，初始化完成時存取端已可用。備妥失敗（實體不可用）時 run 失敗並註明資源不可用，不進入 pipeline 本體，且已取得的容量被釋放。
- 存取端綁定該 run 與取得當下的資源設定：持有期間資源設定被修改，該 run 繼續使用舊設定，之後取得的 run 使用新設定。

**回收與失效**
- Run 以任何方式終止（成功、失敗、取消、中斷）時，Engine 回收該 run 的所有存取端與其佔用的實體，進行中的操作被取消。
- 管理員強制釋放持有者時，存取端同時失效：之後的操作失敗並註明原因為強制釋放；進行中的操作被取消；容量釋放後下一位等待者取得時，實體不會同時被兩個 run 使用。強制釋放端點的其他行為不變，08-api 補充此語意。
- 停用資源使等待者失敗，不影響持有者的存取端；降低容量不收回持有者的存取端。

**錯誤與記錄**
- 回傳給 run 的實體錯誤只含錯誤類別，不含連線字串、路徑或驅動訊息原文；原文與例外寫入 Engine log，以 `errorId` 對應。
- Run 的 log 記錄資源取得、存取端失效與實體錯誤類別，不記錄機密與請求內容。Run 的 trace 每次資源操作一個 span，只記錄資源名稱、型別與操作類別。

**開發入口**
- 開發入口以同一份契約提供本機實作：資源定義由本機組態提供（不連 Engine），機密由開發人員的本機環境提供；單一 run 沒有競爭，初始化立即成功。
- 錄製在開發入口記錄「使用了哪個資源（名稱與型別）與動作類別」，不記錄內容；metadata 提案據此產生型別宣告（[ADR-004](../adr/ADR-004-recording.md)）。Engine 的 run 不帶錄製選項。
- Engine 與開發入口以同一組行為驗收測試驗證：取用規則、失效、錯誤類別、錄製。

## 架構約束

- 容量取得、等待、釋放語意不變（ADR-007）；本項不引入請求級或交易級的取得與釋放。
- 契約在 core，Engine 與開發入口各自實作；探索與分析不得執行 pipeline 邏輯（[ADR-003](../adr/ADR-003-jar-and-discovery.md)）。
- 型別集合封閉；Fake 型別只存在於測試原始碼。
- 測試使用真實 class loader 隔離與真實 PostgreSQL（Testcontainers），不使用 Stub 或 Mock；需要替代品時使用自製的簡易真實實作（Fake）；嚴格 TDD；不新增 CI；完成程式碼變更時依專案規則先以 ktfmt 格式化。
