# 非功能性考量與風險

本文回答：這個移植有哪些風險、怎麼緩解、哪些需要先驗證。

| 風險 | 影響 | 緩解／處置 |
|---|---|---|
| Linux 虛擬顯示下瀏覽器指紋被目標網站識破（軟體渲染）；來源系統在該環境未驗證 | 擷取回傳 bot-check 頁而看似成功 | WI-1000 關卡；擷取結果要有「頁面可信」的判斷（5xx、過薄、檢查頁特徵）；不通過時停下來由架構決定 |
| 直接以 DevTools 協定控制 Chrome 的穩定性（等待時機、取消、崩潰） | 擷取不穩 | WI-1000 驗證；run 取消與逾時必須結束 Chrome 行程 |
| SQLite 驅動的原生程式庫在每個 run 的獨立 class loader 下載入失敗 | 第二次 run 起無法寫入 | 驅動由 Engine 載入一次（ADR-024、WI-1003 驗收 8）；該項不可行時改 PostgreSQL |
| 資料庫持續增長（頁面全文、封面影像、模型對話） | 磁碟耗盡 | 原始資料依天數清除（WI-1004）；Engine 的目錄用量上限與資料庫檔的備份納入維運 |
| SQLite 單寫入者與外部工具同時讀取 | 寫入等待或讀取不一致 | 日誌模式與忙碌等待由 Engine 設定檔固定；外部只做唯讀查詢 |
| Engine 崩潰或被強制終止時遺留 Chrome 行程 | 資源洩漏、占用顯示 | 啟動時清理屬於本 pipeline 啟動的行程；處理建議見 `deploy/browser.md` |
| unsafe pipeline 以 Engine 身分執行任意 IO | 安全邊界降低 | 逐版本允許（管理員的信任決定）；LLM、資料庫與憑證檔仍走 context |
| run 持有 LLM 資源（容量 1）整個 run 期間 | 其他使用同資源的 pipeline 等待整個 digest run | 接受；run 級持有是 ADR-019 的決定 |
| 標已讀不可逆、帳號共用 | 誤標造成資料遺失 | 閘門在程式；沒有摘要不標；無 url 不標；驗收含「閘門關閉時零標記」 |
| 模型被靜默替換 | 判定意義改變 | 每次呼叫比對回應的模型與請求的模型，不符即中止 |
| 成本隨 cap 線性成長（每篇每條件一次呼叫） | run 時間長 | 接受，維持現行行為；run 逾時由 trigger／Engine 設定 |
| 擷取內容是不受信任的輸入 | 提示注入、檔案路徑注入 | 模型只回答判定與引文，url、標題、路徑由程式組成；引文必須是頁面文字的子字串 |

## 可觀測性

- run log 逐階段一行宣告與結果；計數（collected、kept、filtered、untouched、refused）於結束時輸出。
- 沿用 Engine 的 log／metric／trace；不輸出機密與擷取到的頁面全文。
