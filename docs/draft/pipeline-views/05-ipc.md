# IPC 模型：view API 契約

本文回答：Console 與 Engine 之間如何列出與讀取 view，錯誤與分頁如何傳遞。決策見 [ADR-033](adr/ADR-033-pipeline-views.md)。只描述契約的語意，具體欄位名稱在實作時於 08-api 定案。

## 通訊

- 同步 HTTP/REST，兩個唯讀端點，同其他 API 的認證（Bearer 或 OIDC 工作階段，角色至少 developer）。
- 定址沿用資源綁定：以內容雜湊與 pipeline 名稱指定版本；管理員可用 `uploader` 指定上傳者，多上傳者而未指定時回 `ambiguous_version`。
- 不涉及服務間通訊；Engine 只對 pipeline 已綁定的資源發出唯讀查詢。

## 端點語意

| 端點 | 語意 |
|---|---|
| 列出 view | 回傳該版本宣告的所有 view：識別、標題、說明、參數定義、欄位定義、鑽取、掛載角色的目前解析狀態（可執行、`unbound`、資源停用等）。不執行任何查詢 |
| 讀取 view | 帶參數值與分頁，回傳欄位定義與一頁資料列，以及「還有更多」的標記。不提供總筆數（避免昂貴的全表計數） |

## 契約要點

- **冪等與安全**：兩者皆為 GET，無副作用；重複呼叫安全。
- **分頁**：預設一頁 50 列、上限 200；排序以宣告的預設排序為準，並要求排序具決定性，使翻頁不重複不遺漏。
- **參數驗證**：缺少必填、型別不符、不在固定選項內都是 400，指出參數名稱而不回顯值。
- **錯誤**：資源角色未綁定或停用（沿用 `problem` 值）、查詢逾時、查詢與資料結構不符（例如新版 view 對尚未升級的資料庫）、回應超過大小上限，各有明確錯誤碼；未預期失敗為既有的 500 `internal_error` 加 `errorId`。
- **逾時與重試**：Console 不自動重試；使用者手動重新整理。
- **背壓**：每個資源的 view 並行數有上限，超過回 429 風格的明確錯誤（沿用 Engine 現有的忙碌語意），不排隊占用 run 的容量。
- **版本演進**：view 宣告新增欄位時舊 Console 忽略未知欄位；端點路徑在 `/api/v1` 之下。
- **信任**：回應中的儲存格值是不可信文字，Console 不解譯為標記。
