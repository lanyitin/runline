# WI-1012 資源角色與綁定（Engine、core、devkit）

本文回答：資源角色與綁定在 Engine 側要達成什麼行為。狀態：已核可（2026-10-08）；綁定以（上傳者，pipeline 名稱）為單位的修訂（第 2、3、4、7、12 條）於同日核可。

目標：pipeline 能宣告資源角色（名稱、型別、用途），開發人員與管理員能把角色綁定到既有資源，run 依綁定取得資源。決策見 [ADR-025](../adr/ADR-025-resource-roles-and-binding.md)。工作儲存庫：runline。

## 驗收條件

1. 宣告：pipeline metadata 可為每個資源角色提供選填的用途說明（短文字，長度上限由實作決定並寫入 08-api）；既有只宣告名稱或名稱加型別的 jar 不需重新上傳，行為不變（角色名即同名資源）。用途出現在上傳回應與 pipeline 查詢的 metadata 中，不影響判定。
2. 綁定資料：以（上傳者，pipeline 名稱）為單位保存「角色 → 資源」的對應；同一位上傳者的各版本共用；不同上傳者的綁定彼此獨立；新版本新增的角色未綁定；移除的角色其綁定不影響新版本且可被清理。遷移保持既有資料與行為；既有環境沒有綁定資料，遷移不需轉換。
3. 綁定 API：可查詢某 pipeline 每個角色的名稱、型別、用途、目前綁定與資源狀態（存在、停用、型別是否相符、是否為同名預設）；可設定與解除綁定。開發人員只能操作自己的綁定；管理員可操作任何上傳者的綁定，多位上傳者而未指定 `uploader` 時回 `ambiguous_version`（規則同 ADR-020）。未認證或角色不符回既有的錯誤；設定時資源不存在回 404 類錯誤，型別不符回 422，並與既有 `resource_not_found`、`invalid_resource` 風格一致。解除綁定時，呼叫者可見範圍外的角色與不存在的回應位元組級相同。資源的建立、修改、刪除仍是管理員專屬。
4. 取得：建立 run 時依 run 所屬版本的（上傳者，pipeline 名稱）解析綁定；未綁定時用同名資源；解析失敗以 `resources_unavailable` 回報，`problem` 能區分未綁定且無同名資源、不存在、停用、型別不符。多個問題一併回報。
5. 容量：同一 run 內多個角色綁到同一個資源時，該資源的容量只取得一次；以容量 1 的資源與兩個角色驗證 run 能開始。使用量與並行上限以資源為單位。
6. 存取端：pipeline 以角色名稱取用存取端（既有的取用方式不變）；pipeline 看不到實際資源名稱。錄製在開發入口記錄使用了哪個角色與動作類別。
7. 資源頁與刪除預覽：宣告者資訊改為顯示綁定或同名引用該資源的 pipeline 與角色，含上傳者（對開發人員只含自己的）；刪除仍可在無持有者與等待者時進行，之後相關 run 被拒絕。
8. 上傳警告：沿用既有警告類別，依綁定後的結果計算（例如綁定的資源已停用）。
9. 開發入口：本機資源定義以角色名稱為鍵，行為與 Engine 一致；同時支援 `sqlite`（見 [WI-1003](WI-1003-sqlite-database-kind.md)）。
10. 文件：05、06、08-api、ADR-007 與 ADR-019 的相關描述更新並以連結標示補充 ADR-025；`ApiDocumentationTest` 保持通過。
11. 可觀測與稽核：綁定的設定與解除記錄操作者與時間於 log，不輸出機密；metric 標籤維持資源名稱與型別，不新增高基數標籤。
12. 隔離：兩位上傳者各自上傳同名 pipeline 時：A 設定、更換、解除綁定不改變 B 的 run 取得的資源，也不出現在 B 的任何回應（含綁定檢視、資源的宣告者、log 對 B 可見的部分）；B 無法以任何輸入得知 A 的存在；管理員可分別查看並以 `uploader` 操作。以兩位開發人員與一位管理員的 Bearer 身分驗證。

## 架構約束

- 型別集合維持封閉；不新增資源型別。
- 角色與資源是兩個識別，邊界只傳 JDK 內建型別（05）。
- 機密規則不變（ADR-019）；綁定不改變誰能看到機密。
- 遵守 ADR-020 的版本可見性與不洩漏規則。
- 以真實資源與真實資料庫驗證，不使用 Stub 或 Mock。
