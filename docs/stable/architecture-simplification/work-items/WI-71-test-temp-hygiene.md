# WI-71 測試不遺留暫存資料

本文回答：測試與建置要如何處理自己產生的暫存資料，讓全量 `check` 可以無限次重複執行，如何驗收。狀態：已核可（2026-10-30）。相依：無。

## 背景

測試建立的暫存目錄在結束後不刪除。每次全量 `check` 在系統暫存目錄留下約 1.6 GiB（`ConsoleBuildTest` 每個測試約 120 MiB，其餘如 run 測試工具、打包後的 Engine、金鑰庫等合計約 130 MiB），累積後 Testcontainers 的 PostgreSQL 寫不進資料，[WI-57](../../../stable/pipeline-engine/work-items/WI-57-test-environment-robustness.md) 的重新驗收因此受阻。

## 行為與驗收條件

- 每個測試建立的暫存檔與暫存目錄，在該測試結束時被移除，**不論測試通過、失敗或被中斷於例外**；測試啟動的行程與容器同樣在結束時停止。
- 全量驗證指令（WI-57 所列的 `cleanTest ... check`）執行前後，系統暫存目錄中由本專案測試產生的檔案總量差為零（容許測試框架與 Gradle 本身的快取）。以連續執行 3 次全量驗證、每次前後量測驗證，回報中附上量測值。
- 某個測試失敗時，排查所需的資訊（失敗訊息、相關 log）仍保留在 Gradle 的測試報告中，不依賴遺留的暫存目錄。
- 只改測試與測試支援；產品程式不變。
- 符合[總覽全域約束](README.md#全域約束適用本總覽所有項目)中適用的條件（本項不屬純結構調整，但產品行為不得改變）。

## 架構約束

- 測試的外部系統仍使用真實容器或自製的簡易真實實作，不以 Stub 或 Mock 取代來省空間。
- 不以「放寬或跳過測試」換取空間；不刪除既有測試。
- 不新增 CI、git hook 或外部相依。
