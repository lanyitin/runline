# WI-1486 欄位固定的層保存時只取欄位區塊

本文回答：場景層與中間彙整的回答，保存時要保留哪些內容。狀態：已核可（2026-10-18）。相依：WI-1483、WI-1488（預設場景提示要求四個欄位）。決策見 [ADR-080](../adr/ADR-080-summary-degradation-conditions.md) 決策 3、4。儲存庫：T。

## 行為與驗收條件

1. **只取欄位區塊**：場景摘要與逐層彙整的中間摘要，保存的文字止於第四個欄位（`Ending`）的內容；其後的所有內容（修稿、說明、自言自語、重複的標記或欄位）不保存。
2. **邊界的判定**（由 pipeline 的文字規則決定，不由模型）：
   - 只在回答以標記開頭時套用（略過開頭的空推理區塊後，第一個非空白內容就是標記）；
   - 區塊從該標記起算，取標記之後第一個以 `Ending` 為標籤的行，標籤容許大小寫與 Markdown 裝飾（粗體、反引號、項目符號）；
   - `Ending` 的內容從標籤後算起，延續到第一個空行或回答結束（容許模型把該欄位折成多行）；
   - 標籤只在行首辨識，欄位內容中間出現的 `Ending` 字樣不算。
3. **完整與被截斷的回答都適用**：回答完整結束、或因生成上限被截斷但四個欄位已完整時，都依上述判定裁剪。
4. **原文不丟失**：被裁掉的文字仍留在該次呼叫的紀錄（EXCHANGE 的回應原文）中。
5. **回答不是以標記開頭時不裁剪**：標記前有前言或推理時（預填被忽略等少見情況），沒有可靠的邊界（這類回答可含多個標記與多組欄位），維持現行的標記尋找方式，不套用裁剪；不因此降級。
6. **欄位不完整時**：回答被截斷在第四個欄位之前時，沒有可裁的邊界，保存已有的內容；不因此降級。其中「一個完整欄位也沒有」的處置待決（見總覽的待確認問題），本項維持保存。
7. **標記**：沿用 [WI-1483](WI-1483-scene-summary-answer-opening.md) 的解析（帶或不帶標記皆可）；保存的文字格式不變。
8. **其他層不變**：片段層（散文）與全片層不套用本項。
9. **下一層看到的是裁剪後的文字**：場景彙整、全片摘要與翻譯語境使用的場景摘要，都是裁剪後的版本。

## 架構約束

- 不改 Engine；不新增資料表欄位。
- 嚴格 TDD；測試以假服務重現：欄位後接修稿、欄位後接說明、`Ending` 折成多行後接修稿、標籤帶裝飾、欄位內文含 `Ending` 字樣、截斷在欄位之後、截斷在第三個欄位、回答含重複標記、回答以前言開頭（不裁剪）、中間彙整同樣裁剪。
