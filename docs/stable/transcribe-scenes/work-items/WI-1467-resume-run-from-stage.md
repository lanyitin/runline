# WI-1467 失敗的 run 從指定階段續跑

本文回答：如何讓失敗或中斷的 run 以新 run 從任一階段續跑並延續前次結果。狀態：已核可（2026-10-15）。相依：WI-1455 至 WI-1465（全部已完成）。決策見 [ADR-063](../adr/ADR-063-resume-run-from-stage.md)。儲存庫：T。

## 行為與驗收條件

1. **參數**：新增兩個可選參數：來源 run 與起點階段。兩者都空為一般 run；只設其一在 `intake` 以設定類失敗指出參數；起點階段須是 pipeline 的有效階段名稱。掃描模式與一般 run 的行為不變，也不自動續跑。
2. **驗證**：來源 run 須存在、為失敗或中斷（成功的 run 不可續跑）、起點之前各階段的資料完整、未被保留規則清除、影片檔仍在收件根目錄。任一不符，run 在 `intake` 以設定類失敗結束，訊息指出是哪一項，不含路徑與根目錄。
3. **起點之前的階段**：取用來源 run 的結果；這些階段不呼叫任何模型，不重算，log 標示「沿用自來源 run」。
4. **起點階段**：已完整完成的單位沿用，其餘重做。單位為轉錄與對齊的片段、潤飾與摘要與翻譯的場景片段（沿用 ADR-052）。重做的單位依該階段的現行規則處理（含重試、降級、及早止損）。
5. **起點之後的階段**：全部重新計算，不取用來源 run 的結果。
6. **音訊與畫面**：起點階段或之後的階段需要時，從影片重新取得；起點為翻譯時不抽取音訊與畫面。
7. **參數**：起點之前的階段的參數固定取自來源 run；續跑的 run 送入這些參數的不同值時，intake 以設定類失敗指出參數（或明確忽略並記錄，擇一，實作時回報）。起點與之後階段的參數用新 run 送入的值。log 標明沿用的單位所用的參數可能與新值不同。
8. **來源 run 不變**：續跑前後，來源 run 的狀態、階段資料、EXCHANGE 與結果完全相同。
9. **關聯與可見性**：新 run 記錄來源 run（schema 升版，只向前遷移，沿用既有的備份與回滾原則）；`runs` view 與 RUN SUMMARY 顯示來源 run、起點階段、沿用的單位數與重做的單位數。
10. **再續跑**：續跑失敗的 run 本身可再被續跑；其來源記錄為該 run。
11. **產出**：成功時兩份 SRT 與一般 run 規則相同；來源語言由被採用的片段決定（ADR-062 之後僅採用的片段）。續跑成功與否依一般規則（降級、全部失敗）。
12. **重現情境**：
    - 在翻譯階段因及早止損失敗的 run，以起點翻譯續跑成功，且 ASR、對齊、潤飾、摘要階段的模型呼叫為 0、不抽取音訊。
    - 起點為潤飾時，轉錄與對齊沿用，潤飾以後重算。
    - 起點為轉錄且部分片段已完成時，已完成的片段沿用。
    - 來源 run 為成功、不存在、影片已移除、資料被清除、起點之前的階段資料缺少，各自以明確的設定類失敗結束。
13. 其餘行為（各階段規則、參數、view 的其他欄位）不變。

## 架構約束

- 不改 Engine；續跑是 pipeline 的功能，新 run 是一個獨立的 run。
- 新參數須在 pipeline 宣告（Engine 拒絕未宣告的參數）；README 說明參數、驗證與排錯。
- schema 只向前遷移；部署前備份資料庫，回報回滾點。
- 嚴格 TDD；測試不使用 Stub 或 Mock，以假服務與真實資料庫重現第 12 條的各情境，並驗證「沿用的階段沒有模型呼叫」。
- 部署時需處理的事（新參數、schema 版本、環境變數、掛載）回報時列出。
- 可拆成較小的交付先後完成（例如先翻譯起點、再擴大到其他階段）；若拆，先回報拆法，不得改變驗收條件的總體要求。
