# WI-24 類別層級的白名單條目

本文回答：白名單如何支援完整類別條目，使預設白名單能只放行標準輸出所需的類別。狀態：已核可（2026-10-05）。相依：WI-21。

## 背景

[ADR-014](../adr/ADR-014-class-level-allow-list-entries.md) 決定白名單條目可為套件或完整類別。目前白名單模型只有套件條目；Engine 的過渡白名單與開發入口的白名單設定也只解析套件條目。

## 行為與驗收條件

### 分析
- 白名單支援類別條目：節點的類別符合類別條目，或其所屬套件符合套件條目，即在白名單內；受信任節點不再向下展開。
- 類別條目只放行該類別及其巢狀類別；同套件的其他類別、該類別所在套件的其他成員、子套件都不受放行。
- 類別條目放行的類別，其內提供 IO 的成員仍受 [ADR-011](../adr/ADR-011-jvm-exit-calls.md) 與 [ADR-013](../adr/ADR-013-io-sensitive-members.md) 的成員層級規則約束，不受豁免。
- 既有只含套件條目的白名單，判定與改動前完全相同；既有分析測試全部通過，數量不減少。
- 以真實編譯的 jar 驗證：只放行標準輸出類別的白名單下，使用印出文字的典型 Kotlin pipeline 為 safe；同一份白名單下，以檔名開啟檔案的用法（透過該類別的開檔建構）仍為 unsafe；使用同套件其他檔案類別者仍為 unsafe。
- 條目的種類（套件或類別）在白名單模型中是明確的，不依賴名稱猜測；驗證名稱格式，對不合法或歧義的條目給出清楚的錯誤。

### 消費端
- Engine 的過渡白名單組態能表達類別條目；啟動時驗證條目格式，不合法者啟動失敗並指出鍵名。已存在的套件條目組態維持有效。
- 開發入口的白名單設定能表達類別條目；顯示判定時，所用白名單的版本標示與內容包含兩種條目。
- 組態與 API 對兩種條目使用一致且明確的格式，格式的細節（含 devkit 與 Engine 現有兩種不一致的格式如何統一）依 [WI-10](WI-10-allowlist-admin.md) 的待確認問題處理；本項至少使類別條目在兩邊都可用，並在回報中說明格式。
- Engine 對已儲存的判定不自動重判（重判由白名單變更或管理員操作，見 WI-10）。

### 預設白名單的類別條目
- 評估並回報預設白名單需要的最少類別條目：使印出文字與讀取標準輸入的典型 pipeline 為 safe 所需的類別；逐項說明理由，以及考慮過但不納入的類別。經架構決定後定案，定案前不寫入預設白名單。

### 共同
- 建置、全部測試（含打包形態的測試）在 JDK 25 下通過，`ktfmtCheck` 通過；既有測試數量不減少。

## 架構約束

- 依 [ADR-014](../adr/ADR-014-class-level-allow-list-entries.md)、[ADR-002](../adr/ADR-002-context-and-unsafe.md)、[ADR-013](../adr/ADR-013-io-sensitive-members.md)。
- 修改範圍限於 analyzer 的白名單模型與比對，以及 engine 與 devkit 的白名單解析；若需要其他修改，停下來回報。
- analyzer 主程式維持只依賴 JDK 與 Kotlin 標準函式庫，不依賴 core 或其他專案模組。
- 測試使用真實編譯的 jar（Java 與 Kotlin 皆有）；類別條目的比對邏輯須做突變驗證（暫時破壞再還原，確認測試失敗）。
- 只靜態判定，Runner 不加入執行期攔截；不執行 pipeline 邏輯，也不觸發其靜態初始化。
- 不新增外部相依；不新增 git hook 或 CI；完成程式碼變更時依專案規則先以 ktfmt 格式化。
