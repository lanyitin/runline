# WI-1463 轉錄片段被截斷時降級，不重試、不計入及早止損

本文回答：轉錄片段被生成上限截斷時 pipeline 要怎麼做。狀態：已核可（2026-10-15），已完成。相依：WI-1455、WI-1456。決策見 [ADR-059](../adr/ADR-059-truncated-chunk-is-content-not-outage.md)。儲存庫：T。

## 行為與驗收條件

1. **不重試**：轉錄的回答因長度截斷時，該片段不再重試。
2. **降級**：該片段沒有文字，不送對齊，沒有條目；計入階段與 run 的降級及 `transcribeFailed`；EXCHANGE 的結束原因為截斷；log 列出片段與原因。
3. **不累計止損**：轉錄階段的截斷不計入及早止損的連續失敗。逾時、5xx、格式不符、其他原因的行為與門檻不變；其他階段的截斷行為不變。
4. **全部失敗才失敗**：轉錄結束時，有語音的片段全部沒有取得文字，run 以轉錄類別失敗，訊息含原因與片段數；至少一個片段成功則 run 以降級結束。沒有語音的片段不算在內；沒有任何有語音的片段時維持現行的沒有語音失敗。
5. **可觀測**：結果行與 RUN SUMMARY 的 `transcribeFailed` 之外，另列原因為截斷、逾時、其他的片段數；README 的排錯章節說明如何判讀。
6. 其他轉錄行為（生成上限、逾時重試、格式不符重試）不變。

## 架構約束

- 不新增參數；不改變對齊、場景、潤飾、摘要、翻譯與 view 的行為（view 的降級原因可顯示新的原因欄位）。
- 嚴格 TDD；測試不使用 Stub 或 Mock，以假服務重現「每次都回報截斷」的情境。
