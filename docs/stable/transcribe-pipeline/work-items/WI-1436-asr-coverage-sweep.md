# WI-1436 以 ASR 補掃 VAD 空隙

本文回答：實作 [ADR-044](../adr/ADR-044-asr-coverage-sweep.md) 要達成的行為。狀態：已核可（2026-10-13）。相依：WI-1429、WI-1432、WI-1435。儲存庫：T（runline-transcribe）；文件部分另開文件工作項。

## 行為與驗收條件

1. **補掃**：VAD-B 之後，相鄰條目之間（含影片首尾）超過 `sweepMinGapSeconds` 的空隙，被切成連續窗口，長度為 `sweepWindowSeconds`（最後一窗可較短，但不短於最小片段長度），逐窗口以與一般段落相同的轉錄路徑與模型轉錄。參數 `sweepEnabled`（預設開啟）、`sweepMinGapSeconds`、`sweepWindowSeconds`、`sweepMinChars` 為管理員可調的 pipeline 參數，預設值由實作者依 ADR-044 的資料提案、架構師核可，並寫入入口文件的參數表與 runbook（單一寫處）。
2. **無語音**：回答為 `language None` 或空者丟棄，計入「補掃無語音」計數。
3. **幻覺過濾**：語言與整部影片主要語言不同且文字短於 `sweepMinChars` 者丟棄，計入「補掃過濾」計數，並在 log 與資料庫留下窗口時間、語言與文字，使其可查；主要語言一致或文字夠長者保留。主要語言以 VAD 段的轉錄結果多數決，沒有 VAD 段時不過濾。
4. **成為條目**：保留的窗口成為新的字幕條目並與 VAD 條目依時間排序、不重疊；文字長度超過一個條目合理上限者，依句子邊界拆成多個條目，時間依字元數比例分配於窗口內。這些條目標記來源為補掃，並標示時間為估計值。
5. **後續階段**：補掃條目走潤飾、核對、翻譯、匯出，遵守 ADR-038 決策 4 的不變式；字幕檔與 SRT 內容包含它們。
6. **紀錄**：資料庫記錄每個條目的來源（VAD 或補掃）與時間是否為估計值，以及被過濾的窗口（時間、語言、文字）；使用下一個可用的結構版本（目前最新為 7），遷移前向、冪等，舊 run 的條目視為來源 VAD。
7. **Console**：`entries` view 顯示條目來源；新增（或擴充）view 列出補掃被過濾的窗口。不改變既有 view 的欄位名稱與值，只新增欄位或 view。
8. **log 與計數**：RUN SUMMARY 與轉錄階段 log 增加補掃的窗口數、保留數、無語音數、過濾數與新增秒數。
9. **關閉時**：`sweepEnabled=false` 的 run，行為與 WI-1434 之後完全相同。
10. 驗證：用 `FakeOpenAiServer` 涵蓋：空隙被補掃並產生條目、`language None` 丟棄、跨語言短回答被過濾、主要語言一致的短回答保留、長文字拆分與時間比例、不與 VAD 條目重疊、`sweepEnabled=false`、影片首尾空隙、沒有 VAD 段（全部由補掃產生）；另以 arr 上同一支影片的 VAD 段與空隙清單（見 ADR-044 背景）作為固定輸入資料；jar 上傳 Engine 後，Console 讀取新 view 一次。

## 架構約束

- 不新增儲存音訊或圖片；補掃窗口的音訊只在記憶體傳給模型。
- 一次一個請求，`llm` 資源容量 1，不改變端點選擇規則（ADR-042）。
- 重試與降級規則、`TRUNCATED` 處理、ADR-038 的其餘不變式不變。
- 薄 jar、嚴格 TDD、不使用 Stub 或 Mock。
