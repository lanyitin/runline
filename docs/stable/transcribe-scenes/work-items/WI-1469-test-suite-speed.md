# WI-1469 縮短測試套件的執行時間

本文回答：如何讓 T 的測試更快而不降低檢查力，以及怎麼驗收。狀態：已核可（2026-10-15）。相依：無（建議在 WI-1467 提交之後做，避免與其工作樹衝突）。決策見 [ADR-065](../adr/ADR-065-test-suite-speed.md)。儲存庫：T。

## 行為與驗收條件

1. **量測報告**：先交一份量測，內容為每個類別與每個測試的耗時、分類（單元、假服務加真實資料庫、外部行程、量測工具）、等待來源（sleep、退避、逾時、行程啟動），並標出前 20 名。量測方法可重現（指令寫在 README）。
2. **去掉人為等待**：測試中的重試退避與逾時使用極短的測試值（以既有參數），不改 production 預設；不新增只為測試存在的 production 後門。去掉等待前後，被測行為的斷言不變。
3. **共用啟動**：Engine、外部行程、資料庫 schema 的啟動在隔離不受影響時由同類別測試共用；每個類別在隨機順序下通過。
4. **並行**：測試以類別為單位並行執行。先讓所有類別隔離（隨機埠、獨立暫存目錄、獨立資料庫檔、不共用可變的環境），再開啟並行；連續執行全套至少 3 次，結果一致，無偶發失敗。
5. **分組**：
   - 每個測試屬於且僅屬於一個任務；改動前後的測試總數與名單一致，報告列出對照。
   - 量測工具的測試依 ADR-065 的建議獨立成任務，不在預設 `test` 內；它能以單一指令執行，並與預設全套互不重疊。若量測顯示不宜如此，先回報。
   - 依賴平台的測試（降噪基準）在不符平台時以前提條件跳過並註明原因；在 Linux 照常執行並通過。非 Linux 的預設全套不再有固定失敗。
6. **目標**：本機全套 ≤ 8 分鐘、單一階段的相關測試 ≤ 2 分鐘（ADR-065 的建議值）；報告列出改動前後的實測。目標不可行時，回報原因與可達的數字，由架構決定。
7. **檢查力不降低**：沒有 `@Disabled`、沒有刪除測試、沒有放寬斷言；沒有新增 Stub 或 Mock；變異檢查（在被測行為中人為破壞一處）抽查至少 5 個經過改動的類別，確認它們仍會失敗。
8. **文件**：README 與 tdd-coder 使用的測試指令說明更新：如何跑相關測試、跑全套、跑量測工具的測試、並行的前提。
9. 不改 production 行為、參數、schema。

## 架構約束

- 不改 production 程式碼的行為；若為了測試隔離必須改 production（例如埠由外部指定），先回報。
- 嚴格 TDD 不適用於純測試基礎設施的重構，但每項改動前後都要有可比較的量測與全套結果；測試重構時被測行為不得改變。
- 並行與共用啟動的任何偶發失敗，視為未完成，不以重試掩蓋。
- 與其他進行中的項目（WI-1467 等）並行時，在獨立的 worktree 與分支上工作。
- 回報時列出：量測前後數字、分類與分任務的對照、並行穩定性的連續執行結果、變異檢查的結果。
