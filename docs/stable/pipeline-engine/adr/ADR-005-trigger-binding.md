# ADR-005 Trigger 由管理員在 Engine 端綁定

狀態：已核可（2026-10-04）。回答：誰決定 pipeline 何時被觸發，以及 trigger 如何運作。

## 背景
Trigger 只有 cron 與 webhook。需決定它們屬於 pipeline 作者還是營運者，並決定觸發時使用的參數、webhook 密鑰的處理、綁定的版本、cron 的表達方式與時間語意，以及重送與當機時的行為。

## 決策
- Pipeline metadata 不含 trigger。
- 管理員在 Engine 端建立 trigger，綁定到特定版本的 pipeline 定義。綁定不跟隨最新版：換版本時管理員更新綁定。新版本的 unsafe 設定本就不繼承（[ADR-006](ADR-006-unsafe-policy.md)），綁定與其一致，由管理員重新確認。
- 每個 trigger 有管理員指定、唯一的名稱，用於網址與 run 的來源名稱。
- 觸發時使用的參數由 trigger 持有：建立或修改 trigger 時帶入一組固定參數，並依該 pipeline 定義的 metadata 驗證（缺少必填、未宣告的參數即拒絕）。參數以管理員提供的原樣保存，預設值由單一建立流程套用，使重新綁定時能重新驗證管理員給的值。Webhook 請求的內容不影響參數，只作為觸發訊號。

### Cron
- 以標準五欄表達式描述，每個 trigger 可指定 IANA 時區，預設為 UTC。
- 表達式解析使用 cron-utils（Apache-2.0）。它成熟、純 Java、以 `java.time` 為基礎，相依只有 Engine 已有的 slf4j；其最後一次發佈為 2023 年，不再有新版本是已知的取捨。函式庫被限制在單一類別內，日後更換只是局部改動。
- 排程為單實例；錯過的時間不補跑；同一排程時間只觸發一次。
- 夏令時間：
  - 不存在的時間（跳時）順延到間隙結束後同樣的距離，使當天仍觸發一次。
  - 重複的時間（回撥）只在第一次出現時觸發，使每日工作不會執行兩次；代價是間隔小於一小時的工作，在重複的那一小時內沒有觸發。
  - 預設時區 UTC 不受夏令時間影響；需要避免此限度的 trigger 應使用 UTC。

### Webhook
- 每個 trigger 一組密鑰：
  - 密鑰由 Engine 隨機產生，只在建立時回傳一次；資料庫只保存其雜湊，之後無法取回。
  - 呼叫端在專用標頭提供密鑰；Engine 以抵禦時間差的方式比對。對不存在的 trigger 也執行同樣的比對，使回應與時間都無法用來判斷 trigger 是否存在。
  - 所有驗證失敗（密鑰錯誤、trigger 停用、trigger 不是 webhook、trigger 不存在）的回應完全相同。驗證失敗的呼叫只記錄 log 與 metric，不寫入觸發紀錄。
  - 管理員可輪替密鑰：產生新密鑰，舊密鑰立即失效。
  - 密鑰不得出現在 log、trace 或錯誤訊息。
- 以 delivery 識別碼去重：呼叫端必須在專用標頭提供 delivery 識別碼，同一 trigger 內重複的識別碼只建立一個 run，之後的請求得到與第一次相同的接受回應。去重由資料庫的唯一性保證，在並行重送下仍成立。
- 去重視窗等於 webhook 觸發紀錄的保留期限：紀錄被清理後，同一識別碼可再次被接受。保留期限由組態決定，預設 7 天（見 [WI-20](../work-items/WI-20-run-retention.md)）。
- 每個 delivery 至多觸發一次：Engine 在觸發已認領、尚未結算時終止，下次啟動時該觸發被標記為「中斷」，其識別碼仍視為已被認領，重送得到接受回應但不產生 run。以非預期的失敗收場的觸發（回應為內部錯誤）可被重送並重新認領。

### 觸發時的建立
- Trigger 觸發時經由與手動建立相同的單一建立流程（[WI-08](../work-items/WI-08-run-orchestration.md)），受 unsafe 設定、參數驗證、資源檢查與並行額度的約束。建立被拒絕時不建立 run，記錄 log 與 metric（含拒絕原因），trigger 保持啟用，並記錄於觸發紀錄。
- 觸發紀錄由管理員可查詢：每次 cron 觸發與每個被接受的 webhook 呼叫一筆，含時間、結果與原因、對應的 run。

## 取捨
- 得到：營運者掌控何時執行與用什麼參數，作者不能自行排程；密鑰在資料庫外洩時不外洩；外部系統無法用請求內容影響參數；版本變更經管理員確認；重送與並行重送不會產生重複的 run。
- 失去：作者無法隨 pipeline 一起版本化排程；每個新版本都需管理員調整綁定；webhook 無法把外部資料傳給 pipeline；密鑰遺失只能輪替，不能取回；cron 函式庫沒有新版本；有夏令時間的時區下，高頻工作在回撥的那一小時不觸發；當機時被中斷的 delivery 不會因重送而補觸發；去重只在保留期限內有效。

## 後果
- Trigger 的資料表以「拒絕刪除」的方式參照 pipeline 定義（[06](../06-data-model.md)）。
- 觸發紀錄隨保留期限清理；縮短保留期限等於縮短去重視窗。
- 排程器與啟動時的「標記為中斷」步驟假設單實例；多實例前需先處理排程重複與他實例進行中觸發被誤標的問題（[07](../07-nfr-risks.md)）。
- 需要由 webhook 內容決定參數時，另開 ADR 修訂本決策。
- 需要「跟隨最新版」時，另開 ADR 修訂本決策，並一併處理其與 unsafe 設定不繼承的關係。
- 需要更換 cron 函式庫時，替換單一類別並維持上述時間語意。
