# WI-1451 可行性關卡：強制對齊

本文回答：經 llm-gateway 以 GPU 執行的 Qwen3-ForcedAligner，能否以可接受的精度與速度對齊 30 秒片段。狀態：已核可（2026-10-14）。相依：WI-1461、WI-1462。決策見 [ADR-051](../adr/ADR-051-long-chunks-and-forced-alignment.md)、[ADR-056](../adr/ADR-056-alignment-on-gateway-gpu.md)。儲存庫：T（量測工具與報告）。量測在 arr 上進行，由使用者或 homelab-deployer 執行。

## 行為與驗收條件

1. 量測工具的對齊步驟可呼叫 gateway 的對齊端點，請求內容與 [05](../05-ipc.md) 的契約相同。
   - 既有的 CPU 對齊方式保留，作為對照。
   - 缺少轉錄文字的片段列為轉錄失敗，其餘片段照常量測，不中斷整次量測。
   - 單一片段的對齊失敗或逾時列為對齊失敗，同樣不中斷。
2. 以 run 8 的影片（日語）取至少 10 個 30 秒片段。
   - 轉錄文字用 Qwen3-ASR 的實際輸出，並套用 WI-1461 的生成上限；
   - 至少涵蓋三種片段：對白密集、有長停頓、有背景雜音或喘息。
3. 量測並記錄於報告：
   - 從 arr 呼叫時，第一個請求的耗時（含 GPU 切換與模型載入），以及之後每片段的耗時（中位數、最大值）；
   - 對齊後第一個 Lemonade 請求的額外耗時（切回與重新載入）；
   - 時間精度：每片段人工標記至少 5 個字詞的起點，計算與對齊結果的誤差（中位數、最大值）；
   - 對齊失敗或明顯錯位的片段數。明顯錯位的定義：該片段標記誤差的中位數超過 1.0 秒。
   - CPU 方式的初步數據（2026-10-14，arr 8 vCPU）作為對照，列在報告中。
4. 通過條件（由使用者核可）：
   - 一小時影片（約 120 片段）的對齊總時間，含兩次 GPU 切換，不超過 30 分鐘；
   - 起點誤差中位數不超過 0.3 秒；
   - 失敗片段少於 10%。
5. 報告放在 runline 的 `docs/draft/transcribe-scenes/`，從工作項總覽連結，並列出重跑量測的步驟。

## 架構約束

- 只驗證可行性，不改 pipeline 的階段；量測工具以後續項目可重用的方式留下。
- 量測工具可以直接呼叫 gateway；pipeline 本身必須經 Engine 資源（ADR-056）。
- 不改動 Lemonade 與 gateway 的設定。
- 不通過時停下來回報，由架構決定。
