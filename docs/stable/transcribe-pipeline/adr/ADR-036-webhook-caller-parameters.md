# ADR-036 webhook 的呼叫端提供參數

狀態：已核可（2026-10-11）。取代 [ADR-005](../../pipeline-engine/adr/ADR-005-trigger-binding.md) 中「Webhook 請求的內容不影響參數，只作為觸發訊號」一條；ADR-005 其餘不變。回答：webhook 如何讓呼叫端傳入參數而不削弱安全模型。

## 背景

transcribe pipeline 需要每次觸發指定不同的檔名。ADR-005 規定參數只能在建立 trigger 時固定，且 webhook 本文從不讀取。

## 決策

1. trigger 新增「呼叫端提供的參數」清單，只有 webhook 可設定。清單中的名稱必須是綁定版本所宣告的參數；一個參數不能同時是固定值與呼叫端提供。
2. 建立或修改 trigger 時檢查：綁定版本中沒有預設值、又不在固定參數內的必填參數，必須在呼叫端提供清單內，否則拒絕（避免永遠建立不出 run 的 trigger）。
3. 清單為空的 webhook 行為與現在完全相同：本文不讀取、不影響參數。
4. 清單不為空時，請求本文為 JSON 物件，鍵為參數名稱、值為文字。處理順序：先驗證密鑰與 delivery 識別碼（失敗行為不變），通過後才讀取本文。
5. 本文大小有組態上限；清單外的鍵、缺少必填的鍵、值不符 pipeline 對該參數的規則，皆回 400，指出參數名稱，不回值。400 不消耗 delivery 識別碼，呼叫端可修正後以同一識別碼重送。
6. 通過後的值與固定參數合併，再走既有的 run 建立流程（unsafe、參數檢查、資源、並行限制皆適用）。run 的參數紀錄含這些值。
7. 去重不變：同一 delivery 識別碼只第一次生效，之後回相同的 202，本文被忽略。
8. 呼叫端提供的值不得用於機密；文件明說。

## 取捨

- 得到：一個 trigger 服務任意多檔案；密鑰與去重沿用。
- 失去：持密鑰者可影響 run 參數，風險由 pipeline 自行驗證其參數（例如路徑）承擔；值會進入 run 紀錄。
- 否決：以 URL 查詢字串傳值（值會進入存取 log）；每檔一個 trigger（不可用）。

## 後果

- 須修訂 README「Triggers」與 `08-api.md` 的 webhook 與 trigger 欄位、新增 400 錯誤碼；Console 的 trigger 表單可選擇支援。
- 因參數被拒的呼叫記在指標與 log，與認證失敗同樣不寫入觸發紀錄：400 不消耗 delivery 識別碼，而沒有識別碼的紀錄不會被保留清除移除，會無限增長。
