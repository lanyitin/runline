# ADR-048 Console 以單一窄版面斷點提供手機版面

狀態：已核可（2026-10-13）。補充 [ADR-015](../../pipeline-engine/adr/ADR-015-console-frontend.md)；不修訂任何 stable 決策。回答：Console 如何在手機上可用，版面規則與驗證標準為何。

## 背景

Console 為 Svelte 靜態 SPA，由 Engine 提供。版面是桌面版：固定側邊欄、寬表格、桌面尺寸的對話框。使用者要在手機上查看 run 與 log，也要能做管理操作。

## 決策

1. **版面只分兩種：窄版面與寬版面**，以視窗寬度 768px 為界；768px 以上（含平板）為既有的寬版面，其行為與外觀不變。斷點在設計系統中定義一次，各處引用，不各自重定。
2. **導覽**：窄版面時側邊欄收成抽屜，由頂列的選單鍵開關；選取項目、按 Esc 或點遮罩後關閉；開啟時焦點進入抽屜、關閉時回到選單鍵；選單鍵與抽屜有名稱與展開狀態標示，文案走多語系。
3. **頂列與麵包屑**：窄版面不得溢位；次要資訊（如 Engine 資訊）可省略，主要操作（導覽、語言、登出）保留。
4. **主要清單改為卡片**：run 清單、pipeline 清單與總覽中的清單，在窄版面每筆為一張卡片，顯示該清單原有的關鍵欄位（狀態、名稱、時間等），可點進詳情；寬版面維持表格。
5. **其他表格**：管理頁與詳情頁中的表格（含 view 表格）在窄版面於自身容器內水平捲動，第一欄固定；整頁不得水平捲動。
6. **log 檢視**：長行在自身容器內換行或捲動，既有的即時串流、自動捲動與合併行為不變。
7. **表單與對話框**：窄版面表單為單欄；對話框不超出視窗，內容過長時在對話框內垂直捲動，操作鈕保持可見。
8. **觸控**：窄版面下按鈕、連結與表單控制項的可點區域至少 44px；輸入欄位字級至少 16px，避免 iOS 聚焦時自動放大。
9. **長內容**：雜湊、名稱與伺服器回傳的文字在容器內換行或截斷並可看全文；不可信文字維持既有的純文字呈現。
10. **驗證標準**：每個路由在 360px、390px 與 768px 寬下，整頁不得水平溢位，主要操作可點；以既有的真實瀏覽器 e2e 搭配手機尺寸視窗驗證。

## 取捨

| 選項 | 優點 | 缺點 |
|---|---|---|
| 採用：單一斷點、卡片加捲動表格、抽屜導覽 | 規則少、可預測；查看頁體驗好；桌面不受影響 | 平板使用寬版面，窄平板直立時空間較緊 |
| 多斷點（手機、平板、桌面） | 每種裝置更貼合 | 規則與測試倍增，現階段收益小 |
| 全部水平捲動 | 實作最簡單 | run 清單在手機上難讀 |
| 底部分頁列 | 拇指好按 | 管理頁項目多，放不下 |

## 後果

- 每個新頁面或元件都要遵守窄版面規則，驗證標準涵蓋所有路由。
- 既有 Console 測試與 e2e 仍須通過，寬版面行為不得改變。
- 窄版面的文案（選單鍵、抽屜）需要所有支援語言的翻譯。
