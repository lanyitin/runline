# ADR-058 長片段、場景與生成上限的預設值

本文回答：WI-1451、WI-1452 量測後，transcribe-scenes 的參數預設值取多少、依據是什麼。狀態：已核可（2026-10-14）。補充 [ADR-051](ADR-051-long-chunks-and-forced-alignment.md)、[ADR-052](ADR-052-scenes-as-llm-units.md)、[ADR-055](ADR-055-thinking-policy-and-early-stop.md) 中尚未固定的預設值，不取代任何決策。

## 背景

- 量測在 arr 與 gateway 上進行：影片 run 8 的 10 分鐘段落（180 至 780 秒），所有請求經 gateway。
- 長片段：19 個送出，0 失敗、0 截斷；最大請求 1,407,894 位元組，資源的 `maxRequestBytes` 為預設的 32 MiB。
- 轉錄的每秒音訊 token 數：長片段最大 3.21（19 個樣本）。
- 潤飾、片段摘要、翻譯：一小時影片推算 4 張畫面 47.1 分鐘、6 張 46.0、8 張 50.5；加上轉錄 1.5 分鐘與其他階段 16.6 分鐘，合計 64 至 69 分鐘，遠低於 3 小時。
- 場景偵測：門檻 0.3、0.4、0.5 分別得 27、24、20 個場景，一小時影片的場景片段數約 320、321、320；最短場景 15.8 秒。使用者看畫面判定三組全部合理。
- 轉錄品質與換人標記的正確率延後到成品字幕核對（[WI-1452](../work-items/WI-1452-feasibility-long-chunks-and-segments.md)），所以與品質有關的預設值以成本與請求大小為依據，核對後可調整。

## 決策

| 參數 | 預設值 | 依據 |
|---|---|---|
| `chunkTargetSeconds` | 30 | 量測的長度；請求大小在上限內，0 失敗 |
| `chunkMaxSeconds` | 33 | 量測的切法在目標前後 3 秒內找切點，最長約 33 秒；最大請求以此為準 |
| `asrTokensPerSecond` | 12 | 實測最大值的約 3.7 倍，失控時仍很快被截止 |
| `asrTokenMargin` | 64 | 沿用 WI-1461 的預設 |
| `framesPerSegment` | 4 | 成本與 6、8 張相差不到 4 分鐘，請求最小（約 114 KB），契約守住 8 次中 8 次；品質缺數據，核對後可調高 |
| `segmentTargetSeconds` | 12 | 量測與成本推算的長度 |
| `frameMaxEdgePixels` | 512 | 量測的邊長 |
| `sceneThreshold` | 0.3 | 三組都經判定合理，場景片段數幾乎相同（320、321、320），取門檻最低者以保留較多真實的切換 |
| `sceneMinSeconds` | 3 | 本素材的最短場景 15.8 秒，1 至 3 秒結果相同；取較長者以併入閃爍造成的短場景 |

## 取捨

- 得到：預設值有實測依據，成本遠低於 3 小時目標，請求遠低於 `maxRequestBytes`。
- 失去：
  - 只有一部影片的一段 10 分鐘；其他類型的素材（快節奏、暗場）可能需要調整，參數保持可調。
  - 品質相關的預設值（`framesPerSegment`、`chunkTargetSeconds`）尚未經人工驗證，成品字幕核對後再檢視。
  - 門檻 0.3 對鏡頭微動較敏感，場景數較多；成本差異可忽略。

## 後果

- WI-1455、WI-1456、WI-1457 以上表為預設值宣告參數。
- 成品字幕核對後，若品質不佳，依序檢視 `framesPerSegment`、`chunkTargetSeconds` 與提示詞，另開決策調整。
