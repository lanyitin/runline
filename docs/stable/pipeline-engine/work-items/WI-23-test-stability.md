# WI-23 測試穩定性

本文回答：如何消除既有測試中的不穩定（偶發失敗），使每次完整執行的結果可信。狀態：已核可（2026-10-05）。相依：無。

## 背景

[WI-22](WI-22-surface-cleanup.md) 的第一次完整執行中，觸發紀錄的測試因 `ConcurrentModificationException` 失敗，第二次完整執行通過。原因是測試支援程式在另一個執行緒仍在寫入日誌列表時讀取它。不穩定的測試使每次驗收都得靠重跑判斷失敗是否真實，也會掩蓋真正的競態問題。

## 行為與驗收條件

- 已知的不穩定測試被修正：測試支援中擷取日誌的類別，在多個執行緒同時寫入與讀取時不再丟出例外，也不遺漏或重複事件。
- 盤點所有模組的測試支援與測試程式中，被多個執行緒共用的可變狀態（日誌擷取、時鐘、計數器、收集結果的列表、排程器與測試執行緒之間的共享資料），列出每一處並說明其執行緒安全性；有風險者一併修正，無風險者說明理由。盤點結果寫在回報中。
- 盤點同時涵蓋依賴睡眠或固定等待時間的測試；以條件等待或可控制的時鐘取代不必要的睡眠，不得放寬斷言或縮小被驗證的行為。
- 修正的有效性以重複執行驗證：
  - 曾失敗的測試（`TriggerFirerTest` 相關）在連續重複執行至少 50 次下全數通過。
  - 觸發、排程、資源、run 排程與優雅關閉相關的測試類別，各在連續重複執行至少 20 次下全數通過。
  - 完整的測試（含打包形態的測試）連續執行至少 5 次，全數通過。
  - 回報重複執行的指令與結果，並保留各次的結果。
- 為了證明修正確實消除競態，對日誌擷取以多執行緒壓力測試驗證：在多個執行緒同時寫入下，反覆讀取仍不丟出例外且事件完整；此測試在還原舊實作時必須失敗（暫時還原再恢復）。
- 不刪除任何既有測試、不放寬任何既有斷言；測試數量不減少，新增的壓力測試除外。
- 若盤點發現競態來自正式程式碼而非測試支援，停下來回報，不自行修改正式程式碼。
- 建置、全部測試在 JDK 25 下通過，`ktfmtCheck` 通過。

## 架構約束

- 只修改測試與測試支援程式；不修改任何模組的正式程式碼。
- 測試使用真實 PostgreSQL（Testcontainers）與真實行程，不使用 Stub 或 Mock；時間以可控制的時鐘提供，不以睡眠換取通過。
- 不新增外部相依；不新增 git hook 或 CI；完成程式碼變更時依專案規則先以 ktfmt 格式化。
