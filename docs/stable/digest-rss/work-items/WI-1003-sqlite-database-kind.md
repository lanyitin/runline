# WI-1003 `jdbc-pool` 新增 `sqlite` 資料庫種類（Engine 與 devkit）

本文回答：Engine 與 devkit 如何支援 SQLite 資料庫種類。狀態：已核可（2026-10-08）。

目標：管理員可把一個 SQLite 資料庫檔定義為共享資源，pipeline 以既有的窄 SQL 存取端使用它，保持 safe；開發人員在 devkit 本機執行時同樣可用。這是 Engine 與 devkit 的擴充，依 [ADR-024](../adr/ADR-024-sqlite-run-store.md) 與 ADR-019 決策 7；既有契約參考 [WI-48](../../pipeline-engine/work-items/WI-48-jdbc-pool-resource.md)。工作儲存庫：runline。

## 驗收條件

1. 資源設定接受資料庫種類 `sqlite`，以資源根目錄下的相對路徑指定資料庫檔；路徑不得跳出根目錄，不接受自由格式連線字串，不需要主機、埠、帳密、金鑰庫別名。不合規回 422 `invalid_resource`，`problem` 與既有類別一致。
2. 資料庫檔不存在時，在第一次需要時建立；父目錄不存在則回報檔案類錯誤。
3. 設定檔固定：可同時讀取的日誌模式、啟用外鍵、設定忙碌等待時間；管理員不可更改這些行為，只能設定 WI-48 既有的逾時與額度。
4. 存取端契約不變（查詢、更新、交易），SQL 文字原樣交給資料庫；型別對應、錯誤分類（含檔案鎖定、約束違反）、列數與大小上限與 WI-48 一致。
5. 連線額度與並行：多個 run 同時使用同一資料庫時，寫入互相等待而不是失敗，直到逾時；以真實並行的 run 驗證。
6. 資源檢查端點可驗證資料庫檔可開啟、可寫入；型別目錄端點（`GET /api/v1/resource-types`）列出 `sqlite` 與其允許的欄位，Console 的資源表單依目錄顯示。
7. 取消與強制釋放：進行中的查詢被中斷、交易被回滾、連線在清理後才歸還。
8. 驅動只由 Engine 載入一次；連續多次 run（各自獨立 class loader）使用同一資料庫都成功，這是本項的核心驗證。
9. 外部工具可在 Engine 運作時以唯讀方式開啟資料庫檔並讀取已提交的資料。
10. 08-api、型別目錄與 WI-48 的文件一致性更新；`ApiDocumentationTest` 保持通過。
11. devkit 的本機資源定義接受 `sqlite`：以本機組態指定資料庫檔位置（相對於本機資源根目錄），其他欄位與 Engine 的規則一致；不合規時明確失敗。
12. Engine 與 devkit 對 `sqlite` 跑同一組行為測試（沿用 WI-48 的共用行為套件做法）：交易、錯誤類別、型別對應、取消、同時讀取；devkit 路徑下連續多次 run 同樣成功。

## 架構約束

- 型別集合維持封閉；只新增資料庫種類，不新增資源型別，不改 core 的存取端契約。
- 以真實 SQLite 與真實檔案系統驗證，不使用 Stub 或 Mock。
- 本項觸及 pipeline-engine，完成時須在 ADR-019 與 WI-48 以連結標示擴充。
- 驅動在 Engine 載入一次若不可行，停下來回報，由架構決定改用 PostgreSQL（ADR-024 備援）。
