# WI-1009 下載派發

目標：對保留的文章啟動下載，並記錄派給了誰。行為參考：來源的 `dispatch-downloads.mjs`、`lib/torrent.mjs`。工作儲存庫：`runline-digest-rss`。

## 驗收條件

1. 來源順序：feed 項目內的 torrent／magnet 優先，其次為擷取結果的下載欄位；有者送 rqbit，皆無者以文章 url 送 streamexa。
2. 每次派發寫入 DOWNLOAD（目標服務、種類、連結、結果、狀態、嘗試次數、錯誤）；「哪些文章被派給 streamexa 或 rqbit」可由資料庫完整回答。
3. 以文章為單位冪等：已成功者重試時不重複派發，失敗者重試；判斷依據是資料庫紀錄。
4. 任何失敗不影響摘要與標已讀，run 仍成功結束，失敗寫入紀錄與 log。
5. 沒有保留文章時不做任何呼叫。
6. 以兩個 MCP 服務的 Fake（真實實作）驗證；token 依 ADR-023，不入 log 與資料庫。

## 架構約束

- 此階段不做任何判斷，只依既有資料派發。
