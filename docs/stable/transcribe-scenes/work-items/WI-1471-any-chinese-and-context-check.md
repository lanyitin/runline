# WI-1471 翻譯接受任何中文字形，語境檢查不誤判短句

本文回答：移除翻譯的簡體字檢查，以及語境重複檢查如何不誤判短句。狀態：已核可（2026-10-15）。相依：WI-1468（已完成）。決策見 [ADR-067](../adr/ADR-067-any-chinese-is-accepted.md)。儲存庫：T。

## 行為與驗收條件

1. **字形不檢查**：翻譯回答中的行含簡體字、繁體字或兩者混用，都不判違規；`SIMPLIFIED_CHARACTERS` 不再出現在驗證、重試原因、結果行、RUN SUMMARY 的原因計數與 README。譯名（`NAMES:`）不檢查字形。
2. **未翻譯仍判定**：回答的行含假名仍為 `UNTRANSLATED`；其他回答契約（條目數、序號、時間不變、行數與換人規則、語境內容不得出現）不變。
3. **語境重複檢查**：條目只因為文字與語境的某條譯文相同，而它的來源文字與該語境條目的來源文字不同，不判 `CONTEXT_RETURNED`；回答中出現語境的來源文字、或同一條同時帶有語境的來源與譯文，仍判違規。
4. **預設提示詞**：預設 `translateSystemPrompt` 不再要求繁體字，改為要求用中文翻譯；README 的提示詞引文與文件測試同步。覆寫提示詞的行為維持。
5. **重現情境**（假服務）：
   - 回答混用簡體與繁體字，被接受；
   - 回答全為簡體字，被接受；
   - 前一片段的譯文為「亮亮的。」，本片段某條來源不同、譯文也是「亮亮的。」，被接受；
   - 回答抄回語境的來源文字，仍為 `CONTEXT_RETURNED`；
   - 回答仍含假名，仍為 `UNTRANSLATED`。
6. **文件**：README 的驗證表、限制說明、排錯章節移除簡體字的內容；文件測試維持相符。
7. 其餘行為（條目、時間、換人資料、各階段規則）不變。

## 架構約束

- 不改 Engine；不新增參數；不改 schema。
- 嚴格 TDD；測試不使用 Stub 或 Mock。
- 測試範圍依 tdd-coder 定義的 §1.1，不跑全套。
- 與其他進行中的項目並行時，在獨立的 worktree 與分支上工作。
- 回報時列出測試範圍與結果、jar 路徑與 sha256、提交。
