# WI-1014 digest-rss 的資源角色與用途註記

目標：digest-rss 以角色宣告它需要的三個資源，每個角色帶型別與用途，管理員與開發人員可在設定介面選擇實際資源。工作儲存庫：`runline-digest-rss`。

## 驗收條件

1. 三個角色：語言模型（型別 `openai-compatible`）、紀錄資料庫（型別 `jdbc-pool`）、服務憑證檔（型別 `file`）。角色名稱為程式內部的穩定識別，不再是管理員必須建立的資源名稱。
2. 每個角色有一句用途說明，清楚到管理員只看它就知道該選哪種資源（例：該模型需支援圖片輸入與對話、資料庫需可寫入、憑證檔放什麼）。
3. 上傳後 Engine 的 pipeline 查詢顯示三個角色的型別與用途。
4. 程式經由角色取用存取端，不假設任何實際資源名稱。
5. 開發入口的本機資源定義以角色名稱為鍵，仍可執行；既有測試維持通過。
6. 原 WI-1002 的固定資源名稱不再出現在程式、文件與本機設定中。

## 架構約束

- 依 ADR-025 與 WI-1012 的最終契約；契約與本文衝突時停下來回報。
- 不改變 pipeline 為 unsafe 的判定結果（ADR-022）。
