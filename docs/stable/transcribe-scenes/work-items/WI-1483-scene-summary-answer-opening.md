# WI-1483 場景層摘要的回答開頭由預填固定

本文回答：thinking 關閉時，場景層摘要請求要如何固定回答的開頭，以及解析要接受什麼。狀態：已核可（2026-10-18）。相依：無。決策見 [ADR-077](../adr/ADR-077-scene-summary-answer-opening.md)。儲存庫：T。

## 行為與驗收條件

1. **預填**：thinking 關閉時，使用場景層提示的每個請求（場景摘要與逐層彙整的中間摘要），結尾的助理輪為「已結束的空推理區塊」之後接上第一行標記與換行。標記是契約規定的 `SUMMARY:`；覆寫 system prompt 的呼叫端不能因此改變標記，也不能刪去標記（沿用 [ADR-054](../adr/ADR-054-scene-summaries-and-translation-context.md) 的規定）。
2. **thinking 開啟時**不加預填，行為與現行相同。
3. **其他層不變**：片段層與全片層的請求形狀、提示、取樣參數、生成上限都不變。
4. **解析**：
   - 回答帶標記或不帶標記都接受；
   - 回答開頭的空推理區塊忽略（服務會把預填連同續寫一併回傳）；
   - 回答中標記重複出現時，以第一個標記之後的內容為準；
   - 解析後的摘要文字與現行格式一致（標記之後的四個欄位）。
5. **紀錄**：EXCHANGE 的請求紀錄能看出該請求的預填含標記，日後可與預填不含標記的請求比較；回應紀錄仍是服務回傳的原文。
6. **續跑與沿用**：續跑時沿用的舊摘要不重新產生；新請求依本項的形狀送出。
7. 其餘行為不變（重試、降級、及早止損、生成上限、逾時）。

## 架構約束

- 不改 Engine；不新增資料表欄位。
- 嚴格 TDD；測試以假服務重現兩種服務行為：回傳整段預填加續寫；只回傳續寫。另保留少量契約測試守住請求形狀。
- 對真實 Lemonade 的行為（預填被當成續寫的開頭、不回 400）已在量測中觀察到，實機再驗證由 homelab-deployer 執行，不在本項。
- 回報時列出改動的提示預設值，與 README 摘要章節需同步的敘述。
