# ADR-046 以 DeepFilterNet3 降噪後再做 VAD，取代雙 VAD

本文回答：silero 漏判人聲時，改以降噪前處理取代第二個 VAD 偵測器是否可行，以及採用的邊界。狀態：已核可（2026-10-13）。取代 [ADR-045](ADR-045-dual-vad.md)（雙 VAD）與其工作項 WI-1438、WI-1439；與 [ADR-044](ADR-044-asr-coverage-sweep.md)（ASR 補掃）互補。

## 背景

使用者決定捨棄雙 VAD，改用 DeepFilterNet3（DFN）降噪後再做 VAD。homelab-deployer 在 arr 的 NTRH-002-C.mp4（234 秒）上的離線實驗，以下各項的 ASR 一律用原始音訊：

| 設定 | 區間數 | 日語字數 | 非日語段數 |
|---|---|---|---|
| silero@0.5，原始音訊（現況） | 27 | 232 | 1 |
| silero@0.5，DFN 衰減上限 24 dB | 37 | 327 | 3 |
| silero@0.5，DFN 預設（衰減上限 100 dB） | 40 | 340 | 5 |
| 雙 VAD（0.3／0.7）0.35／0.25，原始音訊 | 42 | 403 | 17 |
| 雙 VAD 0.45／0.40，原始音訊 | 53 | 416 | 12 |

- 降噪後 silero 的日語字數比現況多約 41%，比雙 VAD 少約 19% 到 21%。
- 降噪後送 ASR 的音訊會使辨識變差（87 段實驗中日語字數 458 降為 437 與 440，且部分原本正確的台詞變成他語），所以降噪音訊只用於 VAD，ASR 一律用原始音訊。
- DFN 衰減上限 24 dB 的 ASR 副作用比預設小，新增段落的非日語段較少。
- 工具：deep-filter v0.5.6（Rust 預編譯，授權 MIT 或 Apache-2.0 擇一，無附加條件）；輸入 48 kHz 單聲道；234 秒音訊在筆電 CPU 約 10 秒。
- macOS arm64 預編譯檔 `deep-filter-0.5.6-aarch64-apple-darwin`（27,877,081 位元組）的 sha256 為 `4601e7f4e4c03e59a4c5b5000216ef3add3e808799cfccd95e14e83ea4611081`，用於開發與本機測試。
- 延遲：預設輸出相對輸入落後 487 個樣本（48 kHz，約 10 毫秒，互相關實測）；啟用延遲補償後落後為 0，輸出比輸入短 1440 個樣本（30 毫秒）。
- ASR 對相同輸入有少量不穩定（temperature 0 下，跨批次有 1 到 4 段文字不同），比較看總量，不看單段。

## 決策

1. 在 VAD 之前增加降噪步驟，使用 DFN3，作為獨立行程，與 silero 工具同為外部工具。pipeline 只依契約，不依內部實作。
2. 降噪輸出只供 VAD 使用；分段後的音訊切片與 ASR 一律取自原始音訊，條目時間不變式（ADR-038 決策 3、4）不變。
3. 降噪衰減上限做成管理員可調的參數（`denoiseAttenLimitDb`），預設 24 dB；降噪開關也是參數（`denoise`），關閉時行為與現況完全相同。衰減上限為 0 時不做降噪，工具原樣輸出。
4. 降噪後的 VAD 沿用現有 silero 工具與 ADR-038 的判定及門檻，不引入第二個偵測器、不做機率合併。
5. 降噪工具不可用（未設定、不存在、執行失敗）且開關開啟時，run 以 `CONFIGURATION` 失敗並指出原因，不靜默退回。
6. ADR-044 的 ASR 補掃保留，負責降噪後 VAD 仍漏掉的空隙。
7. 工具版本與模型雜湊固定並記錄於專案文件；缺少或不符時失敗，不連網下載。
8. 工具必須使用延遲補償，補償後輸出與輸入的對齊延遲為 0，使降噪不引入時間位移。輸出的長度不比輸入長，最多短 100 毫秒（模型前瞻的尾端）；pipeline 轉為 16 kHz 時於尾端補零回原長度。

## 取捨

| 選項 | 優點 | 缺點 |
|---|---|---|
| A. DFN3 降噪後 silero（採用，使用者決定） | 單一偵測器；無 TEN 授權的附加條件；DFN 授權乾淨；不需在 Java 重現前處理 | 日語召回比雙 VAD 低約 20%；多一個 Rust 執行檔；音訊須以 48 kHz 擷取；每 234 秒多約 10 秒處理 |
| B. 雙 VAD（ADR-045） | 召回最高 | 授權有附加條件；Java 前處理須重現；兩個工具 |
| C. 降噪加雙 VAD | — | 在雙 VAD 上沒有額外增益（日語字數 402 到 409 對 403），不採用 |

## 後果

- 召回比雙 VAD 差的部分由 ADR-044 的補掃彌補；兩者合併後的實際成效待 arr 的 run 驗證。
- 雜音造成的短段仍由 ADR-044 的幻覺過濾處理。
- 部署多一個外部工具：Linux／AMD64 容器內可用的 DFN 執行檔與模型。
- pipeline 的音訊擷取多一份 48 kHz 單聲道（先升頻 16 kHz 的做法在 VAD 上較差，不採用）。
- ADR-045 與 WI-1438、WI-1439 標為已取代並保留，TEN 的實驗數據與授權分析供日後參考。

## 部署可行性（已在 arr 的 Engine 容器驗證）

- 預編譯檔 `deep-filter-0.5.6-x86_64-unknown-linux-musl`（36,417,296 位元組，sha256 `70775e251eee44c0f2451a1e833326cf8bcbbe304d3e7cd12851e6fce72ef7da`）為靜態連結，不依賴 glibc 或其他函式庫；模型內建於執行檔，不需模型檔、不連網。
- 在 Engine 容器（Ubuntu 26.04、x86_64、uid 1000）內執行成功：234 秒音訊耗時 38.1 秒（即時率約 0.16），記憶體峰值約 123 MiB。
- 輸出與 Mac 版 99.99% 樣本相同（最大差 1 LSB）；silero 在其上得到相同結果：37 段、涵蓋 20.5%、邊界差 0.0 秒。
