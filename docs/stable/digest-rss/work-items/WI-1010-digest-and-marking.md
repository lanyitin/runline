# WI-1010 摘要、檢查與標已讀閘門

目標：產出 digest 並記入資料庫，且只在條件全部滿足時標已讀。行為參考：來源的 `run-digest-facts.sh`、`write-summary.mjs`、`assemble-digest.sh`、`check-digest.sh`、`analysed-ids.sh`。工作儲存庫：`runline-digest-rss`。

## 驗收條件

1. 事實（計數、表格、封面、連結）完全由程式從本次 run 的資料庫紀錄計算，不經模型。
2. 主題摘要為唯一第二種模型呼叫，thinking 關；沒有保留文章時不呼叫。摘要失敗時仍產出只含事實的 digest。
3. digest 為摘要與事實的位元組串接，不由模型重打連結。
4. 檢查階段確認 digest 由本次事實組成，結果記錄，不改變 run 結果。
5. 可標已讀集合：有保留或過濾判定、且有 url 者（兩種都標）；擷取失敗、文字不足、未被讀者處理、被隔離者都不在其中。
6. 標記閘門：標已讀開關非明確開啟、或不存在 digest，集合為空且零標記；以「閘門關閉時對 FreshRSS Fake 零呼叫標記」驗收。
7. 摘要、事實與完整 digest 寫入 DIGEST，以 run 識別；run 結束輸出其位置。
8. 計數與 digest 內容、資料庫紀錄三者一致（逐位比對，不只看數字）。

## 架構約束

- 閘門在程式內，不依賴任何提示。
- 摘要不得使用模型輸出決定 url、標題、路徑。
