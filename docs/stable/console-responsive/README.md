# Console 響應式版面（手機可用）

本文回答：Console 如何在手機瀏覽器上可用，範圍、版面策略與驗證方式為何。狀態：已核可（2026-10-13）。補充 [ADR-015](../pipeline-engine/adr/ADR-015-console-frontend.md)（Console 前端）；沒有與 stable 衝突，stable 原本沒有任何手機或響應式的要求。

## 1. 需求摘要

- 目標：在手機瀏覽器上使用 Console，主要是查看 run、log、pipeline 與 view，管理頁也要能操作。
- 角色：開發人員與管理員，兩種角色在手機上都能登入並使用。
- 範圍內：窄螢幕的導覽、版面重排、表格呈現、表單、對話框、觸控操作、驗證。
- 範圍外：原生 App、離線、推播、新的視覺設計稿、Engine 與 API 的任何改動、真機自動化測試。
- 假設（已由使用者確認採推薦值）：
  - 目標寬度從 360px（直式手機）到桌面；平板落在桌面版面，但不得溢位。
  - 瀏覽器為目前主流的 iOS Safari 與 Android Chrome。
  - 查看資訊的頁面（run、log、pipeline、view）精修；管理頁保證可用，不逐頁調整。
  - 沿用現有設計系統的 token，不新增設計稿。
- 待確認問題：無。

## 2. 現況觀察

- 已有 `viewport` meta；整個 Console 只有一個斷點，用來在 1100px 以下隱藏頂列的 Engine 資訊。沒有任何版面重排。
- 側邊欄、13 個含表格的元件、對話框與 log 檢視都是桌面版面。
- 前端沒有 CI；驗證用既有的真實瀏覽器 e2e（`console/e2e`）。

## 3. 方案比較與推薦

| 面向 | 採用 | 未採用 |
|---|---|---|
| 範圍 | 全部頁面可用，查看資訊的頁面精修 | 只做查看頁（管理頁在手機上破版）；全部精修（工作量最大） |
| 表格 | 主要清單在窄螢幕改為卡片，管理頁寬表格在自身容器內水平捲動並固定第一欄 | 全部水平捲動（run 清單難讀）；全部卡片（工作量最大） |
| 導覽 | 窄螢幕時側邊欄收成抽屜 | 底部分頁列（管理頁項目太多放不下） |

決策與取捨見 [ADR-048](adr/ADR-048-responsive-console.md)。

## 5. IPC 模型

不適用：只用既有的同源 `/api/v1`，不改變任何 API 契約。

## 6. 資料模型

不適用：沒有資料變更。

## 7. 非功能性考量與風險

| 風險 | 緩解 |
|---|---|
| 桌面版面被改壞 | 寬版面的行為與外觀不變，既有 Console 測試與 e2e 必須全部通過 |
| 手機上的水平溢位（版面被截掉或整頁橫向捲動） | 驗證項目明列：在 360px、390px、768px 下每個路由整頁不得水平溢位 |
| 長內容（log 行、雜湊、名稱、伺服器回傳的文字）撐破版面 | 長內容在自身容器內換行或捲動；不可信文字維持既有的純文字呈現 |
| 觸控難以點中、iOS 聚焦輸入時自動放大 | 窄螢幕下可點元件至少 44px，輸入欄位字級至少 16px |
| 抽屜的鍵盤與螢幕閱讀器可用性 | 焦點管理、Esc 關閉、名稱與狀態標示，沿用既有 `Dialog` 的做法 |
| 只在模擬視窗驗證，與真機有差異 | 接受；使用者可事後在真機驗收，差異以缺陷處理 |
