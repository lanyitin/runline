# WI-1400 webhook 的呼叫端提供參數

狀態：已核可（2026-10-11）。實作已完成於 runline 工作樹，待驗收。儲存庫：R。相依：無。本文回答：Engine 要達成什麼行為，使 webhook 能傳入參數。決策見 [ADR-036](../adr/ADR-036-webhook-caller-parameters.md)。

## 目標

webhook trigger 可宣告一組「呼叫端提供的參數」；呼叫時由請求本文帶入，驗證後與固定參數合併建立 run。

## 驗收條件

1. 建立與修改 trigger 的 API 可設定呼叫端提供清單，只限 webhook；cron 設定時被拒絕並指出原因。
2. 清單中的名稱不是綁定版本宣告的參數、與固定參數重複、或必填且無預設的參數既不固定也不在清單時，建立與修改皆被拒絕並指出參數名稱；被拒的變更不改變任何東西。trigger 重新綁定到另一版本時重新檢查。
3. 清單為空的 webhook 行為與修改前完全相同，包含不讀取本文。
4. 清單不為空時：密鑰或 delivery 識別碼錯誤的回應與現在完全相同，且不讀取本文；通過後才讀取本文。
5. 本文不是 JSON 物件、超過大小上限、含清單外的鍵、缺少必填鍵、或值不符該參數規則時，回 400 並指出參數名稱（不回值）；此時不消耗 delivery 識別碼，同一識別碼修正後可重送並成功。
6. 通過時回 202；run 的參數為固定參數加呼叫端值，且既有的 unsafe、參數檢查、資源與並行限制照常適用；run 的紀錄可見這些值。
7. 同一 delivery 識別碼重送回相同的 202，不建立第二個 run，本文被忽略。
8. 本文大小上限由組態決定，有預設值，文件列出。
9. 因參數被拒的呼叫在指標與 log 中與認證失敗區分（各有原因分類）；不寫入觸發紀錄（400 不消耗 delivery 識別碼，無識別碼的紀錄不會被保留清除移除）；密鑰與參數值不出現在 log、指標或錯誤訊息（值只在 run 的參數紀錄中）。
10. README「Triggers」、`08-api.md` 與 ADR-005 的相關敘述依 ADR-036 修訂；`ApiDocumentationTest` 通過。

## 架構約束

- 不新增資源型別；不改變 cron 行為；認證模型不變。
- 呼叫端提供的值視為不可信輸入，不得作為機密使用。
