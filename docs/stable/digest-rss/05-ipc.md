# IPC 模型

本文回答：pipeline 與各外部系統怎麼通訊、語意與失敗處理為何。

| 對象 | 通道 | 語意 | 失敗處理 |
|---|---|---|---|
| Lemonade | `openai-compatible` 存取端（同步或串流，圖片隨請求） | 讀者：每篇每條件一次、thinking 開；摘要寫手：thinking 關。並行度 1 | 中途消失：對尚未判定者重試一次，再失敗則放棄並記錄；回應的模型與請求的模型不符即中止 |
| FreshRSS MCP | HTTPS，Streamable HTTP，JSON-RPC；回應為 SSE 框架；session id 由初始化取得並於後續帶上 | 取得未讀（上限 cap）；標已讀（冪等，不可逆） | 取不到清單：本次無事可做，不標、不擷取；缺 token 時伺服器回「找不到工具」而非認證錯誤，須識別並明確報告 |
| rqbit／streamexa MCP | 同上 | 保留的文章啟動下載；以文章記錄，已成功者不重複派發 | 失敗記錄在下載結果，下次重試；不影響摘要與標已讀 |
| Chrome | DevTools 協定（本機） | 開頁、等待、截圖、取可見文字、在頁面開著時取 torrent 檔 | 5xx 視為失敗而非頁面；逾時與取消時結束行程 |

## 通訊原則

- 外部服務的存取端點與憑證由組態提供，不寫進程式。
- 所有「腳本能確定的答案」（零篇、關閉標記、模型不可用）是正常結果，run 以成功結束並記錄原因；模型不可用與 FreshRSS 取不到清單同為成功結束；呼叫錯誤、組態錯誤（含憑證檔缺條目）與服務憑證被拒才是失敗。
- 每個階段在 run log 輸出一行宣告與一行結果，使「失敗的步驟」不會看起來像「被跳過的步驟」。
- 階段之間透過資料庫紀錄交接結果，不經檔案；每個階段只讀自己需要的紀錄。
- 資料庫經 `jdbc-pool` 存取端：同步、可取消、遇到鎖定時等待至逾時。
- 認證：對外服務的位址與 Bearer token 取自憑證檔（ADR-023）；Engine 與 Lemonade 之間的機密由 Engine 持有。
