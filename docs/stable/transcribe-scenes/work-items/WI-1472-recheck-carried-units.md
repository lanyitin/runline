# WI-1472 續跑時用現行規則重新檢查被沿用的單位

本文回答：續跑的起點階段如何找出舊規則放過、現行規則不通過的單位並重做。狀態：已核可（2026-10-15）。相依：WI-1470（已完成）。決策見 [ADR-068](../adr/ADR-068-carried-units-are-rechecked.md)。儲存庫：T。

## 行為與驗收條件

1. **重新檢查**：起點為翻譯時，已儲存的譯文在沿用前以現行規則再檢查一次，只用已儲存的文字，不呼叫模型：
   - 譯文的行含假名；
   - 條目的行數與換人標記不符現行的行數規則；
   - 超過兩行。
   不通過的條目視為未完成，與降級的條目一起重做；通過的條目沿用。片段中只有部分條目不通過時，只重送那些條目（沿用 WI-1470 的部分採用方式）。
2. **不重新檢查的**：來源（潤飾文字）本身沒有假名的條目；沒有假名的日文漢字條目；無法僅憑文字判定的規則（結構、語境重複、截斷）；其他起點階段（轉錄、潤飾、摘要）的行為不變。
3. **可觀測**：log 新增一行 `RESUME RECHECKED`，列出因現行規則重做的條目數與片段數、按原因的計數；RUN SUMMARY 在有時才顯示 `resumeRechecked=<條目數>`，與 `resumeReused`、`resumeRedone` 分開。沒有時，現有輸出不變。
4. **重現情境**（假服務與真實資料庫）：
   - 來源 run 的某個成功片段含一條原樣回傳的日文（有假名），以翻譯起點續跑：只重送該條，其餘沿用，`resumeRechecked` 為 1；
   - 該條來源本身沒有假名（中文原文）：不重送；
   - 沒有假名的日文漢字條目：不重送；
   - 所有條目都通過：不多送任何請求，行為與 WI-1470 相同；
   - 條目重做後仍未翻譯：依現行規則降級，不無限重做。
5. **文件**：README 的續跑章節說明重新檢查的規則與範圍；文件測試維持相符。
6. 其餘行為不變。

## 架構約束

- 不改 Engine；不新增參數；不改 schema。
- 重新檢查的規則與回答驗證共用同一份實作，不另寫一套。
- 嚴格 TDD；測試不使用 Stub 或 Mock。
- 測試範圍依 tdd-coder 定義的 §1.1，不跑全套。
- 與 WI-1471 都改翻譯的驗證；並行須在各自的 worktree 與分支上，或序列執行（建議 WI-1471 先、WI-1472 後）。
- 回報時列出測試範圍與結果、jar 路徑與 sha256、提交。
