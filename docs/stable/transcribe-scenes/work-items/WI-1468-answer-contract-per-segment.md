# WI-1468 回答契約違反以片段為單位處理

本文回答：潤飾、摘要、翻譯的回答違反契約時，重試、保留可用條目與及早止損要怎麼做。狀態：已核可（2026-10-15）。相依：WI-1459、WI-1464、WI-1465。決策見 [ADR-064](../adr/ADR-064-answer-contract-violations-are-per-segment.md)。儲存庫：T。

## 行為與驗收條件

1. **重試附違規原因**：回答因契約違反重試時，請求多附一段說明上次違規原因的簡短文字（包含不符的條目序號或「整段未翻譯」）；其餘請求內容與第一次相同；首次請求不附。EXCHANGE 記錄重試請求附了哪個原因。潤飾、摘要、翻譯三階段都適用。
2. **行數規則（翻譯）**：來源條目有至多一個換人標記時，譯文 1 至 2 行皆可，標記畫在第一行；來源條目有兩個換人標記時，譯文須為 2 行且各保留標記。違反者為 `LINES_CHANGED`。條目數、序號、時間不變的規則不動。兩份 SRT 的條目、時間與換人位置維持相同。
3. **未翻譯**：翻譯回答的行含假名，原因為 `UNTRANSLATED`，視同契約違反並重試；簡體字檢查只對不含假名的行做。譯名（`NAMES:`）的簡體檢查規則不變。
4. **保留合格條目（翻譯與潤飾）**：重試用盡且回答的條目數與序號正確時，逐條判斷：合格者採用，不合格者保留上一階段文字並計入降級；條目數或序號錯誤時整個片段保留上一階段文字。階段與 run 的降級計數另列條目數。
5. **及早止損**：回答契約違反只在片段的重試用盡、且沒有任何條目可採用時，才累計一次連續失敗；片段中有任何一次成功或至少採用一條譯文，連續計數歸零。逾時、5xx、模型不可用、連線等服務層級失敗維持每次呼叫累計；門檻 `earlyStopFailures` 與其他規則不變。轉錄階段不適用。
6. **紀錄**：結果行與 RUN SUMMARY 列出各階段因契約違反降級的片段數與條目數，以及按原因（含 `UNTRANSLATED`）的計數；README 的驗證表與排錯章節同步，文件測試維持相符。
7. **重現**：以假服務重現並驗證：
   - 首次回答違反、重試附原因後通過；
   - 一個片段中部分條目違反，採用其餘合格條目；
   - 回答原樣回傳日文時，原因為 `UNTRANSLATED`，不是簡體字；
   - 來源兩行（一人）被翻成一行時通過，兩人兩行被翻成一行時為 `LINES_CHANGED`；
   - 連續多個片段完全無法採用才及早止損，而兩個片段降級、其餘成功時不止損；
   - 服務層級失敗的及早止損不變。
8. 其餘行為（條目、時間、換人資料來源、摘要內容、view 的其他欄位）不變。

## 架構約束

- 不新增參數；`earlyStopFailures`、`modelRetries` 的語意在文件中更新為「連續失敗的片段數」與「每片段的重試次數」。若實作需要新增參數，先回報。
- 不改 schema（降級的條目數若需持久化，先回報）。
- 嚴格 TDD；測試不使用 Stub 或 Mock。
- 與 WI-1467 都改 T 的 run 流程；兩項並行須在各自獨立的 worktree 與分支上工作。
- 部署時需處理的事（新參數、環境變數、掛載）回報時列出。
