# WI-71 Console 深色模式

本文回答：深色模式要達成哪些行為、如何驗收。狀態：已核可（2026-10-29）。相依：無。決策見 [ADR-70](../adr/ADR-70-console-dark-mode.md)；總覽見 [README](README.md)。

## 背景

Console 只有淺色 token，且 log 檢視的終端面板寫死了顏色。使用者要求所有頁面在系統偏好深色時以深色呈現。

## 行為與驗收條件

- 系統偏好深色時，所有路由（總覽、run 與 log、pipeline、view、管理頁、表單、對話框、登入相關頁）使用深色 token；偏好淺色時外觀與現在完全相同。
- 系統偏好在 Console 開著的時候改變，畫面隨即切換，不需重新整理。
- 瀏覽器內建控制項（捲軸、輸入、選單）在深色下跟著深色。
- 深色色票依 ADR-70 第 4 點：表面分層、強調色用較亮色階、狀態色語意不變、徽章仍有文字。
- log 檢視的終端面板在兩種主題下都是深色，顏色來自 token，與周圍表面仍有可辨識的邊界；既有的即時串流、自動捲動、合併行為不變。
- 元件程式中沒有自訂顏色（log 面板的寫死顏色也移除）；新增檢查使其在日後不會再出現。
- 對比度：自動化檢查涵蓋所有文字與背景 token 配對，兩種主題各一份；一般文字至少 4.5:1，大字與元件邊界至少 3:1；不達標時檢查失敗並指出配對。焦點框在兩種主題下都可見。
- 真實瀏覽器 e2e：以模擬系統深色偏好走過每個路由，驗證頁面套用深色 token、沒有淺色殘留的區塊（背景與文字色符合預期），並驗證偏好切換即時生效。
- 沒有新的 API、設定、儲存或後端改動。

見[總覽的全域約束](README.md#全域架構約束)。補充：不加手動開關；深色色票的具體值由實作決定，但必須通過上述對比度檢查，若無法同時保持設計方向與對比度，停下回報。
