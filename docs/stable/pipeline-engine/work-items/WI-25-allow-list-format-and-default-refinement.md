# WI-25 白名單文字格式統一與預設白名單補強

本文回答：如何讓 Engine 與開發入口以同一種文字格式表達白名單，並補上預設白名單中 Kotlin 常用的資源關閉函式。狀態：已核可（2026-10-05）。相依：WI-10。

## 背景

[WI-10](WI-10-allowlist-admin.md) 之後：

| 項目 | 現況 |
|---|---|
| 文字格式 | 開發入口以尾端 `!` 表示「僅此套件」，Engine 以 `:exact`；兩者對類別條目都用 `class:` 前綴。兩邊各有自己的解析器 |
| 預設白名單 | Kotlin 的資源關閉函式（`use`）編譯為標準函式庫的關閉輔助類別，不在預設白名單，使用它的 pipeline 被判 unsafe；該類別與關閉介面只涉及關閉資源，不提供開檔或網路能力 |

## 行為與驗收條件

### 文字格式統一
- 白名單的文字格式只有一種，以 Engine 現行格式為準：逗號分隔的條目；套件條目為 `套件名`，僅此套件為 `套件名:exact`，類別條目為 `class:完整類別名稱`。
- 格式的解析與輸出由 analyzer 提供單一的共用實作；Engine 的初始白名單組態與開發入口的白名單設定都使用它，兩邊各自的解析器被移除。
- 兩邊對相同的輸入給出相同的結果與相同語意的錯誤：不合法或歧義的條目被拒絕，錯誤指出是哪個條目與原因。以屬性式的測試驗證：任何有效清單經輸出再解析得到相同的清單；同一組不合法輸入在兩邊都被拒絕。
- 開發入口不再接受尾端 `!` 形式：遇到時啟動失敗，錯誤訊息指出環境變數名稱、該條目，並說明改用 `:exact`；不同時支援兩種格式。
- 開發入口列出白名單條目的輸出使用統一格式。
- Engine 的格式與行為不變；既有的 Engine 組態測試通過。
- 外部測試專案與專案內說明（各 README、開發入口操作指南）中出現舊格式的地方同步更新；沒有舊格式的殘留。

### 預設白名單補強
- 預設白名單新增兩個類別條目：Kotlin 標準函式庫的資源關閉輔助類別與資源關閉介面。預設白名單的版本標示由 `default-1` 改為 `default-2`；預設內容仍是單一來源。
- 以真實編譯的 Kotlin 與 Java 樣本驗證：對非檔案資源使用 `use` 的 pipeline 為 safe；以檔案類別開啟資源再 `use` 者仍為 unsafe（由檔案類別或成員層級規則攔下）；移除這兩個條目中的任一個，使用 `use` 的樣本被判 unsafe。
- 既有的預設白名單測試（42 個條目的內容、被排除的類別仍不被信任、移除任一必要條目使對應樣本被判 unsafe）更新為 44 個條目並通過。
- 已存在的 Engine 資料庫中的白名單不被自動改動：預設白名單只在首次啟動時作為初始內容；既有部署如需新增這兩個條目，由管理員以白名單管理 API 新增。此行為在說明文件中明寫。

### 共同
- 建置、全部測試（含打包形態的測試）在 JDK 25 下通過，`ktfmtCheck` 通過；既有測試不減少（被取代的解析器測試改為對共用實作的測試，說明對應關係）。

## 架構約束

- 依 [ADR-014](../adr/ADR-014-class-level-allow-list-entries.md) 與 [ADR-013](../adr/ADR-013-io-sensitive-members.md)：只靜態判定，Runner 不加入執行期攔截。
- 修改範圍限於 analyzer 的白名單格式與預設內容、engine 與 devkit 的白名單解析，以及專案內相關的說明與外部測試專案的設定；若需要其他修改，停下來回報。
- analyzer 主程式維持只依賴 JDK 與 Kotlin 標準函式庫，不依賴 core 或其他專案模組。
- 測試使用真實編譯的 jar（Java 與 Kotlin 皆有）；新增與移除條目的比對邏輯與格式解析須做突變驗證（暫時破壞再還原，確認測試失敗）。
- 測試須穩定：時間以可控制的時鐘提供，不以睡眠換取通過。
- 不新增外部相依；不新增 git hook 或 CI；完成程式碼變更時依專案規則先以 ktfmt 格式化。

## 待確認問題

- 既有 Engine 部署的白名單不會自動取得新的預設條目。是否需要一個「套用新的預設內容」的管理操作（預覽與套用，遵守重判規則）。影響：升級時管理員的操作成本；目前預設為不提供，管理員以既有 API 逐一新增。
