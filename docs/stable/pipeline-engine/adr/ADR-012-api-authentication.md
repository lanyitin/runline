# ADR-012 管理與上傳 API 以設定檔提供的 token 認證

狀態：已核可（2026-10-05）。回答：上傳與管理 API 如何辨識呼叫者與其角色，以及哪些端點不需要認證。

## 背景

Engine 的上傳 API（[WI-06](../work-items/WI-06-upload-and-discovery.md)）要記錄上傳者，管理 API（trigger 綁定、白名單、unsafe 設定、共享資源）要區分管理員與一般開發人員。Webhook 的認證由 per-trigger 密鑰負責（[ADR-005](ADR-005-trigger-binding.md)），不屬於本決策。範本遺留的端點（Engine 關閉、回聲 WebSocket、範例 JSON）不屬於產品功能，其中關閉端點不需認證即可讓 Engine 停止服務。

## 決策

- 上傳與管理 API 以 Bearer token 認證：呼叫端在請求標頭提供 token，Engine 依 token 辨識身分與角色。
- Token 與其對應資料由組態提供（環境變數或組態檔，符合 12-Factor），不寫入程式碼、版本庫或資料庫；每個 token 對應一個名稱與一個角色。
- 角色只有兩種：
  - 開發人員：可上傳 jar、對自己上傳的 pipeline 建立與查詢 run。
  - 管理員：包含開發人員的所有權限，另可使用管理 API。
- 上傳者與各項設定的變更者，記錄為該 token 對應的名稱。
- 未提供或無效的 token 回應「未認證」；有效但角色不足回應「權限不足」。
- Token 比對須抵禦時間差攻擊；token 不得出現在 log、trace 或錯誤訊息中。
- 認證實作為可替換的 provider：角色與身分的語意固定，provider 可日後替換。
- 傳輸的機密性由部署層負責（TLS 終止於 Engine 之前的入口），本決策不處理。
- 不需要 Bearer token 的端點只有：
  - API 文件與其 schema（Swagger／OpenAPI）。
  - Webhook 入口，以 per-trigger 密鑰在專用標頭認證。
- Engine 的關閉不經由 HTTP：關閉由終止訊號觸發（[04](../04-deployment.md)）。範本遺留的關閉端點、回聲 WebSocket 與範例 JSON 端點被移除，不屬於產品的對外介面。
- 任何新增的端點預設需要認證；不需要認證的端點須在本 ADR 明列。

## 取捨

| 項目 | 優點 | 缺點 |
|---|---|---|
| 設定檔提供 token | 簡單；符合 12-Factor；不需要使用者資料庫與引導流程；足以支撐 WI-06、07、08、10 | token 輪替需重啟或重新載入；不適合大量使用者；沒有自助發放與撤銷介面 |
| 可替換的 provider | 日後改為資料庫管理的 token 或外部身分提供者時不影響呼叫端與角色語意 | 需維持角色語意的穩定 |
| 以明列清單限定免認證端點 | 新增端點時不會意外暴露；可由測試列舉驗證 | 新增免認證端點需修訂本 ADR |

被否決的做法：資料庫管理的 token（需要管理員引導流程，範圍較大，日後需要時另開 ADR）；外部身分提供者（目前沒有外部系統，超出需求）；保留關閉端點並加上認證（Engine 的關閉由部署平台以終止訊號處理，沒有需要 HTTP 端點的使用情境）。

## 後果

- WI-06 的上傳 API 與 WI-07、WI-08、WI-09、WI-10 的管理 API 都依本決策判斷身分與角色。
- 日誌與稽核欄位使用 token 對應的名稱，不使用 token 本身。
- 需要自助發放、撤銷或大量使用者時，另開 ADR 替換 provider。
- 測試以列舉所有已註冊的路由驗證：除上述明列的端點外，無 token 一律被拒絕。

## 待確認問題

- 開發人員可否查詢他人上傳的 pipeline 與 run。影響：查詢 API 的授權範圍；現行預設為只允許查詢自己上傳的結果，管理員可查詢全部。
- Token 的輪替方式（重啟生效，或支援不重啟的重新載入）。影響：維運方式；現行預設為重啟生效。
