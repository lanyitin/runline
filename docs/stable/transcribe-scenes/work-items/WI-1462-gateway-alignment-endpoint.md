# WI-1462 llm-gateway 的對齊端點

本文回答：llm-gateway 如何以 GPU 提供 Qwen3-ForcedAligner，並與 Lemonade、d1 共用 GPU。狀態：已核可（2026-10-14），待派工。相依：無。決策見 [ADR-056](../adr/ADR-056-alignment-on-gateway-gpu.md)，契約見 [05](../05-ipc.md)。儲存庫：G（llm-gateway，`/Users/lanyitin/Projects/Personal/llm-gateway`）。

## 行為與驗收條件

1. **端點**：OpenAI 相容的音訊轉錄端點（含 `/v1` 與 `/api/v1` 兩種前綴）。
   - 請求的模型是對齊模型時，由 gateway 處理：
     - 輸入：音訊檔、語言、要對齊的文字（`prompt`）；
     - 回應：`verbose_json` 格式，含全文與每個字詞的文字、起點、終點（秒）。
   - 其他模型照舊原樣轉發給 Lemonade，行為與現在相同。
2. **對齊結果的契約**：
   - 字詞依時間排序，時間落在音訊長度內；
   - 字詞串接後與送出的文字一致，空白與標點的處理規則寫在 README；
   - 以日語與英語的語音各測一次。
3. **請求驗證**：比照決策 API 的錯誤格式（OpenAI 格式，`param` 指出欄位）。
   - 缺少音訊、文字或語言，或音訊無法解碼：回 400；
   - 不支援的語言：回 400，並列出支援的語言。
4. **GPU 共用**：對齊模型是第三方，規則與 d1 相同。
   - 需要對齊時，先讓 Lemonade 卸載所有模型、等 VRAM 釋放，再載入對齊模型；
   - 其他類型的請求到來時，先釋放對齊模型；
   - 另一方有進行中的請求時不切換，排隊的一方優先；
   - d1、對齊、Lemonade 三方之間的切換都正確，原有 d1 與 Lemonade 的切換行為不變；
   - 對齊的推論一次只跑一個。
5. **無法服務**：無法取得 GPU、VRAM 不足或模型載入失敗時，回 503 並說明原因，不改用 CPU。
6. **版本固定與離線**：
   - 對齊模型的 revision 與檔案雜湊固定；
   - 執行時不連網下載，模型檔不存在或雜湊不符時，以明確訊息回 503；
   - 新增的 Python 相依固定版本。
7. **可觀測**：`/_proxy/health` 列出目前佔用 GPU 的一方（含對齊）、對齊模型是否已載入、進行中的對齊請求數。
8. **文件**：README 新增：
   - 對齊端點的契約與呼叫範例，並註明 `prompt` 在此是逐字稿；
   - 新的環境變數（模型 revision、裝置、可用 VRAM 門檻）；
   - 切換規則的三方說明；
   - 從 Engine 資源呼叫的部署後檢查步驟。
9. **效能紀錄**：在 Lemonade 主機上，對 30 秒日語片段記錄：
   - 切換到對齊的耗時；
   - 每片段的對齊耗時（中位數、最大值）；
   - 峰值 VRAM。

   記錄在 README 或交付報告中；這項在實機上量測，由使用者執行。

## 架構約束

- 不改變對 Lemonade 的轉發行為與 d1 的 API。
- 不新增網路埠或服務，在同一個 gateway 程序內完成。
- 認證維持現況（沒有認證）；不在本項處理。
- 嚴格 TDD；測試不使用 Stub 或 Mock。Lemonade 以自製的簡易真實實作代替；對齊模型以真實模型或自製的簡易真實實作驗證切換與契約，至少一個測試以真實模型驗證對齊結果。
