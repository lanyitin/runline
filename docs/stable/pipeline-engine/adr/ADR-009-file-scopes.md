# ADR-009 檔案存取範圍：pipeline 共享目錄與 run 私有目錄

狀態：已核可（2026-10-03）。回答：context 允許 pipeline 存取哪些檔案位置。

## 背景
使用者指定 context 提供的檔案存取只有兩種：同一 pipeline 的不同 run 可共享的目錄，以及只有當下那個 run 才能存取的目錄。Pipeline 若直接使用 JDK 的檔案類別，不在此模型內，也不受任何阻擋。

## 方案比較

| 選項 | 優點 | 缺點 |
|---|---|---|
| A 任意路徑，以 metadata 宣告允許的路徑範圍 | 彈性最大 | 路徑範圍難以撰寫與審核，錄製後需概括化 |
| B 兩種固定範圍的目錄（採用） | 邊界清楚、易強制、易審核、錄製結果簡單 | 無法經由 context 存取其他位置 |

## 決策
採用 B。
- **Pipeline 共享目錄**：以 pipeline 名稱為單位，該 pipeline 的所有 run 共享，跨 run 持續保留。
- **Run 私有目錄**：每個 run 一個，只有該 run 可存取，run 結束後清除。
- Context 的檔案操作只接受相對於這兩種目錄的位置；沒有提供指向其他位置的方式。
- 以相對路徑跳出目錄、或經由符號連結跳出目錄的嘗試，一律被拒絕。
- Pipeline 在 metadata 宣告使用哪些範圍，以及各自是唯讀還是可寫；未宣告的範圍不可用。
- 目錄在 run 的初始化階段備妥。
- 同一 pipeline 的多個 run 同時執行時，共享目錄不做協調；需要互斥者使用共享資源（[ADR-007](ADR-007-shared-resources.md)）。
- 經由 JDK 直接存取檔案的程式碼不受此模型約束；它會在靜態分析中被標為 unsafe（[ADR-002](ADR-002-context-and-unsafe.md)），錄製也看不到它。
- 目錄位置由 Engine 組態決定，共享目錄必須位於持久儲存上。

## 取捨
- 得到：檔案邊界簡單、可審核；「檔案」類別不再需要路徑範圍的宣告與概括。
- 失去：pipeline 無法經由 context 讀取主機上的任意檔案；跨 pipeline 無法共享檔案。

## 後果
- 檔案類別在 context 層本質上就是受限的，不再有「檔案不限制」的狀態。
- 共享目錄是 Engine 的本機持久狀態，與無狀態的部署原則有例外（[04](../04-deployment.md)）。
- 磁碟空間、同時寫入、清理是新增的營運議題（[07](../07-nfr-risks.md)）。
