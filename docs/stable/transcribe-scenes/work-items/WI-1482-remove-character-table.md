# WI-1482 移除角色表與全片摘要的出場人物

本文回答：移除角色表後，摘要、翻譯、資料與文件要有什麼行為。狀態：已核可（2026-10-16）。相依：WI-1474、WI-1475。決策見 [ADR-074](../adr/ADR-074-remove-character-table.md)。儲存庫：T、R（文件）。

## 行為與驗收條件

1. **全片摘要**：回答只要求來源語言與全片摘要，不要求角色表；全片摘要依主題或故事段落組織，不逐場景條列。預設 system prompt 改寫，仍可覆寫；回答標記不再含 `CHARACTERS:`。
2. **不再寫入角色表**：新 run 不寫角色表資料；舊 run 的資料與 Console view 仍可讀。
3. **名字的判斷與相關處理移除**：沒有「是否為片中出現的名字」的判斷，沒有為它而設的重試、降級與告警。
4. **翻譯**：請求不附角色表與譯名；仍附場景摘要與前一片段已翻好的譯文，回答保持條目、行數與換人標記不變。
5. **回答容錯**：模型回答中若仍出現 `CHARACTERS:` 區塊，忽略它，不視為契約違反，不降級。
6. **續跑**：以舊 run 為來源續跑摘要或翻譯時，不使用舊 run 的角色表。
7. **參數**：與角色表有關的參數若有則移除，錯誤訊息要指出被移除的參數名稱；覆寫了舊版 system prompt 的呼叫端，以新契約的要求處理。
8. **文件對齊（R）**：入口 README、01、02、05、06、07 與 runbook 中與角色表、出場人物、譯名有關的敘述，改成現行行為；不留變更敘事。
9. 其餘行為不變（三層摘要、英文摘要、畫面依據、摘要不阻擋翻譯、潤飾、轉錄）。

## 架構約束

- 不改 Engine；schema 只增不改，角色表資料表保留；不刪除既有資料。
- 嚴格 TDD；測試以假服務重現：摘要回答無角色表、回答仍帶 `CHARACTERS:`、舊 run 續跑。
- 部署時需處理的事（移除的參數）回報時列出。
