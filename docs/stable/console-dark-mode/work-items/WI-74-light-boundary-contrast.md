# WI-74 淺色主題的邊界與焦點框對比度達 3:1

本文回答：如何讓淺色主題的元件邊界與焦點框達到 3:1 對比，以及這與 ADR-70「淺色值不變」的關係。狀態：已核可（2026-10-29，Issue #74）。相依：[WI-71](WI-71-console-dark-mode.md) 已合併。總覽見[工作項總覽](README.md)。

## 背景

[ADR-70](../adr/ADR-70-console-dark-mode.md) 第 6 點要求元件邊界與焦點框至少 3:1，第 4 點同時要求淺色 token 的值不變。WI-71 實作時發現淺色有兩項在白底上不達 3:1：輸入欄位邊框 `--border-strong` 約 1.5:1，焦點框 `--accent` 約 2.8:1。深色已全部達標。

## 與 stable 的衝突

本項要改變兩個淺色 token 的值，與 ADR-70 第 4 點「淺色 token 的值不變」衝突。處理方式：本項是該條的限定例外，只限這兩個 token，其餘淺色值維持不變。核可並晉升時，ADR-70 的狀態欄須註明此例外並連結本項（不改動其他實質內容）。

## 行為與驗收條件

- 淺色主題下，輸入欄位等表單控制項的邊框與白色表面的對比至少 3:1；焦點框與其所在表面的對比至少 3:1。
- 對比度自動化檢查的淺色範圍擴大到所有元件邊界與焦點框配對，不再只檢查原本就達標者；不達標時檢查失敗並指出是哪一組。深色的檢查維持不變。
- 只調整讓上述配對達標所需的 token；其他淺色 token 的值與外觀不變。淺色下以一般邊框區隔區塊的卡片、表格、分隔線不屬於「元件邊界」，維持現狀。
- 由於 `--accent` 同時用於強調色（連結、徽章、狀態點等），改動不得使其他以它為底或前景的既有配對失去原有對比；若無法同時滿足，另設焦點框專用 token，而不改強調色。
- 既有 Console 單元測試與 e2e 全部通過；深色模式的 e2e 不受影響；淺色的 e2e 若依賴色值，更新為新值並說明原因，不得放寬斷言。
- 沒有新的 API、設定、儲存或後端改動。

## 架構約束

- 色值由實作決定，只要通過 3:1；淺色外觀的小幅變化（欄位邊框變深、焦點框變深）是預期結果。
- 元件不自訂顏色，維持 token 層修改。
- 測試不使用 Stub 或 Mock；嚴格 TDD；專案沒有 CI，驗證皆可在本機完成。
