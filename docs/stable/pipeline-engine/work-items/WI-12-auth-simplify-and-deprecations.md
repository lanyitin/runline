# WI-12 簡化認證骨架並消除 deprecated 用法

本文回答：如何處理 WI-00 遺留的範本認證與建置警告。狀態：已核可（2026-10-03）。相依 WI-00（已完成）。

## 背景

認證不是核心功能，之後另行規劃。目前的範本骨架含有不安全或不符合 12-Factor 的行為，且建置有 deprecated 警告。

## 行為與驗收條件

- 認證只保留最小的擴充點，供日後接上真正的機制。
- 不存在任何會放行弱憑證的規則，例如帳號與密碼相同即通過。
- 不存在寫死的外部網址與直接讀取環境的敏感設定；oauth 與 form 範例移除。
- 沒有任何現行端點依賴認證才能運作，Swagger 與 WebSocket 的既有行為不變。
- 建置不得出現 deprecated 警告；使用的函式庫替代方案由 tdd-coder 選擇，若替代會改變行為則回報。
- 建置與既有測試在 JDK 25 下通過。

## 架構約束

- 不新增認證功能；日後的認證模型由獨立 ADR 決定。
- core 與 Runner 不得受影響。
