# WI-1301 Engine 的唯讀 view API

本文回答：Engine 如何列出與執行 view，並保證唯讀與不影響 run。狀態：已核可（2026-10-11）。相依：WI-1300。儲存庫：runline。

## 背景

見 [ADR-033](../adr/ADR-033-pipeline-views.md) 與 [05-ipc.md](../05-ipc.md)。

## 行為與驗收條件

1. 「列出 view」回傳宣告與每個 view 掛載角色的目前解析狀態；不執行查詢。「讀取 view」依參數與分頁回傳欄位定義與一頁資料列，以及「還有更多」標記。
2. 認證、定址、隔離同資源綁定：開發人員只能存取自己上傳的版本；他人的與不存在的版本回應位元組級相同；管理員以 `uploader` 指定，多上傳者未指定回 `ambiguous_version`。
3. 資源解析與 run 相同；未綁定、未定義、停用、型別不符各回明確錯誤（沿用 `problem` 值）。
4. **唯讀保證**：即使查詢文字含寫入、DDL、多個語句、改變連線設定的語句，也不得修改資料或連線狀態，且回報明確錯誤。保證不依賴資料庫帳號權限。以真實 PostgreSQL 與真實 SQLite 各驗證至少「寫入」「多語句」「改回可寫」三類企圖。
5. SQLite：沒有 run 進行時也能讀取，不在資料庫旁留下造成 Engine 帳號無法使用的檔案（見 digest-rss runbook 第 8 節的限制）；run 進行中讀取成功，且不使 run 的寫入失敗或等待逾時。
6. 參數只作為查詢參數傳遞；缺必填、型別不符、不在固定選項內為 400，指出參數名稱，不回顯值。
7. 分頁預設 50、上限 200；排序依宣告，翻頁不重複不遺漏；不提供總筆數。
8. 上限：套用資源的逾時、列數、回應位元組上限；逾時與超限回明確錯誤碼，不是 500。每個資源有 view 的並行上限，超過回明確的忙碌錯誤；view 讀取不占用 run 的資源容量。
9. 查詢與資料結構不符（欄位不存在等）回明確的「結構不符」錯誤。
10. 可觀測性：每次讀取有 log、metric（次數、耗時、失敗）與 trace，內容含 view 識別、結果碼、耗時、列數；不含查詢文字與參數值，亦不出現在任何錯誤回應。
11. 08-api 新增兩個端點，`ApiDocumentationTest` 通過。

## 架構約束

- 沿用 Engine 現有的資源存取邊界與取消機制（ADR-019、WI-43）；不新增常駐行程。
- 測試不使用 Stub 或 Mock，資料庫用 Testcontainers 的真實 PostgreSQL 與真實 SQLite。
