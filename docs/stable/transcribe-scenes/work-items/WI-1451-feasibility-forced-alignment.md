# WI-1451 可行性關卡：強制對齊

本文回答：Qwen3-ForcedAligner 在 Engine 映像的 CPU 上能否以可接受的精度與速度對齊 30 秒片段。狀態：已核可（2026-10-14）。相依：無。決策見 [ADR-051](../adr/ADR-051-long-chunks-and-forced-alignment.md)。儲存庫：T（量測工具與報告），R（試驗用映像的建置方式）。量測在 arr 上進行，由使用者或 homelab-deployer 執行。

## 行為與驗收條件

1. 一個獨立的對齊工具，可在加入 Python 的 Engine 映像中只用 CPU 執行，不連網。
   - 輸入：音訊片段、文字、語言。
   - 輸出：每個字詞的文字與起訖時間。
2. 以 run 8 的影片（日語）取至少 10 個 30 秒片段。轉錄文字用 Qwen3-ASR 的實際輸出，至少涵蓋三種片段：對白密集、有長停頓、有背景雜音或喘息。
3. 量測並記錄於報告：
   - 每片段的耗時（中位數、最大值）與峰值記憶體；
   - 映像增加的大小；
   - 時間精度：每片段人工標記至少 5 個字詞的起點，計算與對齊結果的誤差（中位數、最大值）；
   - 對齊失敗或明顯錯位的片段數。
4. 通過條件（由使用者核可）：
   - 一小時影片（約 120 片段）的對齊總時間不超過 30 分鐘；
   - 起點誤差中位數不超過 0.3 秒；
   - 失敗片段少於 10%。
5. 報告放在 runline 的 `docs/draft/transcribe-scenes/`（檔名由執行者決定，從工作項總覽連結），並列出重跑量測的步驟。

## 架構約束

- 只驗證可行性，不改 pipeline 的階段；成果（工具與量測方式）以後續項目可重用的方式留下。
- 對齊工具是 pipeline 啟動的本機子行程，作法比照降噪工具（ADR-046）；不得做成網路服務。
- 不通過時停下來回報，由架構決定（退回在 GPU 主機另開服務等選項，見 [03](../03-options.md) A）。
