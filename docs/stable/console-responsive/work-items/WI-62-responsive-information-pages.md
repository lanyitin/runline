# WI-62 查看資訊的頁面

本文回答：run、log、pipeline、view 與總覽在手機上如何呈現。狀態：已核可（2026-10-13）。相依：[WI-61](WI-61-responsive-foundation.md)。

## 行為與驗收條件

- run 清單：窄版面每筆 run 為一張卡片，顯示原表格的關鍵欄位（狀態、pipeline、來源、時間與持續時間），整張卡片可點進詳情；篩選與分頁操作在窄版面可用；寬版面維持表格。
- pipeline 清單與總覽中的清單：同樣在窄版面為卡片，保留原有的關鍵資訊與連結；寬版面不變。
- run 詳情：欄位在窄版面單欄排列；失敗原因與 trace 在自身容器內捲動或換行；取消等操作可點；寬版面不變。
- log 檢視：長行在自身容器內換行或捲動，不撐出整頁；即時串流、自動捲動、合併行為與既有一致。
- pipeline 詳情與 view 頁面：說明、參數、定義資訊單欄排列；詳情中的表格與 view 表格在自身容器內水平捲動，第一欄固定；view 的參數表單在窄版面單欄。
- 雜湊、名稱與伺服器回傳的文字在容器內換行或截斷且可看到全文，不可信內容維持純文字呈現。
- 以上頁面在 360px、390px、768px 下整頁不水平溢位，主要操作可點（以 WI-61 的共用檢查驗證）。
- 既有 Console 測試與 e2e 在寬版面全部通過。

## 架構約束

- 卡片與表格呈現同一份資料，由同一個資料來源產生，不複製資料取得邏輯。
- 不修改 Engine 與 API；不改變 run 的即時更新行為。
- 測試不使用 Stub 或 Mock。
