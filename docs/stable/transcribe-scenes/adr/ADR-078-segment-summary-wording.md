# ADR-078 片段摘要稱呼自己為「片段」，不使用「場景」

本文回答：片段層摘要的用詞如何避免讓場景層誤解輸入。狀態：已核可（2026-10-18）；背景中「片段層的提示沒有 scene 一詞」只對程式預設成立，run 38 的覆寫提示含有該詞，已由 [ADR-081](ADR-081-default-summary-prompts-adopt-measured-structure.md) 更正，決策 1 的用詞規定併入 [WI-1488](../work-items/WI-1488-default-summary-prompts.md) 的片段提示。補充 [ADR-054](ADR-054-scene-summaries-and-translation-context.md) 決策 2（片段摘要）；與 stable 沒有衝突。量測依據見[量測報告](../summary-leak-experiment-report.md)。

## 背景

- 片段層的提示只用「segment」稱呼處理單位，沒有 "scene" 一詞；模型在回答時自行寫出「The scene ends with …」。
- 片段摘要是場景層的輸入。場景層看到「場景在此結束」，又看到地點從車內跳到臥室，就質疑這些行是不是同一個場景，隨後自言自語（[ADR-077](ADR-077-scene-summary-answer-opening.md)）。
- 量測：場景 30 的輸入只把「The scene ends with」改成中性說法，外洩由 10/10 降到 6/10，截斷同步下降；單獨不足以擋住，但說明用詞是成因之一。

## 決策

1. **片段摘要的用詞**：片段層的 system 提示以肯定句規定：摘要的對象稱為「segment」（片段）；摘要不使用 "scene" 一詞；描述片段的結尾時，寫成「這個片段的最後」發生什麼，不寫場景或影片在此結束。
2. **以肯定的稱呼為主**：提示先規定該用的詞，再說明不用的詞；不只靠「不要寫 scene」的否定句。
3. **適用範圍**：片段層。場景層與全片層的提示不變（它們本來就以「scene」稱呼自己的單位）。
4. **不在儲存時改寫模型的回答**：pipeline 不把回答中的 "scene" 替換成 "segment"，因為字幕或內容裡可能有正當的用法（例如 "a love scene"）。

## 取捨

- 得到：場景層看到的輸入不再暗示「這裡結束了」，降低觸發疑慮的條件；與 [ADR-077](ADR-077-scene-summary-answer-opening.md) 疊加成兩道防線。
- 失去：
  - 提示改變後，模型仍可能寫出 "scene"；沒有保證，也不在儲存時糾正；
  - 片段摘要的品質（涵蓋度、事實）可能受提示改動影響，需要重新抽樣檢查；
  - 以舊提示產生、被續跑沿用（[ADR-063](ADR-063-resume-run-from-stage.md)、[ADR-068](ADR-068-carried-units-are-rechecked.md)）的片段摘要，仍帶舊用詞，同一個 run 內會混用。
- 備選：
  - 儲存時替換用詞：不採用，理由見決策 4；
  - 只在場景層提示說明「各行的結尾字眼只代表片段結尾」：另可併用，未列入本決策。

## 後果

- 片段層提示的預設值與 `SummaryDocumentationTest` 一類守住文件與程式相同的文件需同步修改。
- 驗收需涵蓋：新產生的片段摘要不含 "scene"（以抽樣統計，容許少數例外）；場景層以新片段摘要為輸入時，外洩率不高於現行。
- 工作項：[WI-1484](../work-items/WI-1484-segment-summary-wording.md)。

## 待確認問題

1. 提示中以哪一組說法描述「片段的最後」，需要用實際片段（帶圖片）抽樣比較；這屬於實作時的提示調整，不在本決策內固定。
2. 場景層提示是否同時加一句說明各行可能有地點變化、各行的結尾字眼只代表片段結尾（上述備選）。
