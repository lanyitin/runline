# ADR-007 跨 pipeline 共享資源由 Engine 在初始化階段協調

狀態：已核可（2026-10-03）；由 [ADR-019](ADR-019-typed-shared-resources.md) 補充（2026-10-06），資源可對應實際的檔案、連線池與服務；run 終止時的釋放順序、釋放等待上限、關閉時的釋放與錯誤優先為 2026-10-08 修訂。回答：多個 pipeline 如何互斥或限流地使用同一個外部資源（例如 lemonade server）。

## 背景
每次 run 使用獨立 root class loader（[ADR-001](ADR-001-isolated-classloader.md)），run 內部的鎖無法彼此看見。共享資源的存取必須由 class loader 之外、Engine 持有的機制協調。

## 方案比較

| 選項 | 優點 | 缺點 |
|---|---|---|
| A 在 metadata 宣告，run 初始化階段一次取得全部，run 結束才釋放 | 無死結、行為簡單、可事先驗證 | 整個 run 都占用資源，即使只在一小段用到 |
| B 宣告名稱，執行中以範圍方式取得與釋放 | 粒度細、吞吐好 | 可能死結，需逾時與取得順序規範 |

## 決策
採用 A（使用者指定）。
- 資源由管理員在 Engine 定義：名稱與容量（容量 1 即互斥，大於 1 即限流）。資源另有型別：`counter` 只有名稱與容量（即本 ADR 的語意），其他型別對應實際的實體並提供存取端，見 ADR-019；以下取得、等待與釋放的語意適用所有型別。
- Pipeline 在 metadata 宣告所需資源名稱（可另指定型別，見 ADR-019）。
- Run 有獨立的「初始化」階段，位於 pipeline 本體執行之前，在此階段取得所有宣告的資源。
- 取得是整體的：所有宣告的資源與並行額度同時可用時，run 才一併取得並開始執行；不做部分持有，因此沒有死結，也不會有 run 一邊占著資源一邊等額度。
- 等待者依先進先出順序；有等待逾時，由 Engine 組態設定，pipeline 不能自訂。逾時則 run 失敗並註明原因。
- 等待中被取消的 run 從等待佇列移除。
- Run 終止時（成功、失敗、取消、中斷），Engine 先使該 run 的所有存取端失效，再釋放它持有的全部資源與並行額度，之後才把 run 記錄為已結束。因此，任何人透過 API、Console、metric 或 trace 觀察到 run 已結束時，該 run 已不再持有資源，存取端也已不能使用；等待中的 run 可以立即取得被釋放的資源。失效或釋放本身失敗或卡住時，run 仍被記錄為已結束，並以 log 與 metric 記錄釋放失敗；這是唯一允許「已結束但釋放未完成」的情況，且可被觀察。Engine 重啟時標記為中斷的 run 不受此順序限制，因為重啟後沒有任何持有。釋放在排程之外進行，一個 run 的釋放卡住不影響其他 run 的開始與結束。Engine 關閉時，釋放的等待改由關閉寬限時間的總預算限制（[04](../04-deployment.md)「優雅關閉」），不套用釋放等待上限；預算用完時未完成的釋放隨行程結束，重啟後沒有任何持有。其他時候，排程最多等「釋放等待上限」（Engine 組態，預設 30 秒）：超過時，把 run 記錄為已結束，歸還它的並行額度，並寫 error log 與 metric（區分「失敗」與「逾時」）；卡住的資源容量仍算占用，等待者繼續等，直到釋放實際完成才歸還並喚醒等待者。各型別的清理本身也有自己的逾時（例如 `jdbc-pool` 歸還連線前的重置），使「卡住」只在型別逾時也失效時才發生；釋放等待上限是最後的保險。Run 本身失敗而釋放也失敗時，run 的失敗是主要結果，釋放的失敗附在其上一併呈現，不取代它；Engine 與開發入口相同。理由：沿用「關閉寬限時間」會混用兩種語意（關閉時等 run 停止、結束時等釋放），使其中一方無法依需要調整。
- 逾時未結束的持有者維持占用，直到實際結束或管理員強制釋放。
- 管理員可查詢持有者與等待者。
- 資源狀態由 Engine 持有，不持久化；Engine 重啟時所有進行中 run 標記為中斷，資源隨之釋放。
- 資源宣告不影響 safe／unsafe 判定。
- 開發入口提供同語意的本機實作，不連 Engine；單一 run 不會競爭，初始化立即成功。

## 取捨
- 得到：無死結、簡單、可事先驗證與顯示。
- 失去：持有時間等於整個 run；吞吐低於 B。

## 後果
- 協調跨越 class loader 邊界，只使用 JDK 內建型別（[05](../05-ipc.md)）。
- `counter` 型別的資源鎖是約定式的：它不綁定 pipeline 實際連到該資源的網路動作，未宣告就連線的 pipeline 不會被攔下。有實體的型別經 Engine 中介的存取端強制限制（ADR-019）；unsafe 的 pipeline 仍可直接使用 JDK 繞過。
- 多實例部署前，資源狀態需改為共享儲存（[07](../07-nfr-risks.md)）。
