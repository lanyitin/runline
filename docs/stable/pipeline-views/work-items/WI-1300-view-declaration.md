# WI-1300 view 宣告與上傳驗證

本文回答：pipeline 如何宣告 view，以及上傳時要驗證什麼。狀態：已核可（2026-10-11）。相依：無。儲存庫：runline。

## 背景

見 [ADR-033](../adr/ADR-033-pipeline-views.md) 的「宣告」。

## 行為與驗收條件

1. pipeline 可宣告零到多個 view，每個含：識別、標題、說明、掛載的資源角色、唯讀查詢、參數（名稱、型別：文字／整數／固定選項、必填與否）、欄位（名稱、標籤、型別：文字／整數／時間／狀態；狀態值可指定正面／中性／負面語氣）、預設排序、可選的鑽取（目標 view、帶入目標哪個參數、取自哪一欄）。
2. 宣告隨 artifact 版本保存，可由既有的版本查詢取得（含查詢文字，僅上傳者本人與管理員可見）；不含 view 的舊 jar 行為完全不變。
3. 上傳時驗證，不合格為上傳錯誤並指出哪個 view 與哪個問題，一次列出全部問題，被拒絕時不留下任何殘留：識別重複；掛載的角色不存在或型別不是資料庫；鑽取目標不存在或參數對不上；欄位或參數名稱重複；欄位型別或參數型別不在允許集合；固定選項型參數沒有選項；鑽取的來源欄位不在該 view 的欄位中；預設排序的欄位不在該 view 的欄位中。
4. 宣告不影響 safe 或 unsafe 判定，也不影響資源角色與綁定的現有行為。
5. 讀取 metadata 時不需要執行 pipeline 邏輯（ADR-003）。
6. 08-api 與 metadata 說明文件各記載一次宣告格式，其他處以連結引用。

後續由 [ADR-034](../adr/ADR-034-view-parameter-binding.md) 與 [WI-1304](WI-1304-view-named-placeholders.md) 在此基礎上新增佔位符的上傳驗證。

## 架構約束

- 宣告式，與 ADR-003 一致；不新增執行期程式碼路徑。
- 測試不使用 Stub 或 Mock；上傳驗證用真實 PostgreSQL（Testcontainers）。
