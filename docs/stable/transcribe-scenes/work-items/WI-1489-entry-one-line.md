# WI-1489 潤飾與翻譯不標換人、不分行，條目是一行文字

本文回答：條目在潤飾與翻譯後是一行文字、不再有換人與對話破折號，要做哪些改動、如何驗收。狀態：已完成（2026-10-18）。相依：無。決策見 [ADR-083](../adr/ADR-083-entry-is-one-line.md)。儲存庫：T。

## 行為與驗收條件

1. **潤飾提示**：規範不談分行、換人與對話破折號；條目以序號與文字送出。
2. **翻譯提示**：送出的條目只有序號與文字，不帶 `- `；規範要求每個條目的譯文寫成一行，摘要與語境只用來理解發生的事。
3. **回答的解析**（潤飾與翻譯）：同一序號底下的多行以空格接成一行，空行略過；行首的破折號是文字的一部分，原樣保留。沒有任何非空白字的條目是 `EMPTY`。降級而保留上一階段文字的條目，其行同樣接成一行。
4. **紀錄**：`entry_line` 的 `polish` 與 `translate` 每個條目只寫 `line` 1；`new_speaker` 不寫入（維持 0）。轉錄的行不變；schema 不變。
5. **輸出**：兩份 SRT 與 HTML 報告不畫對話破折號。參數 `subtitleDialogueDash` 移除，送入時以未宣告的參數拒絕。
6. **觀測與量測**：條目 view 移除換人欄；潤飾的階段結果移除 `turns`；可行性量測的換人正確率與人工判定表移除。
7. **續跑**：沿用的潤飾與翻譯文字以一個條目一行寫進新 run，不沿用換人標記；兩份 SRT 依這些文字重新做出。來源 run 的資料不變。

## 架構約束

- 不改 Engine；schema 不變，舊 run 的兩行與換人標記保留、可查。
- 嚴格 TDD；續跑以 ADR-083 之前的紀錄形狀（兩行、換人標記、兩份 SRT 的破折號）為來源驗證條件 7。
