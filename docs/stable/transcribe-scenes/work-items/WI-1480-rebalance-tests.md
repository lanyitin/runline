# WI-1480 依量測重配測試層，縮短工作回饋時間

本文回答：如何把行為規則下沉到快速測試、把端到端測試縮到少量，並達成回饋時間目標。狀態：已核可（2026-10-15）。相依：WI-1479（量測報告）。決策見 [ADR-072](../adr/ADR-072-test-pyramid-and-relaxed-test-doubles.md)。儲存庫：T。範圍與順序以 WI-1479 的報告修訂；報告顯示與假設不同時，先回報由架構決定，不依本文硬做。

## 行為與驗收條件

1. **分層與任務**：測試分為純邏輯、行程內整合、端到端、量測工具四類，各有獨立的 Gradle 任務與單一指令；每個測試屬於且僅屬於一類；改動前後的測試總數與名單有對照，報告列出。預設的日常任務為前兩類；端到端層與全套（含量測工具）只在使用者指定時執行。
2. **行為規則下沉**：下列行為規則以純邏輯或行程內整合層驗證，端到端層只留接線的最小斷言：答案解析（潤飾、摘要、翻譯）、重試與及早止損的判斷、降級原因、續跑的選擇規則、報告內容的組成。遷移一律逐項對照：舊測試斷言的每一項行為，在新位置都有同等或更強的斷言，報告附對照表。
3. **端到端縮減**：端到端層的測試數量與每個階段的覆蓋由報告決定；原則是每個階段與每個外部契約至少一個，且不重複驗證已在下層驗證的規則。
4. **行程內執行**：能在同一個 JVM 內驅動的 pipeline 測試，不啟動子行程；共用昂貴的啟動（資料庫 schema、樣本檔）。
5. **測試替身的使用**：依 ADR-072 決策 3：凡能縮短測試時間的替身都允許，任何邊界皆可；套件中仍保留少量真實或契約測試守住對外協定（資料庫、模型服務的 HTTP 協定、外部行程），數量與位置依量測決定並列在報告；不新增 production 後門，不以「只驗證替身被呼叫」取代行為斷言。
6. **檢查力不降低**：沒有 `@Disabled`、沒有刪除行為斷言、沒有放寬斷言；變異檢查：在被測行為中人為破壞一處，抽查至少 8 個經過遷移的測試，確認它們仍會失敗；並至少涵蓋重試、止損、解析、續跑、報告各一。
7. **目標**：純邏輯層全部 ≤ 1 分鐘；單一工作項的相關測試 ≤ 3 分鐘；全套 ≤ 10 分鐘；報告列出改動前後實測。目標不可行時，回報可達數字與原因，由架構決定。
8. **穩定性**：連續執行全套至少 3 次結果一致，無偶發失敗；隨機順序下通過；任何偶發失敗視為未完成，不以重試掩蓋。
9. **文件**：README 說明各層的定義、各任務的指令、新增測試應放哪一層、替身的使用邊界；tdd-coder 使用的測試範圍說明同步（`.claude/agents/tdd-coder.md` §1.1 與 §2 已由架構依 ADR-072 修改，不屬本項）。
10. 不改 production 行為、參數、schema；為了可測性必須改 production 的內部邊界（例如抽出介面）時，行為不變並先回報。

## 架構約束

- 分批進行：一次遷移一個階段或一類規則，每批前後有量測與測試名單對照；不一次改全部。
- 並行派工時在獨立 worktree 與分支；與功能工作項（例如後續 WI）並行時避免同時改同一批測試檔。
- 回報時列出：量測前後數字、分層與任務對照、遷移對照表、變異檢查結果、穩定性連續執行結果、jar 或分支資訊。
