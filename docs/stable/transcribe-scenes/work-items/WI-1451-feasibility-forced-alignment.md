# WI-1451 可行性關卡：強制對齊

本文回答：經 llm-gateway 以 GPU 執行的 Qwen3-ForcedAligner，能否以可接受的速度對齊 30 秒片段，以及時間精度何時、如何驗證。狀態：已核可（2026-10-14）；速度與失敗率的條件已由實機數據滿足，時間精度延後到成品字幕核對。相依：WI-1461、WI-1462。決策見 [ADR-051](../adr/ADR-051-long-chunks-and-forced-alignment.md)、[ADR-056](../adr/ADR-056-alignment-on-gateway-gpu.md)。儲存庫：T（量測工具與報告）。量測在 arr 上進行，由 homelab-deployer 執行。

## 行為與驗收條件

1. 量測工具的對齊步驟可呼叫 gateway 的對齊端點，請求內容與 [05](../05-ipc.md) 的契約相同。
   - 既有的 CPU 對齊方式保留，作為對照。
   - 缺少轉錄文字的片段列為轉錄失敗，其餘片段照常量測，不中斷整次量測。
   - 單一片段的對齊失敗或逾時列為對齊失敗，同樣不中斷。
2. 以 run 8 的影片（日語）取至少 10 個 30 秒片段。
   - 轉錄文字用 Qwen3-ASR 的實際輸出，並套用 WI-1461 的生成上限；
   - 至少涵蓋三種片段：對白密集、有長停頓、有背景雜音或喘息。
3. 量測並記錄於報告：
   - 從 arr 呼叫時，第一個請求的耗時（含 GPU 切換與模型載入），以及之後每片段的耗時（中位數、最大值）；
   - 對齊後第一個 Lemonade 請求的額外耗時（切回與重新載入）；
   - 對齊失敗的片段數與原因；
   - CPU 方式的初步數據（2026-10-14，arr 8 vCPU）作為對照，列在報告中。
4. 通過條件（由使用者核可）：
   - 一小時影片（約 120 片段）的對齊總時間，含兩次 GPU 切換，不超過 30 分鐘；
   - 失敗片段少於 10%。
5. 時間精度不在本關卡量測，延後到成品字幕核對（見下節）。
6. 報告放在 runline 的 `docs/draft/transcribe-scenes/`，從工作項總覽連結，並列出重跑量測的步驟。

## 延後的驗證：成品字幕的時間核對

- **為什麼延後**：起點精度原本以人工標記字詞起點量測，需要聽得懂日語的人；使用者無法執行。
- **何時**：WI-1460 完成、能產出完整字幕之後。
- **怎麼核對**：以播放器同時播放影片與成品字幕，在全片分散的位置抽查字幕出現與實際說話開始的時間差，是否在可接受的範圍。抽查的數量與可接受的範圍，由使用者在核對時決定；這兩項尚未決定。
- **不通過時**：時間偏移的來源可能是對齊（逐字稿比語音長時尾端字詞被壓到音訊結尾）、長片段的切點，或條目組成規則。停下來由架構決定，不自動回退。
- **量測工具**：保留人工標記的流程（`marks.tsv`），日後有人能標記時可補量。

## 架構約束

- 只驗證可行性，不改 pipeline 的階段；量測工具以後續項目可重用的方式留下。
- 量測工具可以直接呼叫 gateway；pipeline 本身必須經 Engine 資源（ADR-056）。
- 不改動 Lemonade 與 gateway 的設定。
- 速度條件不通過時停下來回報，由架構決定。
