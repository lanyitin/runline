# WI-1435 記錄並在 Console 顯示各片段（VAD-A 組）的摘要

本文回答：使用者如何在 Console 看到每個片段的摘要。「片段」即 VAD-A 組（使用者已確認）。狀態：已核可（2026-10-13）。相依：WI-1433（已完成）、WI-1432（已完成）。儲存庫：T（runline-transcribe）。補充 [06-data-model.md](../06-data-model.md)（新增一個實體與結構版本 7）與 [WI-1433](WI-1433-console-summary-and-frames.md)（其 `summary` view 目前只有整部影片）。

## 背景

摘要階段先為每個 VAD-A 組產生摘要，再彙整為整部影片的摘要。組摘要現在只存在 `exchange.response`，結果表只有整部影片的摘要。`exchange.response` 體積大，且 view 規則禁止選取，因此 Console 看不到各片段的摘要。

## 行為與驗收條件

1. **記錄**：摘要階段為每個 VAD-A 組記錄其摘要文字，鍵為（run、組序號）；連同該組的起訖時間（秒）與是否降級（摘要缺少）。新 run 在摘要階段成功取得組摘要時寫入；降級或失敗的組記為缺少，不寫空字串冒充成功。
2. **階層式摘要**：若某組因過長而被拆成多個子片段分段摘要（階層式），資料庫記錄的是該組最終的一份摘要，不記錄中間彙整。
3. **結構**：新增一個實體（建議名稱 `group_summary`，名稱由實作者決定並寫入資料模型），遷移為前向、冪等、於 run 開始時套用，結構版本 7；舊 run 沒有紀錄，view 對舊 run 回空，不報錯。
4. **`summary` view 擴充**：沿用 WI-1433 的 `summary` view，在整部影片的列之前（或之後，由實作者依可讀性決定並寫入說明）加上各組的列：範圍（組序號與起訖，時:分:秒）、段序、文字。組內多段落同樣一列一段。整部影片的列、欄位名稱與值不變。
5. **不存媒體**：只存文字與時間，不存圖片與音訊。
6. **保留**：隨 run 一起保留與清除，沿用既有保留規則。
7. 驗證：涵蓋成功的組、降級的組、舊 run（版本 6）升級後的 view、組數很多的 run（數千條目）在 30 秒內回應；jar 上傳到 Engine 後讀取一次；README 同步。runbook 與資料模型文件的修改回報給架構師，併入文件工作項。

## 架構約束

- 不由 `exchange.response` 回推，不放寬 view 的「不選取 `exchange.prompt`、`exchange.response`」規則。
- 不改變既有 view 的欄位與值（穩定契約）。
- 薄 jar、嚴格 TDD、不使用 Stub 或 Mock，與其他 T 項相同。
