# 7 非功能性考量與風險

狀態：已核可（2026-10-12）。本文回答：容量、安全、失敗模式與風險為何。

## 容量估算（假設，須在 WI-1413 量測）

- 一小時影片，語音佔 60%，VAD-B 平均 3 至 5 秒：約 400 至 700 段。
- Lemonade 呼叫次數：轉錄 N，核對 N，潤飾與翻譯各 A 組，摘要約 A 加 1，補掃（開啟時）另有每個窗口一次轉錄請求 W 次，合計 2N + 3A + 1 + W；補掃保留的窗口使 N 與 A 變大。A 與 N 的比例取決於停頓長短，實測的合成語音為 0.88，連續語速快的素材會低得多。W 取決於 VAD 沒涵蓋的空隙總長（空隙總秒數除以 `sweepWindowSeconds`）。N 為 600 時約 1,400 至 3,000 次；每個窗口的轉錄請求遠短於對話階段的請求，W 對總時間的影響相對很小。每次 5 至 20 秒時，一小時影片需約 3 至 12 小時。
- 降噪（開啟時）在 VAD 之前處理整份音訊，僅 CPU，耗時與影片長度成正比，相對於 LLM 階段的數小時很小；補掃窗口數與降噪的即時率來自單次實驗，數字與待量測項見 [runbook](runbook.md) 第 12 節與第 17 節。
- 長度上限 `maxMediaSeconds` 預設 6 小時：接近上限的影片，單次 run 約 18 至 72 小時，期間獨佔 Lemonade 資源。
- 圖片：每條目最多 6 張縮圖，轉為文字請求的一部分；請求大小上限須配合。
- 磁碟：WAV 約 115 MB／小時（6 小時約 700 MB）；畫面檔以條目為單位建立並隨即刪除。

## 安全威脅與緩解

| 威脅 | 緩解 |
|---|---|
| 呼叫端以檔名讀取收件目錄外的檔案 | 檔名為相對路徑；拒絕絕對路徑、`..`、解析符號連結後在根目錄外、非一般檔案；檔名以參數陣列傳給行程，不經 shell |
| 偽造 webhook | per-trigger 密鑰，驗證先於讀取本文；本文大小有上限 |
| 提示注入（字幕或畫面中的指令） | 模型只回文字，無工具；結果寫入資料庫與字幕檔，字幕檔的位置與檔名不由模型內容決定；回答須通過條目數與時間檢查 |
| 有權呼叫 webhook 的人讓 pipeline 在收件根目錄內建立或覆蓋 `.srt` | 寫入範圍只限請求的影片檔所在目錄，且解析後（含符號連結）須在收件根目錄之內；檔名只由影片檔名與固定的語系規則組成；目標是目錄或符號連結時拒絕；先寫暫存檔再原子換名，兩個檔全有或全無；`intake` 階段先檢查目錄可寫與檔名可用。殘餘風險：檢查與換名之間有極短的時間差，目錄在這段時間被換成指向根目錄外的連結時，寫入的是換名那一刻的目錄；收件根目錄的寫入權應由呼叫端以外的人控制。Engine 帳號因此對收件根目錄有寫入權限，其他掛載仍唯讀（[04](04-deployment.md)） |
| 掃描模式讀取收件根目錄下所有項目 | 掃描只讀取目錄與檔案屬性；不跟隨符號連結（檔案與目錄皆然），不進入也不處理以點開頭者，非一般檔案略過；選定的影片仍通過與指定 `file` 相同的檔名檢查；最多檢視一萬個項目；log 只記計數，不列路徑 |
| 巨大或損毀的檔案 | ffprobe 先驗證有音訊串流與長度上限（`maxMediaSeconds`）；行程有逾時與取消時終止 |
| pipeline 是 unsafe | 管理員逐版本允許；pipeline 為薄 jar，只用 JDK、core、Kotlin 標準函式庫 |

## 失敗模式與降級

| 失敗 | 行為 |
|---|---|
| 檔案不存在、不可讀、無音訊、超過長度上限 | run 失敗，原因明確 |
| 掃描模式沒有待處理的影片 | run 立即成功，結果說明為 `NO_PENDING`，不進入 `audio` 以後的階段，不寫檔案；仍留下 run 紀錄 |
| 掃描選到的影片處理失敗 | run 失敗，該次計入這個檔案的失敗次數；同一檔案（相對路徑、大小與修改時間相同）達 `scanMaxAttempts` 次失敗後不再被選中，不阻擋其他影片；檔案被取代或修改後重新計數 |
| 影片所在目錄不可寫、在收件根目錄之外，或字幕檔名被目錄或符號連結佔用 | run 在 `intake` 失敗，不做轉錄；專用的失敗分類見 [runbook](runbook.md) |
| 字幕檔寫出失敗（`export`） | run 失敗，專用分類；資料庫的 `result` 已保存，可由資料庫取回。降級的 run 照常寫出；取消、逾時，或失敗於 `export` 之前的 run 不寫任何檔案 |
| ffmpeg 或 VAD 工具失敗或不存在 | run 失敗，指出缺哪一項 |
| 轉錄失敗（重試用盡） | run 失敗（沒有文字無法繼續） |
| 潤飾、核對、翻譯失敗 | 該組退回上一階段文字，標記降級，run 仍成功；降級數可查 |
| 補掃窗口轉錄失敗（重試用盡） | 略過該窗口，run 繼續；每個失敗窗口計入降級，run 的結果為 `success-degraded`；全部窗口失敗且沒有任何條目時以 `TRANSCRIPTION_FAILED` 失敗（[runbook](runbook.md) 第 10 節） |
| Lemonade 不可達 | 資源層逾時；視同上述 |
| Engine 重啟、取消或逾時 | run 立即結束並為 interrupted 或 cancelled；工作目錄由下次 run 開始時清理孤兒；不續跑 |

## 風險

| 風險 | 說明 | 處置 |
|---|---|---|
| Lemonade 圖片輸入或音訊端點不可用 | 全案依賴 | WI-1404 為可行性關卡，未通過就停下回報 |
| 獨佔 Lemonade 數小時至數十小時 | 後來搶資源的 digest-rss run 會處於等候狀態 | 假設 8：使用者已接受；以排程錯開可降低等候 |
| 長影片的 run 時間與中斷損失 | 長度上限 6 小時時，單次 run 可達數十小時，中斷即全部重跑 | 假設 7：中斷立即結束、不續跑；管理員可在 trigger 以較小的 `maxMediaSeconds` 限制；`RUNLINE_RUN_TIMEOUT_SECONDS` 不設定或遠大於預期 |
| 條目一一對應被模型破壞 | 影響時間軸 | ADR-038 的不變式與退回規則 |
| cron 間隔短於處理時間，等待資源的 run 累積 | Engine 沒有「前一個 run 未結束就跳過」的政策；每個等候的 run 在輪到時各自掃描，沒有待處理就立即結束，但佔用等候佇列，也可能遇到 `RUNLINE_RESOURCE_WAIT_TIMEOUT_SECONDS` 而失敗 | 排程間隔不小於典型的處理時間（[runbook](runbook.md) 第 14 節）；跳過政策是獨立議題（[ADR-040](adr/ADR-040-cron-scan-mode.md)） |
| 掃描的正確性依賴 `llm` 資源容量為 1 | 容量大於 1 時，兩個同時開始的 run 可能選到同一部影片 | 容量保持 1（[runbook](runbook.md) 第 5 節）；容量改大須另行處理，不屬於現行設計 |
| 以「字幕檔存在」判定「已產生字幕」 | 刪除或搬走 `_zh-TW.srt` 會使影片再被處理；字幕檔被別的程式放在影片旁（即使內容不是本 pipeline 寫的）會使影片永遠不被掃描 | 想重做就刪除字幕檔；排錯見 [runbook](runbook.md) 第 15.2 節 |
| 呼叫端以「新檔出現」觸發 webhook，pipeline 新建的檔案又觸發 run | 產生無效的 run | 呼叫端須忽略 pipeline 寫出的檔案（規則見 [04](04-deployment.md)） |
| 說話內容被潤飾或翻譯改寫意思 | 準確度 | 核對階段以畫面印證；保留每階段文字供比對 |
| VAD 參數敏感 | 切太碎或太長 | 全部為參數，並記錄各階段計數 |
| VAD 判定邏輯與官方實作不一致 | 判定規則在 pipeline 重現 | 以官方 Python 實作對同一批音訊產出的區間作為驗收基準；模型版本固定 |
| 模型版本介面差異 | 舊版與新版 silero 的狀態介面不同 | 工具固定模型版本與雜湊，升級視為新決策 |

## 可觀測性

階段 log（起訖、計數）；每次模型呼叫的耗時與重試；降級計數；失敗原因分類。指標沿用 Engine 的資源指標（等待、持有、請求數、token）。
