# WI-34 Console 的認證邊界、登入、跨分頁工作階段與 Engine 標示

本文回答：Console 如何登入、保存工作階段、跨分頁同步，並在每頁顯示 Engine 的版本與 commit hash，且讓登入方式日後可替換。狀態：已核可（2026-10-05）。相依：WI-28、WI-33。決策見 [ADR-017](../adr/ADR-017-console-websocket-and-token.md)、[ADR-016](../adr/ADR-016-engine-build-info-endpoint.md)。

## 背景

Token 登入是過渡機制，日後會被 OIDC 與帳號密碼取代（另開 ADR）。本項建立與憑證種類脫鉤的認證邊界，目前唯一的實作是 Bearer token。

## 行為與驗收條件

**認證邊界**
- 前端有一條明確的認證邊界；其餘程式只依賴與憑證種類無關的能力：目前登入狀態與身分（名稱、角色）及其變化通知、登入入口、為 API 請求附加認證資訊的單一出口、登出與 401 的統一處理、跨分頁同步與保存（同步的是不透明憑證）。畫面、路由與資料存取不直接接觸 token；以前端靜態檢查或測試強制（違反即失敗）。
- Token 的輸入畫面只屬於 token 登入方式；登入頁的外殼（版本與 hash、語系切換）與登入方式無關。

**Token 登入與工作階段**
- 登入：輸入 token 後以 `GET /api/v1/system` 驗證；401 顯示無效並不保存；成功取得名稱與角色，導覽依角色顯示（管理員專屬頁僅管理員可見，直接輸入網址也被擋並導向適當畫面）。
- 保存在 sessionStorage，不使用 localStorage，不提供「記住我」；token 不出現在網址、路由、歷史、前端 log 與錯誤回報。
- 跨分頁（BroadcastChannel，同源）：新分頁啟動時向已登入的分頁請求憑證，取得後存入自己的 sessionStorage，逾時沒有回覆則顯示登入畫面；登入、登出與「401 而清除」都廣播，所有分頁同步；登出傳播到所有分頁並回到登入畫面。頻道只傳登入狀態事件與憑證。
- 競態與邊界有驗收：兩個分頁同時啟動、頻道無人回覆、登出與詢問同時發生、重新整理單一分頁（sessionStorage 保留）、所有分頁關閉後重新開啟（需重新登入）。
- 任何 API 回 401：清除並廣播，回到登入畫面並保留原目標頁，登入後返回。
- 非 HTTPS（本機開發的 localhost 除外）下登入時顯示警告。

**Engine 標示**
- 登入前（含登入頁頁尾）以 `GET /api/v1/info` 顯示版本與短 hash（7 碼，等寬字型）；登入後改用 `GET /api/v1/system`。每個畫面都顯示：側邊欄底部的 Engine 晶片與頂欄右側（寬螢幕）。
- `dirty` 為 true 時在短 hash 後顯示 dirty 標記；`commitHash` 為 `unknown` 時顯示 unknown。
- 點擊或懸浮顯示：版本、完整 40 碼 hash（可複製）、建置時間（commit 時間，說明語意）、JDK、運行時間、API 基底網址（取自瀏覽器目前網址）、白名單版本；登入前只顯示公開欄位。
- 連線狀態點由最近一次 API 呼叫是否成功判斷，不呼叫探測端點。
- 全部文字經 WI-33 的多語系機制。

**驗收方式**
- 使用真實的打包後 Engine、真實 PostgreSQL（Testcontainers）與真實瀏覽器引擎（多分頁情境需真實 BroadcastChannel 與 sessionStorage 行為）；單元測試涵蓋邊界的純邏輯。不使用 Stub 或 Mock；需要替代品時使用自製的簡易真實實作（Fake）。
- 以真實 Engine 驗證：開發人員 token 看不到管理員頁，管理員 token 看得到；無效 token 被拒。
- 驗證邊界可替換：以一個自製的第二種登入方式（Fake，僅用於測試）接上邊界，證明畫面程式不需修改即可運作；此 Fake 不進入產物。

## 架構約束

- 不改變 API 契約與 [ADR-012](../adr/ADR-012-api-authentication.md)；不新增登入端點或伺服器端工作階段。
- 不設計 OIDC 或帳號密碼流程。
- 不新增 CI；前端測試納入 `check`。
