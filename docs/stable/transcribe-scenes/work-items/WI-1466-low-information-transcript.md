# WI-1466 低資訊量的轉錄文字視同沒有文字

本文回答：轉錄文字幾乎全是重複語助詞時 pipeline 要怎麼做。狀態：已核可（2026-10-15）。相依：WI-1463、WI-1465。決策見 [ADR-062](../adr/ADR-062-low-information-transcript-is-not-subtitle.md)。儲存庫：T。

## 行為與驗收條件

1. **判定**：轉錄成功的片段文字（含經懲罰重試救回者），幾乎全由少數幾種字元重複構成時，判為低資訊量。門檻為新參數，值域在 intake 檢查，錯誤指出參數；預設值依 ADR-062 的待確認問題決定。
2. **處理**：低資訊量的片段不送對齊、沒有條目，計入階段與 run 的降級及 `transcribeFailed`；原因另列為低資訊量；EXCHANGE 保留原文；log 列出片段編號與原因；不計入及早止損。
3. **不誤傷**：短而真實的回應（單句「はい」「うん」等）不被判為低資訊量；正常對話片段（可用 run 13、16 的 180 至 360 秒文字作為樣本）不受影響。
4. **全部失敗才失敗**：有語音的片段全部沒有可用文字（含低資訊量）時，run 以轉錄類別失敗，訊息含各原因的片段數；至少一個片段可用則降級完成。
5. **來源語言**：被判為低資訊量的片段不參與來源語言的決定；因此全片都是呻吟的影片不會產出以該語言命名的字幕檔。
6. **可觀測**：結果行與 RUN SUMMARY 的轉錄失敗原因多列低資訊量的片段數；RUN SUMMARY 的降級括號納入轉錄階段，各階段加總等於總降級數；README 的排錯章節說明如何判讀與如何調整門檻。
7. **重現**：以 run 17 的四個片段文字（兩個救回、兩個截斷）重現時，結果為 NO_TRANSCRIPT 失敗，影片旁沒有字幕檔。
8. 其餘行為（生成上限、懲罰重試、對齊、場景、潤飾、摘要、翻譯、view）不變。

## 架構約束

- 不改 Engine；只新增一個門檻參數，不新增環境變數或掛載，不改 schema（原因欄位若需持久化，先回報）。
- 判定與語言無關，不依賴詞典或外部服務。
- 嚴格 TDD；測試不使用 Stub 或 Mock，以假服務重現「全部呻吟」「呻吟與正常對話混合」「單句短回應」三種情境。
- 部署時需處理的事（新參數、環境變數、掛載）回報時列出。
