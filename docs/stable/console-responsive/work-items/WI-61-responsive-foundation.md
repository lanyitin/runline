# WI-61 窄版面的基礎

本文回答：窄版面要先具備哪些共用規則與驗證基礎，後續頁面才能依此調整。狀態：已核可（2026-10-13）。相依：無。決策見 [ADR-048](../adr/ADR-048-responsive-console.md)。

## 行為與驗收條件

- 視窗寬度低於 768px 為窄版面，768px 以上為寬版面；斷點在設計系統中定義一次，各元件引用同一個來源。
- 窄版面的導覽：側邊欄不常駐，頂列有選單鍵；按下開啟抽屜，選取項目、按 Esc 或點遮罩後關閉；開啟時焦點進入抽屜，關閉時回到選單鍵；選單鍵與抽屜有名稱與展開狀態標示。寬版面維持常駐側邊欄，行為不變。
- 窄版面的頂列與麵包屑不溢位：次要資訊可省略，導覽、語言切換與登出保留且可點；麵包屑過長時在自身區域內截斷或換行。
- 窄版面下，按鈕、連結與表單控制項的可點區域至少 44px；輸入欄位字級至少 16px。
- 頁面主體整頁不水平捲動；提供一個共用的方式，讓寬內容（表格、程式碼、長字串）在自身容器內捲動或換行，後續工作項沿用。
- 新增的文案（選單鍵、抽屜）在所有支援的語言都有。
- 驗證基礎：既有的真實瀏覽器 e2e 能以手機尺寸視窗執行，並有共用的檢查「整頁無水平溢位」與「導覽可開關」；先在登入後的首頁與一個含表格的頁面證明可用。
- 既有 Console 測試與 e2e 在寬版面全部通過。

## 架構約束

- 不新增斷點之外的版面分類；寬版面行為與外觀不變。
- 不修改 Engine 與 API。
- 沿用現有 `Dialog` 的焦點與鍵盤處理方式。
- 測試不使用 Stub 或 Mock。
