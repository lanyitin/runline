# WI-1446 Console 建立 run 與 trigger 頁面能完整顯示與編輯長文字參數的預設值

本文回答：長達數百字、含多行的文字參數（如 prompt）在建立 run 的頁面如何顯示預設值與輸入。狀態：已核可（2026-10-13）。依據 [WI-1445](WI-1445-prompt-parameters.md)。相依：無。儲存庫：R（runline，`console/`）。

## 背景

建立 run 的頁面（`console/src/pages/CreateRunPage.svelte`）對每個參數使用單行文字輸入，預設值作為輸入框的占位文字，並在說明列以內嵌文字顯示「預設：…」。短值夠用；長達數百字且含多行的 prompt 在單行輸入框中看不到全文，在說明列也不易閱讀與比對。Trigger 的表單（`TriggerFormPage.svelte`）有相同的參數列表。

## 行為與驗收條件

1. **顯示預設值全文**：建立 run 頁面對每個有預設值的參數，能閱讀預設值的全文，保留換行，可捲動或展開，不截斷；短值的顯示與現況相同（不增加干擾）。
2. **輸入**：長文字或含換行的預設值，輸入欄位為多行文字區；留空表示使用預設值，與現況相同。使用者可從預設值開始修改（例如有「以預設值填入」的操作），但不強制：不操作就不送出該參數。
3. **判斷依據**：何者算長文字，由頁面依預設值本身判斷（含換行，或長度超過實作者提案的門檻）；不需要 Engine 新增參數型別。若實作者認為需要 Engine 的宣告 metadata 新增欄位，先回報架構師，不自行擴充 API。
4. **範圍**：建立 run 與 trigger 表單（固定參數）一致；預設值與使用者輸入都只當純文字顯示，不解讀為標記語言；含特殊字元的值不影響頁面。
5. **無障礙與語系**：沿用現有元件與 i18n 機制，新增的文字有繁中與英文兩份。
6. **驗證**：以現有的前端測試方式涵蓋：短值維持現況、長值與多行值顯示全文且保留換行、輸入多行值能送出、留空不送出該參數、特殊字元（HTML 標記、引號）被當作文字、trigger 表單一致。

## 架構約束

- 不改 Engine API 與參數宣告的格式。
- 不引入新的前端相依套件（除非先回報架構師）。
- 嚴格 TDD；前端測試用現有的測試設施。
