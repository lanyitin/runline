# 非功能性考量與風險

本文回答：view 機制的可觀測性、安全、效能與失敗模式。決策見 [ADR-033](adr/ADR-033-pipeline-views.md)。

## 安全

| 威脅 | 緩解 |
|---|---|
| 查詢文字企圖寫入或執行多個語句 | Engine 保證唯讀與單一語句，不依賴帳號權限；兩種資料庫都以真實實例驗證（WI-1301） |
| 參數注入 | 參數值只作為查詢參數傳遞 |
| 不可信文字造成 XSS | 儲存格一律純文字顯示；不提供連結與標記型別 |
| 開發人員透過 view 讀到他人資料 | view 只能讀 pipeline 已綁定的資源，此能力開發人員在自己的 run 中本來就有；他人版本的 view 回應與不存在相同 |
| 回應洩漏機密 | 連結欄不提供；查詢文字與參數值不進回應與 log |

## 效能與失敗模式

- 昂貴的查詢：逾時、列數、位元組上限與每資源並行上限；超過時明確報錯，run 不受影響。逾時為 30 秒與資源語句逾時中較小者，並行上限預設 4、可由環境變數調整（[ADR-035](adr/ADR-035-view-read-limits.md)；變數名稱與預設值見 [部署文件](../pipeline-engine/04-deployment.md)）。
- SQLite 單寫入者：view 讀取不得阻塞 run 寫入（日誌模式讀寫並行）；WI-1301 驗證 run 進行中讀取仍可成功。
- 結構不符：新版 view 對舊資料庫報「結構不符」，由使用者在下一次 run（結構於 run 開始時升級，digest-rss 06）後恢復；不降級為錯誤的資料。
- 資源停用或未綁定：view 清單顯示狀態，讀取回明確錯誤。

## 可觀測性

- 每次讀取記錄 view 識別、結果碼、耗時與列數，並有對應的 metric（次數、耗時、失敗）與 trace；不記錄查詢文字與參數值。

## 風險

- view 查詢是資料庫方言文字，pipeline 換資料庫時要改寫（可接受，view 隨 pipeline 發佈）。
- 通用表格的表達力有限；若日後需要圖表或明細頁，另開 ADR 擴充欄位型別，不改變唯讀與隔離邊界。

## 成本

不新增執行單元；成本是 Engine 與 Console 的開發量與少量查詢負載。
