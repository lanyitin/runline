# 非功能性考量與風險

本文回答：這次重整對非功能需求的影響，以及主要風險與緩解方式。

## 非功能影響

| 面向 | 影響 |
|---|---|
| 對外行為 | 不變。API、錯誤代碼、組態鍵、log 訊息、metric 與 span 名稱、判定結果皆維持 |
| 效能與容量 | 不變；不改執行模型、並行模型與資料存取 |
| 安全 | 改善：core 的受信任面縮小到撰寫契約（[ADR-024](adr/ADR-024-core-contract-only.md)）；機密仍只由 engine 的金鑰庫提供，不穿過 accessors 的對外描述 |
| 可觀測 | metric 與 trace 的名稱、標籤不變；可觀測事件的來源移到 accessors，轉換仍在 engine |
| 建置與發佈 | 模組數與產物不變；新增依賴方向檢查納入 `check`；位元組級可重現維持 |

## 風險與緩解

| 風險 | 可能性 | 影響 | 緩解 |
|---|---|---|---|
| 大範圍搬移造成行為回歸 | 中 | 高 | 每個工作項只做一種搬移；既有測試（約 5 萬行）全部通過且數量不減少為驗收條件；不在同一工作項改行為 |
| devkit 與 engine 對同一份資源設定的結果不一致 | 中 | 中 | WI-67 以同一組設定案例同時驗證兩者 |
| core 移除公開類別造成外部 pipeline 不相容 | 低 | 中 | 待確認 Q1；判定變化（參照被移走的類別變為 unsafe）屬預期，於 08-api 或 devkit 指南註明 |
| 自動檢查規則過嚴阻礙合理變更 | 低 | 低 | 規則以 ADR-023 的方向表為唯一來源；調整方向須先修訂 ADR |
| 重整期間與功能開發衝突 | 中 | 中 | 待確認 Q4；工作項小而獨立，完成即合併 |
| 金鑰庫或 OpenTelemetry 依賴滲入 accessors | 低 | 高 | ADR-022 約束：accessors 不依賴 engine、金鑰庫實作與 OpenTelemetry，由依賴檢查確認 |
