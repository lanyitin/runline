# WI-04 IO 錄製與 metadata 提案

目標：開發人員錄下一次 run 的所有 IO，並得到可採用的 metadata 提案。

狀態：已核可（2026-10-05）。相依：WI-03。依 [ADR-004](../adr/ADR-004-recording.md) 明定錄製模式的限制處理、事件內容與量、提案內容與採用驗證。

## 行為與驗收條件

### 錄製的開關與模式
- 開發入口可開關錄製；預設關閉。Engine 沒有任何開啟錄製的途徑，Engine 的 run 行為與改動前完全相同；以測試驗證。
- 錄製模式暫時放寬 metadata 宣告的限制：檔案範圍與讀寫、網路範圍、外部行程範圍不受宣告限制，所有動作都被允許並記錄。
- 錄製模式下，目錄範圍的邊界仍然拒絕：絕對路徑、相對路徑跳出範圍、符號連結逃逸；磁碟用量上限仍然生效。被拒絕的邊界違規同樣被記錄，但不納入提案。
- 錄製模式在輸出中明確標示限制已放寬，並說明此次執行不代表一般模式下的結果。
- 錄製不改變 pipeline 的行為與結果：以真實 pipeline 驗證，錄製模式下的輸出與結果，和在不受限制的情況下執行相同（相同輸入）。

### 事件
- 錄製涵蓋檔案、網路連線、外部行程，發生在 context 層。
- 每筆事件至少包含類別、目標、讀寫性質、發生順序：
  - 檔案：所用的目錄範圍（共享或私有）、相對位置與讀寫性質（讀取、列出、查詢存在為讀；寫入、刪除為寫）；不含絕對路徑與檔案內容。
  - 網路：目標主機與埠號；不含傳輸內容。
  - 外部行程：被執行的指令（第一個元素）；不含引數與輸出。
- 事件跨越 class loader 邊界時只使用 JDK 內建型別，不洩漏 devkit 或 Engine 的型別（[ADR-001](../adr/ADR-001-isolated-classloader.md)、[05](../05-ipc.md)）。
- 事件量有上限；超過上限後改以聚合方式保存，不耗盡記憶體，且提案不遺漏任何用過的範圍；以測試驗證（大量重複事件、大量不同目標）。上限由組態決定並有合理預設。

### 提案
- 錄製結束後產出 metadata 提案文件：
  - 檔案：用過的目錄範圍與讀寫（任何寫入或刪除即為可寫）。
  - 網路：實際使用過的主機名稱（不分大小寫、不含埠號，依 [ADR-010](../adr/ADR-010-access-allow-list-matching.md)）。
  - 外部行程：實際執行過的指令名稱。
  - 沒有使用過的類別，提案為「不允許」，不是「不限制」。
- 提案不含共享資源、參數與 trigger。
- 提案以人可讀、可直接對照 pipeline 宣告的文件呈現，註明其涵蓋限度（只涵蓋走過的路徑；直接使用 JDK 的 IO 類別不被錄製）；文件的具體格式由實作提出並說明。
- 提案不自動套用到 pipeline，由開發人員自行採用。
- 提案採用後以一般模式用相同輸入再執行同一 pipeline，不因 metadata 限制而失敗；以真實編譯的 pipeline 驗證：錄製 → 依提案宣告 → 重新編譯 → 一般模式執行成功；涵蓋檔案（讀與寫）、網路（本機真實伺服器）、外部行程各至少一個情境，以及沒有任何 IO 的 pipeline（提案為全部不允許）。
- 提案縮小網路與外部行程範圍後，原本因「未限制」被判 unsafe 的 pipeline 在同一份白名單下，判定可由 unsafe 變為 safe；以測試驗證此關係。

### 共同
- 提供開發人員操作指南的更新：如何開啟錄製、輸出在哪裡、如何採用提案、錄製模式與一般模式的差異與限度。
- 建置、全部測試（含打包形態的測試）在 JDK 25 下通過，`ktfmtCheck` 通過；既有測試數量不減少。

## 架構約束

[ADR-004](../adr/ADR-004-recording.md)：不做重放，不做 mock。錄製發生在 context 層。

- 開發入口與 Engine 共用同一條 Runner 執行路徑與同一份 context；錄製是 context 的可選模式，不得為此另建執行路徑，也不得改變 Engine 的行為。
- core 與 runner 不得因錄製而依賴 Ktor、OpenTelemetry、Engine 或 devkit；core 仍只依賴 JDK 與 Kotlin 標準函式庫。
- 不修改 analyzer 的判定行為；錄製與提案不使用 analyzer 的判定，只與其關係以測試驗證。
- 錄製不得記錄機密：不記錄檔案內容、行程引數與輸出、傳輸內容；錄製輸出不含主機上的絕對路徑。
- 測試使用真實編譯的 pipeline、真實的本機伺服器與真實行程，不使用 Stub 或 Mock；時間以可控制的時鐘提供，不以睡眠換取通過；測試等待須有逾時保護（[WI-26](WI-26-test-timeouts.md)）。
- 不新增外部相依；不新增 git hook 或 CI；完成程式碼變更時依專案規則先以 ktfmt 格式化。
