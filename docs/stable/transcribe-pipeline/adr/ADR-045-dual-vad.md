# ADR-045 以 silero 與 TEN VAD 兩份機率加權判定語音

本文回答：silero 對這類音訊漏判人聲時，如何提高語音區間的召回。狀態：已取代（[ADR-046](ADR-046-denoise-before-vad.md)）；保留供日後參考。修訂 [ADR-038](ADR-038-segment-model-and-stage-invariants.md) 決策 0（VAD 工具只有一份機率序列）；不改變其他不變式。與 [ADR-044](ADR-044-asr-coverage-sweep.md)（ASR 補掃）互補，不互相取代。

## 背景

arr 的實驗（NTRH-002-C.mp4，234 秒；弱真值：ASR 辨識出語音的區間共 31.9 秒應涵蓋、雜音區間 55.8 秒不應涵蓋）：

| 偵測 | 區間數 | 涵蓋 | 應涵蓋被涵蓋 | 不應涵蓋被涵蓋 |
|---|---|---|---|---|
| silero@0.5 | 27 | 13.8% | 0.0% | 0.01 秒 |
| silero@0.3 | 39 | 17.9% | 12.5% | 1.1 秒 |
| TEN@0.5 | 52 | 45.6% | 62.3% | 12.7 秒 |
| 聯集（兩者@0.5，機率取最大） | 50 | 48.3% | 62.5% | 14.3 秒 |
| 交集、平均 | — | 13.7%、22.3% | 0.0%、22.5% | — |

- 加權（silero 0.3、TEN 0.7，0.1 秒格子）的實測：這支影片的人聲區間 silero 機率幾近 0，所以合併後等於 TEN 乘以 0.7；開始／結束門檻 0.35／0.25 時，應涵蓋被涵蓋 64.7%、雜音被涵蓋 13.0 秒；0.35／0.30 為 57.3%、7.2 秒；0.45／0.40 為 43.2%、3.6 秒。這支影片無法顯示 silero 貢獻的價值，silero 的價值在安靜對白的精準邊界。
- 官方 TEN 的 ONNX 模型只含神經網路；前處理（STFT、pitch 估計等）在官方 C++ 實作中，Java 版須自行重現。官方原生函式庫與 ONNX 範例的逐幀機率差異極小（最大 0.0007）。
- silero 對這支影片的人聲逐幀機率最大 0.74、平均 0.05；TEN 同區間平均 0.49。silero 的漏判是系統性的，不是門檻問題。
- TEN 的雜音機率不低（雜音區間 p50 0.30、p90 0.49），門檻降到 0.3 時，沿用「結束門檻＝開始門檻減 0.15」的規則會使區間幾乎不結束（95% 被涵蓋），是規則效應。
- 取兩者聯集新增的區間，經 ASR 確認有真實日語的包括 148.0–150.2、213.5–217.7；其餘多為雜音，ASR 回中文單字或 `language None`。
- TEN VAD 的授權是 Apache 2.0 加附加條件：不得以與 Agora 產品競爭的方式散佈或部署，且只能為自己與直接終端使用者的利益部署自己的應用。含 LPCNet 衍生程式碼（BSD）。

## 決策

1. 增加第二個 VAD 工具（TEN VAD），與現有 silero 工具同為獨立行程，同一種契約：輸入 16 kHz 單聲道 WAV，輸出整個檔案的逐視窗語音機率與視窗長度。pipeline 不依賴任何一個工具的內部實作。
2. TEN VAD 工具首選以 ONNX Runtime 在 Java 行程執行官方 ONNX 模型（與 silero 工具相同的執行環境），特徵擷取以 Java 實作，並以官方實作的輸出作為對照基準。Java 版無法在容許誤差內重現官方輸出時，使用者已允許改用官方預編譯的原生函式庫（Linux x86_64）加 Java 包裝；仍是獨立行程、同一種契約，不進 pipeline jar。切換時須先向架構師回報可行性結果。
3. pipeline 把兩份機率各自平均到 0.1 秒的格子，再逐格加權：`合併 ＝ 0.3 × silero ＋ 0.7 × TEN`（使用者的既有策略）。權重為管理員可調的參數，預設 0.3 與 0.7。合併後的單一機率序列沿用 ADR-038 的 VAD-A、VAD-B 判定。
4. 合併機率使用一組開始門檻與結束門檻；結束門檻為獨立參數，不再固定為開始門檻減 0.15。門檻預設值依實測起算（見 [WI-1439](../work-items/WI-1439-dual-vad-combination.md)）。
5. 最大值（聯集）、交集與等權平均實驗中的召回或精確度較差，不採用；加權比例是使用者的決定，保留為參數。
6. 兩個工具的版本、模型與雜湊固定並記錄；失敗時的行為：TEN 工具不可用（未設定、不存在、執行失敗）時，run 以 `CONFIGURATION` 失敗並指出原因；管理員可用參數關閉雙 VAD，回到單一 silero，行為與之前相同。
7. 雜音區間由後續的 ASR 過濾（`language None`、跨語言短回答）處理；雜音的處理規則由 [ADR-044](ADR-044-asr-coverage-sweep.md) 的幻覺過濾定義，兩項決策共用同一份過濾。

## 取捨

| 選項 | 優點 | 缺點 |
|---|---|---|
| A. 0.1 秒格子加權平均（0.3／0.7，採用） | 兩個偵測器的證據都計入；雜音需兩者同意才高（TEN 單獨 0.3 的雜音，加權後約 0.2）；權重可調 | 0.1 秒粒度略粗於 silero 的 32 毫秒視窗；門檻需實驗決定 |
| A'. 機率取最大值（聯集） | 召回最高；最簡單 | TEN 雜音多，送出的段落增加更多 |
| B. 只換成 TEN | 一個工具 | 失去 silero 在安靜對白中的精準邊界；雜音更多 |
| C. 只用 ASR 補掃（ADR-044） | 不增加偵測器 | 時間粒度粗；每個空隙都要送 ASR |
| D. 先對音訊前處理 | 不增加依賴 | 實測覆蓋率不改善 |

## 後果

- 部署多一個外部工具：TEN VAD 的 ONNX 模型（或在退路下的原生函式庫）與授權條件。授權條款受 TEN 的約束；個人家用部署符合「為自己的利益部署」，runline 若公開散佈需再評估。
- 召回在這支影片仍未到 100%：弱真值以 8 秒切片為單位，涵蓋率包含切片內本來就安靜的部分，所以實際召回高於數字；剩餘缺口由 ADR-044 的補掃處理。
- 送給 ASR 的段落增加（本例約 50 段，每段不到 1 秒的呼叫），對耗時影響很小；轉錄階段的 `language None` 與跨語言短回答增加，被過濾的項目必須可查，不得靜默消失。
- 欄位與資料：資料庫記錄每個條目的來源偵測器（silero、TEN 或兩者）為可選的診斷資訊，由實作者評估是否值得；不得因此改變既有 view 的欄位與值。
- 待確認問題：Java 特徵擷取與官方實作的一致程度由 [WI-1438](../work-items/WI-1438-ten-vad-tool.md) 的可行性關卡確認。
