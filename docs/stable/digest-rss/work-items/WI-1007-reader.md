# WI-1007 讀者

本文回答：讀者要達成什麼行為。狀態：已核可（2026-10-09）；已實作，標註案例數、請求模型 id 的來源與 `condition=none` 的行為於同日修訂，修訂的落實見 [WI-1018](WI-1018-parameter-revision.md)。

目標：對 worklist 的每篇、每個條件，用模型判定並產出保留或過濾的結果，圖文分析結果記入資料庫。行為參考：來源的 `read-article.mjs`、`lib/reader-prompt.mjs`、`lib/lmclient.mjs`、`lib/fold.mjs`、`model-check.mjs`、`reconcile.sh`、`criteria/`。工作儲存庫：`runline-digest-rss`。

## 驗收條件

1. 條件與 rubric 以 id 選擇，隨 jar 發佈；兩種關鍵字（給模型看的、可單獨決定判定的）分開保存，語意與來源一致，短 CJK 子字串不得誤判（例：「カップ」不得命中「カップル」）。`condition=none` 不呼叫模型、不做可用性檢查、`llm` 資源可不綁定，可讀的文章全部記為保留（與來源沒有條件時的行為一致）。
2. 每篇每個條件一次模型呼叫，rubric 為系統提示，附頁面文字與封面圖；經 `openai-compatible` 存取端。讀者 thinking 開。
3. 回答解析、分級映射為 yes／no、否決規則與來源等價：以來源單元測試的案例逐一轉寫，並以 32 個標註案例（來源資料實際為 32 個）重放來源記錄的模型回答驗證解析、映射、否決、引文驗證與對帳；對真實模型是否與標註一致，由不屬預設測試的任務在有真實模型的環境回答。
4. 引文驗證：任何引用必須是該篇擷取文字經正規化後的子字串，否則該條件判 no 並記錄被拒絕；讀者不得決定 url、標題、路徑，保留的紀錄由程式組成。
5. 每個條件寫入 VERDICT（原始分級、yes／no、否決規則、引文與驗證結果、拒絕原因），每次呼叫寫入 READER_EXCHANGE（請求與回應文字、請求與回應的模型、thinking、耗時、用量）；RUN_POST 記錄最終處置與未處理原因。
6. 請求的模型 id 取自 pipeline 參數 `readerModel`（WI-1002）；回應的模型名稱取自串流事件，與請求不符即中止 run 並說明；回應拿不到模型名稱時同樣中止。
7. 模型可用性先行檢查，不可用時不開瀏覽器、不標記，結果記入 RUN。
8. 模型中途消失：只對尚未判定者重試一次，再失敗放棄並記錄；重試不得覆蓋既有的判定（比對內容，不只看計數）。
9. 對帳：每篇送進讀者者必有判定紀錄，否則列為未對帳。
10. 並行度 1。
11. 取樣參數不由 pipeline 送出，由 `llm` 資源的 `defaults` 提供；與來源等價的建議值（temperature 0.6、top_p 0.9、top_k 64、min_p 0.05、max_tokens 8192）寫入上線手冊。

## 架構約束

- 以 Fake 的 OpenAI 相容服務（真實實作）驗證，不使用 Mock。
- 驗收的是行為等價，不是提升準確度。
