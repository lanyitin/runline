# ADR-035 View 讀取的逾時與並行上限

狀態：提案中（2026-10-11）。補充 [ADR-033](../../../stable/pipeline-views/adr/ADR-033-pipeline-views.md)「執行與唯讀」一節與 [07-nfr-risks](../../../stable/pipeline-views/07-nfr-risks.md)。回答：一次 view 讀取最久可以多久、同一資源上同時可有幾個讀取，以及這些值由誰設定。

## 背景

ADR-033 規定 view 套用資源既有的逾時、列數與回應大小上限，並有自己的並行上限。實作時逾時沿用資源的語句逾時（預設 5 分鐘），對互動式的 Console 太長；並行上限寫死為 4，07-nfr 當時說不新增組態。

## 決策

- **逾時**：view 讀取的逾時為「30 秒」與「資源語句逾時」兩者中較小者。30 秒是固定值，不另設組態。超時回應的錯誤語意不變。
- **並行上限**：每個資源同時進行的 view 讀取數，預設 4，可由 Engine 的組態調整（環境變數，12-Factor）。一個值套用到所有資源。值必須是正整數；不合法時 Engine 啟動失敗並指出名稱，不靜默採用預設。
- 列數與回應大小上限維持沿用資源既有設定。

## 取捨

- 得到：Console 不會等待數分鐘；管理員可依主機能力調整並行。
- 失去：需要查詢超過 30 秒的情境不被支援（view 是互動式清單，這類查詢應改為預先彙整的資料）；並行上限不能依資源個別調整。

## 後果

- 07-nfr 的「不新增組態」改為例外：新增一個環境變數，記載於部署文件。
- 由 [WI-1305](../work-items/WI-1305-view-read-limits.md) 處理。
