# WI-33 Console 骨架、設計系統與多語系基礎

本文回答：Console 前端的整體外殼、視覺基礎、路由與多語系基礎如何建立，使後續畫面只需填入內容。狀態：已核可（2026-10-05）。相依：WI-31。決策見 [ADR-015](../adr/ADR-015-console-frontend.md)、[ADR-017](../adr/ADR-017-console-websocket-and-token.md)；視覺規範見 `.superdesign/design-system.md` 與 Superdesign 專案 "Runline Console"（id 4ff467d7-b256-42e1-8f12-5407d2f50001）。

## 背景

WI-31 只有最小入口頁。本項建立外殼與基礎設施，不含具體業務畫面（WI-34 起）。

## 行為與驗收條件

**外殼與視覺**
- 依設計系統實作主題（淺色為主、可選深色）、側邊欄、頂欄、麵包屑、徽章（run 狀態、SAFE／UNSAFE）、表格、狀態點等共用元件；字型自行打包，不載入第三方資源。
- History 路由；未知路由顯示明確的找不到頁；管理員專屬頁（Triggers、Allow-list、Resources）的導覽項依角色顯示（角色來自 WI-34，本項以可替換的身分來源開發）；Engine 頁（版本與建置資訊）開發人員與管理員都可見，不屬於管理員導覽。
- 無障礙基本要求：可用鍵盤操作導覽與表單，對比度符合規範，狀態不只靠顏色表達。

**多語系（ADR-015）**
- 提供 zh-TW 與 en 兩個語系；函式庫已核可（[ADR-015](../adr/ADR-015-console-frontend.md)）：`intl-messageformat` 12.1.3 加 `@formatjs/icu-messageformat-parser` 3.5.21（鎖定版本），其上由專案提供薄的、有型別的翻譯層（`t()`／`translate()`），畫面只呼叫這一層；須支援 ICU 複數與參數、缺漏鍵後備（英文）、翻譯檔隨 bundle 打包。
- 語系偵測順序：先前的選擇 → 瀏覽器偏好（`zh` 系對應 zh-TW、`en` 系對應 en）→ 預設 zh-TW。語言切換在登入前後皆可用，立即生效，不需重新載入或重新登入；選擇存 localStorage（所有分頁共用），不寫入伺服器；`<html lang>` 隨語系更新。
- 翻譯檔每個語系一份，以穩定的鍵索引；兩個語系的鍵集合不一致或缺鍵時，本機建置失敗；英文為後備語系。
- API 錯誤本地化：以 `error` 代碼（加 HTTP 狀態與 `problems[]`、`problem`）對應翻譯鍵；`message` 不作顯示依據，只在「詳細資訊」以原文顯示並標示為伺服器原文；無對應翻譯的代碼顯示通用訊息並附原始代碼（500 附 `errorId`）。
- 本機驗證：08-api 記載的每個錯誤代碼在兩個語系都有翻譯（以 08-api 為單一事實來源，缺漏時失敗並列出代碼）；run 狀態、判定、`reasons[].kind` 等列舉值同樣有翻譯。
- 日期與數字：ISO-8601 UTC 依語系與瀏覽器時區顯示本地時間，懸浮提示顯示 UTC 原值；相對時間、持續時間、位元組大小、數字分隔符依語系格式化；hash、runId、cron、類別名稱不格式化。

**不可信內容的顯示基礎（ADR-017）**
- 提供一個共用的純文字顯示機制，供 pipeline 名稱、參數、log 行、失敗訊息與堆疊、jar 內字串使用；不提供把字串當標記插入的捷徑。以前端靜態檢查規則禁止使用會把字串當標記插入的機制，違反即建置失敗。

**驗收方式**
- 前端單元測試涵蓋語系偵測、切換、鍵一致檢查、錯誤代碼對應、格式化，納入 `check`。
- 元件行為（切換語系不重新載入、鍵盤操作）以真實瀏覽器引擎驗證，使用本機手動執行的腳本（端對端 `npm run e2e`、契約 `npm run test:contract`，需要 Chrome 與執行中的打包後 Engine）；這些腳本不接進 Gradle `check`（使用者決定），執行方式寫入 README，完成時在回報中附上執行結果。
- 若需要 Engine 的替代品，只能用自製的簡易真實實作（Fake），不得使用 Stub 或 Mock。

## 架構約束

- 只修改前端專案與其測試；不改變 API 契約。
- 畫面與路由只依賴身分與角色，不接觸憑證（為 WI-34 的認證邊界預留）。
- 不新增 CI；前端單元測試與型別檢查納入 `check`，真實瀏覽器腳本為手動執行。
