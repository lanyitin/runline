# WI-1305 View 讀取的逾時與並行上限

本文回答：view 讀取的逾時與並行上限如何設定與驗收。狀態：提案中（2026-10-11）。相依：WI-1301（已完成）。儲存庫：runline。

## 背景

見 [ADR-035](../adr/ADR-035-view-read-limits.md)。

## 行為與驗收條件

1. view 讀取的逾時為 30 秒與資源語句逾時兩者中較小者；資源語句逾時小於 30 秒時以資源的為準。超時回應仍為既有的逾時錯誤，且資料庫端的語句被取消、工作階段數回到 0。以真實 PostgreSQL 與真實 SQLite 驗證。
2. 每資源的並行讀取上限預設 4，可由 Engine 的環境變數調整；調整後超過上限的讀取立即得到既有的忙碌錯誤，其他資源不受影響，名額在讀取結束後歸還。
3. 環境變數值非正整數（零、負數、非數字、空白）時 Engine 啟動失敗，訊息指出變數名稱，不靜默採用預設。
4. 環境變數名稱與預設值記載於部署文件與 Engine 的組態說明，各記一次，其他處以連結引用。
5. 逾時與忙碌的 metric、log 行為不變，仍不含查詢文字與參數值。

## 架構約束

- 12-Factor：以環境變數組態，不寫入程式碼。
- 不新增依資源個別設定的機制。
- 測試不使用 Stub 或 Mock。
