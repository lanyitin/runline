# 小模型的行為特徵與對應的工作項

本文回答：實機 run 中觀察到哪些小模型（ASR、對話、摘要）的行為特徵，哪些工作項是為了對付這些特徵而做，各自改了什麼行為。狀態：已核可（2026-10-18）（彙整稿；內容出自 `docs/stable/transcribe-pipeline/` 與 `docs/stable/transcribe-scenes/` 已核可的 ADR、工作項與量測報告；本文不新增決策）。

涉及的模型：Qwen3-ASR（轉錄，chat 端點）、Gemma4-26B-A4B Q2_K_P（潤飾、摘要、翻譯）、Whisper／Kotoba-Whisper（二次轉錄）；對照測試過 Qwen3.5-4B、Mistral-7B-Instruct-v0.3、qwen3.5-0.8b／9b。工作項編號 14xx 的 T 項在 `runline-transcribe` 儲存庫，R 項在 runline。

## 1. 全貌

小模型在這個 pipeline 的共通問題是：它不會自己停、不會守格式、不會說「我做不到」。轉錄模型（ASR）與對話模型（chat）的失敗樣態不同，因此對策也分兩條路線。下面兩段是全貌，第 2 節起才是逐工作項的細節。

### 1.1 轉錄（ASR：Qwen3-ASR、Whisper）

轉錄模型的問題是「不知道該停」與「不知道自己聽到什麼」。遇到雜音、呻吟、笑聲這類非語言內容，它不會回「沒有語音」，而是持續生成，或反覆輸出「嗯」「啊」，一直到生成上限；用戶端逾時並不會讓伺服器停止，一個失控的請求會佔住只能一次服務一個請求的 Lemonade，擋住所有後續呼叫。溫度 0 時重試逐字相同，所以截斷後重試沒有意義，只有改變取樣（重複懲罰）才有機會打斷迴圈，而救回的文字也可能只是更短的「嗯啊啊」。它的語言判斷不可信：日語音訊常被「翻譯」成中文句子（一支影片約 18% 的條目），語言標示也不可靠，指定語言的參數在 chat 路徑無效。Whisper 系模型則在句尾冒出固定的幻覺句、短句重複，語言自動偵測在短片段會誤判。此外它只回文字、不回時間，且每次聽太短就缺少語境。因此對策是：給每個請求依音訊秒數設生成上限；截斷即降級、不重試、不計入止損；僅在截斷後帶懲罰重試一次；用與語言無關的重複度規則把低資訊量文字視同沒有文字；對降級或語言不符的片段，改用固定語言的 Kotoba-Whisper 二次轉錄；時間改由長片段加強制對齊取得；LLM 判斷轉錄好壞的準確度不足，所以一律只用純規則。

### 1.2 對話（chat：Gemma 等，用於潤飾、翻譯、摘要）

對話模型的問題是「不守格式」與「愛自言自語」。開 thinking 會讓推理迴圈、用盡額度，一條三字字幕也能推理數千 token，要它「簡短」或「不要解釋」都沒用；關掉 thinking 後，輸入只要互相矛盾（例如地點跳變、或上一層寫了「場景在此結束」），它仍會在回答前先用明文分析、反覆修稿直到上限，而這些殘文字會被存成正式摘要並傳給下一層。它不守輸出結構：多出 `- `、`->`、原文、問候、程式碼框，條目數、序號、行數、換人標記對不上；它會把已知的時間軸毫秒數「修正」成別的數字；翻譯時會原樣回傳日文；沒有素材時會編造內容或回答「沒有資料」；也會把「the man」這類描述當成人名。這些失敗在三個模型家族上型態一致，而且確定性高：重試（即使附上失敗原因）成功率只有個位數百分比，原樣回傳的片段重試仍逐字相同。更麻煩的是，我們自己寫的檢查規則也常誤判（簡體字集誤收「概」、短句被當成抄回語境），在小模型的雜訊下被放大。因此對策的方向是「預防優先於檢查」：thinking 預設關閉；時間、序號、條目數、換人標記這些已知資料不送給模型也不要求它回傳，由 pipeline 補回；回答以寬鬆方式依序號解析，格式雜訊一律忽略，取不到的條目才降級，不讓整個片段作廢；重試只留給服務層失敗與整個回答空手而回，另加一次只針對未翻譯條目的縮小重試；及早止損只看系統性失敗；場景摘要用預填固定回答開頭、片段摘要用詞避免誘發疑慮、沒有素材就不呼叫模型、欄位固定的層只保存欄位區塊、被截斷的摘要照存並標明給下一層，並把易誤判的檢查（字形、語境重複）拿掉，只留「含假名即未翻譯」這種客觀規則。

### 1.3 兩者共通的原則

- 每個請求都要有生成上限，逾時另設；
- 失敗以最小單位承擔（轉錄為片段，潤飾與翻譯為條目），並保存原文與降級原因，事後可查；
- 以量測而非假設調整，目前證據多來自單一影片與單一模型版本。

| WI-1488（T）預設提示採用量測結構 | run 38 用的是覆寫提示，與程式預設不同，量測結論不一定適用預設 | 場景預設提示改四個固定欄位（Setting／People／Progression／Ending）、1500 字元；片段預設提示改一到三句、500 字元且不含 scene；不寫死「Japanese」。已完成 |
| WI-1486（T）只存欄位區塊 | 場景 30 的摘要在 `Ending` 之後接了未寫完的自言自語，被存成正式摘要 | 以文字規則（非模型）裁掉 `Ending` 之後的內容，原文留在 EXCHANGE；回答不以標記開頭時不裁。已完成 |
| WI-1487（T）截斷旗標 | 被截斷的摘要被下一層當成完整可信 | 記錄「被截斷」；pipeline 在下一層輸入旁加註「可能不完整」；提示規範只可使用明確寫出的內容；不計入止損。已完成（schema 版本 19）。ADR-082 決定沒有任何完整欄位時仍保存 |

## 3. 跨項的設計取向

| 取向 | 說明 | 代表工作項 |
|---|---|---|
| 預防優先於檢查 | 先移除誘因：時間不送、用詞規定、預填開頭、無素材不呼叫 | WI-1464、1484、1483、1485 |
| 結構由 pipeline 掌握 | 序號、時間、條目數、語言碼是已知資料，不要求模型回傳；不可靠的換人標記不再要求（WI-1489） | WI-1464、1473、1474 |
| 能收就收，以最小單位降級 | 轉錄為片段，潤飾與翻譯為條目，摘要為單位 | WI-1463、1473、1474、1486 |
| 確定性的失敗不重試 | 重試只留給服務層失敗與空手而回；唯一例外是縮小範圍的未翻譯重試與帶懲罰的轉錄重試 | WI-1463、1475、1477、1465 |
| 每個請求都有上限 | chat 請求都帶生成上限；逾時另設；用戶端逾時不等於伺服器停止 | WI-1432、1434、1437、1461 |
| 檢查只留客觀可判定者 | 保留的內容檢查：含假名＝未翻譯、低資訊量；字形、語境重複、行數等易誤判的規則已放寬或移除 | WI-1471、1473 |
| 止損只看系統性失敗 | 服務層失敗逐次計；內容層失敗只在整個片段空手而回時計；轉錄與摘要的截斷不計 | WI-1453、1463、1475、1485、1487 |
| 保存資料、事後可查 | 降級原因、截斷旗標、原文（EXCHANGE）、第一次轉錄文字、HTML 報告 | WI-1478、1485、1487、1481 |
| 以量測而非假設調整 | 預填、懲罰、二次轉錄、生成上限都有對應量測；D1 判定因量測不佳而不採用 | WI-1451、1452、1483 |

## 4. 已走過、已放棄的做法

| 做法 | 放棄原因 | 出處 |
|---|---|---|
| 對半拆批重試 | 上限隨批縮小，必然再次失敗 | ADR-055 |
| 附違規原因重試 | 成功率 4%–7% | ADR-069（取消 WI-1468 的部分） |
| 逐項嚴格檢查加重試 | 浪費電與時間，檢查本身誤判 | ADR-069 |
| 簡體字集檢查 | 誤判；需求本身是「任何中文」 | ADR-067 |
| 角色表與譯名 | 影片無可辨識名字，模型常把描述當名字 | ADR-074 |
| 畫面核對階段 | 成本最大，價值已被潤飾取代 | ADR-053 |
| 雙 VAD 加權 | 雜音仍被涵蓋，降噪更有效 | ADR-045、ADR-046 |
| 用 LLM（d1）判定轉錄好壞 | 誤判約 29%，召回 0.25–0.38 | ADR-073 決策 8 |
| JSON 輸出約束 | 與預填並用回 400；thinking 開啟時無額外改善 | 量測報告、ADR-077 |

## 5. 已知限度與未驗證項目

- 證據多來自單一影片（run 38、run 43）與單一模型版本；其他影片與模型的外洩率、降級率未知。
- 預填依賴服務把預填當續寫；換服務或換模型須重新量測（ADR-077）。
- 二次轉錄預設開啟但沒有人工聽測；採用規則擋語言與低資訊量，不擋同語言的錯字（ADR-075）。
- 未翻譯條目重試的救回率未量測（ADR-070）。
- 低資訊量與書寫系統分類的門檻預設值需要更多樣本（ADR-062、ADR-075）。
- 轉錄品質延後到成品字幕核對（ADR-058）；換人標記已移除（ADR-083）。
- Whisper 系（transcriptions 端點）沒有生成上限，失控時伺服器端不一定停止（ADR-057）。
- 多個工作項的完成狀態註明「對真實 Lemonade 未驗證」或「驗收條件尚未由架構師逐條重跑」，細節以各工作項狀態欄為準。
- 本彙整未涵蓋 WI-1449／1450（字幕合併與分段預設，已被長片段取代）、WI-1469／1479／1480（測試速度）的細節，它們與模型行為無直接關係。
