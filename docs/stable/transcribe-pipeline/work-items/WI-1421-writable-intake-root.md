# WI-1421 收件根目錄改為可寫，文件與部署檔對齊

本文回答：為了讓 pipeline 把字幕寫在影片旁，部署與文件要改什麼。狀態：已核可（2026-10-12）。相依：WI-1420。儲存庫：runline（部署檔與文件）；實機驗證需 runline-transcribe 的 jar。

## 背景

見 [ADR-039](../adr/ADR-039-subtitle-files-beside-video.md)。目前 `04-deployment.md` 規定收件根目錄以唯讀掛載給 Engine。

## 行為與驗收條件

1. Docker 與 systemd 的部署檔把收件根目錄改為可寫（對 Engine 使用者），且只有收件根目錄可寫；其他掛載的唯讀性不變。
2. 文件對齊且各記一處：`docs/stable/transcribe-pipeline/01-requirements.md` 第 8、9 條（輸出含檔案、資料庫是完整紀錄）、`04-deployment.md`（收件根目錄可寫、權限與擁有者說明）、`runbook.md`（階段表第 12 階段、結果取回改為檔案、導出自資料庫保留為救援方式、失敗分類、`intake` 階段的可寫檢查與排錯）、`07-nfr-risks.md`（寫入範圍與緩解）、`06-data-model.md`（檔案是 `result` 的副本，不是新資料）。
3. 部署文件明列呼叫端的責任：以「新檔出現」觸發 webhook 的系統必須忽略 `.srt`。
4. 實機驗證：在含真實 Engine 的映像與主機覆蓋層上，對可寫與唯讀兩種掛載各跑一次：可寫時影片旁出現兩個檔，內容與資料庫一致；唯讀時 run 在 `intake` 就失敗並指出原因。環境不允許的部分明說未驗證。
5. 部署檢查腳本（若存在）加入「收件根目錄可寫」的檢查，錯誤訊息指出缺什麼。

## 架構約束

- 只改部署檔與文件，不改 Engine 程式碼與 pipeline 程式碼。
- 同一資訊只寫一處，其他處以連結引用；文件用現在式、宣告式。
- 修改 stable 文件的內容須與核可的 ADR-039 一致，不引入其他行為。
