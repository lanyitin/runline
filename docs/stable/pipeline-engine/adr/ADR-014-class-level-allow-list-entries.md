# ADR-014 白名單條目可為套件或完整類別

狀態：已核可（2026-10-05）。修訂 [ADR-002](ADR-002-context-and-unsafe.md) 的白名單規則，與 [ADR-013](ADR-013-io-sensitive-members.md) 搭配。回答：白名單如何只放行一個類別，而不放行整個套件。

## 背景

ADR-002 的白名單只在套件層級運作。預設白名單依 ADR-013 不含提供檔案與網路 IO 的套件（`java.io` 等）。但 Kotlin 的標準輸出函式（例如印出文字）是 inline-only，編譯後內嵌為對標準輸出串流類別的參照，該類別位於 `java.io`。結果是：任何印出文字的 pipeline 在預設下都是 unsafe，雖然標準輸出由 Runner 攔截並歸屬到 run，是被預期的用法（[07](../07-nfr-risks.md)）。

可選做法：

| 選項 | 結論 |
|---|---|
| 預設白名單放行整個 `java.io` | 否決。`java.io` 含大量檔案操作，需要龐大且易出錯的成員清單來補足，與 ADR-013 的預設原則衝突 |
| 在 context 提供輸出能力 | 暫不採用。方向合理，但要變更 core 的契約，範圍大 |
| 白名單條目可為完整類別名稱 | 採用。只放行需要的類別，並以成員層級規則擋住該類別中提供 IO 的成員 |

## 決策

- 白名單條目可以是套件名稱，或完整類別名稱。
  - 套件條目的規則不變：套件與其子套件受信任（可標記「僅此套件」排除子套件）。
  - 類別條目只放行該類別本身：其他同套件的類別不受影響，也不放行其子套件。類別的巢狀類別視為該類別的一部分，隨之放行。
- 判定一個節點是否在白名單內時，節點的類別若符合任一類別條目，或其所屬套件符合任一套件條目，即在白名單內。受信任節點不再向下展開（ADR-002）。
- 類別條目放行的是類別，不是類別內所有成員：ADR-011 與 ADR-013 的成員層級規則不受豁免。被放行類別中提供 IO 的成員（例如該類別以檔名開啟檔案的建構）仍判違規。
- 條目的種類由其內容辨識：含套件分隔且對應到實際類別名稱的完整名稱為類別條目，其餘為套件條目；驗證時管理員須明示條目為套件或類別，避免歧義。
- 白名單的版本、變更者與重判規則（ADR-002、[WI-10](../work-items/WI-10-allowlist-admin.md)）不變，類別條目與套件條目共用同一份版本化的白名單。
- 預設白名單可包含類別條目：預設內容依 ADR-013 的原則，另加入標準輸出所需的最少類別（標準輸出串流類別與主控台輸入的類別）。具體類別由實作評估後回報，經架構決定後定案。

## 取捨

| 項目 | 優點 | 缺點 |
|---|---|---|
| 類別層級條目 | 精確放行，不擴大到整個套件；預設白名單不含 `java.io` 套件也能使印出文字的 pipeline 為 safe | 白名單模型多一種條目；管理員需理解兩種條目；類別被放行後其內部不被檢查，需依賴成員層級規則擋住 IO 成員 |
| 成員層級規則不受豁免 | 放行類別不等於放行其 IO 能力 | 需要維護成員清單 |

## 後果

- 白名單模型（analyzer）、Engine 的白名單 API 與組態、devkit 的白名單解析都需支援兩種條目（[WI-24](../work-items/WI-24-class-level-allow-list.md)）。
- 既有的僅含套件條目的白名單行為不變。
- 環境變數與 API 的條目格式需能表達類別條目；統一格式見 [WI-10](../work-items/WI-10-allowlist-admin.md) 的待確認問題。
- 需要放行更多類別時，管理員新增類別條目；是否為合適的信任決定，仍由管理員承擔（ADR-002）。
