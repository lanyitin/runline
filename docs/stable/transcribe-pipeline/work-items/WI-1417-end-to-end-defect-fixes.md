# WI-1417 端到端驗證發現的缺陷修正（runline-transcribe）

狀態：已核可（2026-10-12），未開始。儲存庫：T。相依：WI-1413。本文回答：WI-1413 端到端驗證發現的 pipeline 缺陷要達成什麼行為。

## 驗收條件

1. **最後一格畫面**：核對階段的取樣時間不得落在影片最後一格之後；語音延伸到檔案結尾的最後一個條目也能取得畫面，不因此降級。以真實 ffmpeg 產生的、語音到結尾的樣本驗證。
2. **工作目錄設定**：pipeline 讀取環境變數 `TRANSCRIBE_WORK_DIR`（04 的定義）作為工作目錄的上層；未設定時用系統暫存區。設定了但不存在、不是目錄或不可寫時，run 在初始階段失敗並指出該變數，訊息不含路徑。工作目錄的清理（失去擁有者者）、取消與結束時刪除，都作用於實際使用的目錄。README 說明，`deploy/` 的檢查腳本與 drop-in 所檢查的目錄即實際使用的目錄（如需調整 `deploy/`，列入回報，不在此項修改 runline 儲存庫）。
3. **設定類錯誤快速失敗**（05 的設定類錯誤規則）：
   1. 第一個使用對話模型的階段開始前，若資源可列出模型，確認 `llmModel` 與已設的 `polishModel`、`verifyModel`、`translateModel` 在清單內（模型身分的比對沿用 ADR-028 的規則）；不在清單內時 run 以 CONFIGURATION 失敗，訊息指出參數名稱，不指出清單內容。清單取不到（不支援、逾時、被拒）時略過並記錄。
   2. 對話階段收到設定類錯誤（401、403、404、模型不被允許、端點未啟用）時，run 立即以 CONFIGURATION 失敗，不重試、不逐組降級；5xx、回答格式與契約違反仍依原規則重試與降級。
   3. 轉錄階段與對話階段的設定類錯誤處理一致。
4. **VAD 暫存目錄**：每次呼叫 VAD 工具不再在暫存區遺留空的 `onnxruntime-java*` 目錄（工具或呼叫端負責清理，擇一，並以測試驗證）。
5. **媒體失敗的原因**：因媒體問題失敗時，run 結果行（OUTCOME）的原因分類顯示具體原因（無音訊、損毀、超過長度上限、工具缺少、工具失敗、逾時），不只顯示例外類別。
6. 以上每項有先看到紅燈的測試；既有測試通過；README 與（若有）`ParameterDocumentationTest` 一致；完整測試與 `ktfmtCheck` 通過。

## 架構約束

沿用既有階段、重試與降級機制，不改變條目時間與數量的不變式；pipeline 只用 JDK、core、Kotlin 標準函式庫。
