# WI-70 engine 組態依功能歸屬

本文回答：engine 的組態讀取與驗證如何歸屬到各功能，如何驗收。狀態：提案中（2026-10-30）。相依：WI-65。決策見 [ADR-023](../adr/ADR-023-engine-feature-slices.md) 第 1、2 點。

## 背景

組態集中在單一解析處，直接建出各功能的型別，使組態成為所有功能的匯合點（[02](../02-current-state.md) 發現二）。

## 行為與驗收條件

- 每個功能擁有自己的組態段：該功能的環境變數讀取、預設值、範圍檢查與彼此關係的檢查位於該功能內。跨功能的檢查（例如資源根目錄、共享目錄、run 目錄、金鑰庫路徑不得互相包含）由入口層組合，或由擁有該設定的功能提供判斷。
- 組態基礎（讀取環境變數、列出缺少的必要鍵、統一的錯誤彙整）屬共用層，不依賴任何功能。
- 啟動時的行為完全不變：同一組環境變數得到相同的成功或失敗；缺少必要鍵時仍一次列出全部缺少的鍵，訊息文字與順序不變；每一個現行的組態錯誤情境（[README](../../../../README.md) 與 [04](../../../stable/pipeline-engine/04-deployment.md) 所列）都有測試覆蓋，回報中列出對照。
- 依賴方向檢查（WI-65）通過，且組態基礎不依賴功能的規則被檢查涵蓋。
- 符合[總覽全域約束](README.md#全域約束適用本總覽所有項目)的全部條件。

## 架構約束

- 組態鍵、預設值、下限與上限、必要與選填的區分一律不變（12-Factor：組態仍只來自環境）。
- 不引入組態檔格式或新的組態來源。
