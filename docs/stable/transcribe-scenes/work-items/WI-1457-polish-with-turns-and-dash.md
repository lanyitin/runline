# WI-1457 潤飾附畫面與換人資料，SRT 依參數畫破折號，刪除核對

本文回答：潤飾如何以場景片段加畫面修正文字並標出換人，輸出如何畫出破折號，核對階段如何移除。狀態：已核可（2026-10-14）。相依：WI-1456。決策見 [ADR-053](../adr/ADR-053-polish-with-frames-and-speaker-turns.md)。儲存庫：T。

## 行為與驗收條件

1. **請求**：每個有條目的場景片段一次請求，附：
   - 該片段的條目；
   - 每秒一張畫面（至多 `framesPerSegment` 張，長邊 `frameMaxEdgePixels`，只在記憶體）；
   - 前一片段潤飾後的文字作為唯讀語境。
2. **回答契約**：
   - 條目數、序號、時間不變；
   - 每條至多兩行，行首的破折號表示新說話者的開頭；
   - 語境內容不得出現在回答中。

   違反者重試，重試用盡則該片段保留轉錄文字、不標換人，計入降級。
3. **換人資料**：解析後存成 ENTRY_LINE（潤飾階段）：每行的文字（不含破折號）與是否為新說話者的開頭。
4. **輸出**：參數 `subtitleDialogueDash`（預設開啟）開啟時，標記為新說話者開頭的行在行首加對話破折號，規則見 ADR-053 決策 3；關閉時不加，其他內容逐位元組相同。來源語言 SRT 在本項完成時即套用；中文 SRT 在 WI-1459 完成前沿用來源語言的換人資料。
5. **請求過大**：縮小圖片邊長後重送（沿用現行的縮圖機制，不算模型嘗試）。
6. **預設 prompt**：潤飾的 system prompt 預設值改寫，含以下規則，並保留「條目數、序號、時間不變」：
   - 只在確定時修正；
   - 不以發音不同的詞替換；
   - 以行首破折號標出換人；
   - 每條至多兩行。

   `polishSystemPrompt` 仍可覆寫。
7. **刪除核對**：核對階段與其參數移除；舊 run 的核對資料照常可查；參數宣告中不再出現核對的參數。
8. **紀錄**：log 的結果行列出片段數、送出數、降級數、換人標記數。

## 架構約束

- 不改條目的數量與時間；換人是資料，不寫死在文字裡。
- 兩份 SRT 由同一個函式依同一份條目與換人資料畫出。
- thinking 預設關閉，開啟時依 WI-1453 的政策。
- 嚴格 TDD；測試不使用 Stub 或 Mock（模型服務使用既有的假服務）。
