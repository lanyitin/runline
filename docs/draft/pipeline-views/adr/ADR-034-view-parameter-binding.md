# ADR-034 View 的參數以具名佔位符綁定

狀態：提案中（2026-10-11），取代 `docs/stable/pipeline-views/adr/ADR-034-view-parameter-binding.md`；與 stable 的差異只有「決策」新增的「上傳時的方言」與「佔位符的名稱」兩段，以及「取捨」多一項；內容反映已實作並驗收的 WI-1304。補充 [ADR-033](../../../stable/pipeline-views/adr/ADR-033-pipeline-views.md)「宣告」一節；取代 [WI-1301](../../../stable/pipeline-views/work-items/WI-1301-view-api.md) 實作中採用的「位置綁定」（該行為是實作選擇，stable 文件未規定，故無衝突）。回答：view 查詢文字如何引用宣告的參數，以及何時檢查。

## 背景

ADR-033 規定參數值只作為查詢參數傳遞，沒有規定查詢文字如何引用它們。WI-1301 的實作以位置綁定：查詢中的每個參數標記依宣告順序對應一個參數，同一參數不能用兩次，數量不符到讀取時才報錯，上傳驗證（WI-1300）不檢查。尚無已上線的 view 使用此行為（digest-rss 的 view 尚未撰寫）。

## 選項

| 選項 | 優點 | 缺點 | 結論 |
|---|---|---|---|
| A. 位置綁定（現況） | 已實作；與 JDBC 一致 | 作者要自行對齊順序；同一參數不能重複使用（篩選條件常需要）；錯誤到讀取時才發現 | 否決 |
| B. 具名佔位符：查詢文字以「冒號加參數名稱」引用，Engine 解析後轉成位置綁定 | 可讀；可重複使用；上傳時即可檢查；Engine 已有辨識字串、註解、引號的詞法分析器 | 需擴充詞法分析器；須避開 PostgreSQL 的型別轉換記號 | 採用 |
| C. Engine 把值代換進查詢文字 | 實作簡單 | 注入風險，違反 ADR-033 | 否決 |

## 決策

- 查詢文字以具名佔位符引用參數；同一參數可出現多次，每次都綁定同一個值。
- Engine 只在字串、識別符、註解、錢字號引號之外辨識佔位符；PostgreSQL 的型別轉換記號與陣列切片的冒號不是佔位符。
- 查詢文字不得再使用位置參數標記；使用者值仍只以綁定值傳遞，不拼接進查詢文字。
- 上傳時驗證（屬於 view 宣告驗證）：每個佔位符都對應一個已宣告的參數；每個已宣告的參數至少被引用一次；查詢中有位置參數標記為錯誤。錯誤指出 view 與問題，一次列出全部。
- 選填參數未提供時綁定為空值，行為不變。

**上傳時的方言。** 上傳時還不知道該資源角色會綁到哪一種資料庫，所以查詢文字以 PostgreSQL 與 SQLite 兩種語法各解析一次：

- 任一種語法解析出某個名稱，該名稱即視為已被引用；任一種語法解析出位置參數標記，即拒絕。
- 兩種語法都無法解析完的文字（例如引號未結束）上傳時略過，留到讀取時以 `view_query_rejected` 回報。
- 讀取時依實際綁定的資料庫種類解析，不再混用。

**佔位符的名稱。** 名稱以字母或底線開頭，後接字母、數字或底線，區分大小寫。其他字元的參數名稱無法被引用，因此會被報為「未被引用」。`@名稱`、`$名稱`、`?數字` 與 `$數字` 不是佔位符，讀取時被拒絕。

## 取捨

- 得到：作者不必對齊順序，篩選條件可重用，宣告錯誤在上傳時而非讀取時暴露。
- 失去：詞法分析器的維護面擴大；佔位符的辨識規則成為對作者的契約，須在文件中固定；PostgreSQL 的 `?` 運算子因被視為位置標記而不能用在 view 查詢中；兩種語法解析結果不同的查詢，上傳時的判斷較寬鬆，部分錯誤到讀取時才暴露。
