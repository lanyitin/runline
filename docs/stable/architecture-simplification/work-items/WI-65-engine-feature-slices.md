# WI-65 engine 功能切片與依賴方向檢查

本文回答：engine 內部要達成什麼樣的組織與依賴方向，如何驗收。狀態：已核可（2026-10-30）。相依：WI-51（從全綠且無遺留的基線開始）。決策見 [ADR-023](../adr/ADR-023-engine-feature-slices.md)。

## 背景

engine 的功能套件之間有 5 組循環依賴，路由集中在根套件，組裝集中在一處（[02](../02-current-state.md) 發現二）。

## 行為與驗收條件

**功能切片**
- 每個功能（artifact、allowlist、run、trigger、resource、secret、retention、health、info、console）的 HTTP 路由位於該功能自己的套件內；engine 根套件只剩行程入口、啟動與關閉流程、組裝。
- 共用層（API 共用型別如錯誤回應與身分、認證與授權、資料庫連線與遷移、可觀測基礎）不依賴任何功能套件。

**依賴方向**
- 功能之間的依賴完全符合 ADR-023 的方向表；功能之間沒有循環；功能不依賴入口層。
- 「哪些資源使用某機密別名」等反向需求由上游功能提供查詢或由入口層組合，回應內容與現況相同。

**自動檢查**
- `check` 包含依賴方向檢查，涵蓋：ADR-023 的功能方向表與三層規則、Gradle 模組之間的允許方向（core 不依賴任何專案模組；accessors 只依賴 core 與 runner；analyzer 此時仍不依賴任何專案模組，WI-69 再放寬為只依賴 core）。
- 違規時建置失敗，訊息指出違規的來源與目標（套件或模組）。以一個刻意違規的暫時變更確認檢查會失敗，回報中附上失敗訊息，該變更不得提交。
- 規則的內容與 ADR-023 方向表一一對應，回報中列出對照。

**行為不變**
- 符合[總覽全域約束](README.md#全域約束適用本總覽所有項目)的全部條件。

## 架構約束

- 不拆分 engine 為多個 Gradle 模組（[03](../03-options.md) 選項 C 否決）。
- 不新增外部相依；若依賴檢查需要第三方工具，先回報可行選項與代價，由架構師與使用者決定。
- 不改變組態的解析方式（屬 [WI-70](WI-70-engine-config-per-feature.md)），也不改變資源型別的歸屬（屬 [WI-66](WI-66-resource-type-ownership-engine.md)）；本項只搬到正確的套件並修正方向。
