# WI-42 金鑰庫的部署掛載與維運手冊

本文回答：金鑰庫與其密碼如何在 Docker 與 systemd 部署中提供，以及維運如何新增、更新、刪除機密並讓 Engine 重載。狀態：已核可（2026-10-06）。相依：WI-39、WI-41。決策見 [ADR-019](../adr/ADR-019-typed-shared-resources.md) 第 6 點「部署掛載」。

## 背景

WI-41 完成 Engine 側機制與前置驗證。本項把掛載方式與維運步驟落入 `deploy/` 與部署文件，並與兩份平台指南一致。

## 行為與驗收條件

**Docker**
- Compose 範例以唯讀方式掛入金鑰庫檔案，並以 Docker secret 提供密碼檔；Engine 的組態指向它們。映像內不含金鑰庫與密碼；範例使用佔位值，版本庫不含真實機密或真實金鑰庫。
- 以真實 Docker 驗證：掛入測試用金鑰庫後 Engine 啟動成功、`GET /api/v1/secrets` 列出別名；密碼錯誤時 Engine 啟動失敗（結束代碼非 0、原因不含密碼）；容器內金鑰庫為唯讀；映像各層與容器環境變數檢視中找不到金鑰庫密碼。

**systemd**
- 單元與環境檔範例：金鑰庫放在僅服務帳號可讀的組態位置；密碼以 systemd 的憑證機制或僅服務帳號可讀的環境檔提供；說明權限設定。
- 驗證方式同 [WI-39](WI-39-deployment-files.md)：可用時以 `systemd-analyze verify` 靜態檢查，並在可執行 systemd 的環境實測一次載入金鑰庫與密碼錯誤的失敗；兩者都無法執行時回報並由使用者決定，不得宣稱已驗證。

**維運手冊**（併入 04 的平台指南或 `deploy/` 的 README，由實作時擇一並在總覽連結）
- 依 WI-41 前置驗證的實測結果（[ADR-019](../adr/ADR-019-typed-shared-resources.md) 第 6 點）逐步說明：建立金鑰庫、新增、刪除、列出別名；更新機密的流程固定為：複製金鑰庫檔案、在副本上先刪除別名再重新匯入、以原子替換（更名覆蓋）取代原檔、呼叫重載端點並檢視結果。
- 所有金鑰庫工具指令以密碼檔參數提供金鑰庫密碼，不把密碼放在命令列或標準輸入的回顯上，避免密碼出現在命令列與行程清單；手冊明列此為要求而非建議。
- 機密字元集警告：機密限可列印 ASCII；非 ASCII 字元會被工具的密碼編碼破壞且無法還原，且損毀無法在載入時全部偵測，會在連線時呈現為認證失敗。更新或新增機密後，先以資源的「檢查」驗證再依賴它。此限制只針對機密項目，不適用於憑證與私鑰。
- 選用（不阻擋）：調高金鑰庫的 PBE 迭代次數以提高離線破解成本；須實測所用的屬性與對讀取端的影響後才寫入手冊。
- 憑證操作（決策 12；Engine 側行為由 [WI-52](WI-52-tls-trust-and-mtls.md) 驗證）：匯入內部 CA 或自簽伺服器憑證為受信任憑證項目；匯入含私鑰與憑證鏈的 PKCS12，或把 PEM 的私鑰與憑證鏈先轉成 PKCS12 再匯入；列出項目類型、主旨、到期日與指紋；到期前的更換流程同機密（複製、改副本、原子替換、重載）。私鑰的保護密碼與金鑰庫密碼相同，須實測確認並說明。
- 金鑰庫密碼輪替（更新密碼來源並重啟）；金鑰庫與密碼分開備份與還原，沒有金鑰庫時還原資料庫的現象（引用別名的資源檢查回報 `missing`）。
- 手冊中的每個指令都實際執行過，預期輸出與實測一致；範例機密為佔位值。
- 說明限度：機密在 Engine 記憶體以明文存在；環境變數提供密碼時 unsafe pipeline 可讀取，建議機密檔。

**一致性**
- `deploy/` 內的設定與 04-deployment-docker.md、04-deployment-systemd.md 一致；有差異時以文件為準並修正檔案（或回報需要修訂文件）。

## 架構約束

- 只新增或修改 `deploy/` 與部署文件；不修改應用程式碼（需要時回報，由 WI-41 處理）。
- 不納入任何真實機密；不新增 CI。
- 測試使用真實 Docker，不使用 Stub 或 Mock。
