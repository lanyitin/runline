# WI-81 Console favicon 跟隨系統主題

本文回答：Console 的網站圖示如何跟隨系統的深色或淺色偏好，以及驗收條件。狀態：提案中（Issue #81）。相依：無（[WI-71](../../../stable/console-dark-mode/work-items/WI-71-console-dark-mode.md) 已完成）。決策見 [ADR-70](../../../stable/console-dark-mode/adr/ADR-70-console-dark-mode.md)（只跟隨系統）；總覽見[工作項總覽](../../../stable/console-dark-mode/work-items/README.md)。

## 背景

favicon 是單一 SVG 檔，以固定的藍色圓角方塊和白色提示符號組成，顏色寫死，沒有跟著主題。WI-71 的範圍是頁面內的 token，不含這個檔案；WI-71 的「元件不自訂顏色」檢查只涵蓋 `console/src`，不涵蓋它。

## 與 stable 的關係

不衝突。ADR-70 第 1 點（只跟隨系統、不加開關）同樣適用於 favicon，本項是它在這個檔案上的補完，不修訂任何 stable 決策。

## 行為與驗收條件

- 系統偏好深色時，favicon 使用與深色主題一致的配色（較亮的藍色底，符號對比足夠）；偏好淺色時外觀與現在相同。
- 圖示的底色與符號色對比至少 3:1，兩種主題各一組，由自動化檢查涵蓋。
- 切換由圖示自身依系統偏好決定，不需要頁面程式碼、不需要重新載入頁面，也不新增第二個檔案或開關。
- 不支援在圖示內依偏好切換的瀏覽器維持現在的外觀（即淺色版本）；這是可接受的降級，不視為缺陷。
- 配色與 Console 的深色與淺色 token 中的強調色保持一致；因為圖示是獨立檔案，無法引用 token，所以以測試檢查圖示的兩組顏色與對應 token 的值一致，日後 token 改變時測試失敗。
- 真實瀏覽器 e2e 在模擬深色與淺色偏好下，確認頁面實際引用的圖示在兩種偏好下的顏色與預期一致。
- 沒有新的 API、設定、儲存或後端改動。

## 架構約束

- 圖示維持單一 SVG 檔，不載入第三方資源，不由後端動態產生。
- 具體色值由實作決定，只要與強調色 token 一致並通過對比度檢查。
- 既有 Console 單元測試與 e2e 全部通過，不得放寬斷言。
- 測試不使用 Stub 或 Mock；嚴格 TDD；專案沒有 CI，驗證皆可在本機完成。
