# WI-1004 資料紀錄基礎

目標：pipeline 有一個寫入資料庫的紀錄基礎，後續各項只需往裡面記。資料內容與關聯見 [06](../06-data-model.md)。工作儲存庫：`runline-digest-rss`。

## 驗收條件

1. run 開始時建立或升級結構：前向、冪等、記錄結構版本；資料庫的結構版本比 pipeline 新時拒絕寫入並說明。
2. run 開始時建立 RUN 紀錄（參數、pipeline 版本、規則版本），結束時補完（結果、計數、請求與實際回應的模型）。
3. 每個階段寫入 STAGE（起迄、耗時、結果句），內容與 run log 一致。
4. 上一次 run 崩潰而未完成的 RUN，於下一次 run 開始時標記為中斷。
5. 保留清除：依參數天數清除體積大的原始資料（頁面文字、封面影像、模型對話），保留摘要欄位與雜湊；清除失敗不使 run 失敗。
6. 寫入失敗的處置：階段紀錄失敗不中止 run，但涉及標已讀的紀錄失敗時不標記。
7. 資料庫是 pipeline 唯一的寫入去向：驗收時確認 pipeline 沒有任何檔案寫入（Chrome 自己的暫存除外）。
8. 以真實 SQLite（經 WI-1003 的資源）驗證；彙整查詢「某次 run 抓到哪些文章」可由紀錄回答。

## 架構約束

- 不洩漏機密；不存 token。
- 不為後續項目預設內部設計；各項把自己的紀錄接進這個基礎。
