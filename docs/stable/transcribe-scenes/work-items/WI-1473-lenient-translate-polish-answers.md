# WI-1473 翻譯與潤飾的回答依序號寬鬆解析，換人標記由 pipeline 補回

本文回答：翻譯與潤飾如何從不守格式的回答中取得可用的條目。狀態：已核可（2026-10-15）。相依：WI-1468、WI-1471、WI-1472（都已完成）。決策見 [ADR-069](../adr/ADR-069-accept-what-can-be-used.md)。儲存庫：T。

## 行為與驗收條件

1. **依序號解析**：翻譯與潤飾的回答依序號取出各條目的文字；序號區塊之外的內容（問候、註解、自言自語、重複的原文、程式碼框、`<think>` 殼）忽略；重複的序號取第一個；不在本片段的序號忽略。不再有 `NOT_SRT`、`COUNT_CHANGED`、`NUMBER_CHANGED`、`CONTEXT_RETURNED`、`TOO_MANY_LINES`、`LINES_CHANGED`、`SPEAKER_CHANGED` 這些使整個片段作廢的原因。
2. **條目層級降級**：回答中取不到的條目、文字為空的條目，保留上一階段文字並計入降級（原因為缺少或空白）；其餘採用。超過兩行的條目，把多出的行併入第二行。
3. **翻譯的換人標記由 pipeline 補回**：回答每一行行首的 `-`、`->`、全形與其他橫線符號與其後的空白一律剝除；標記依來源資料畫出：譯文兩行且來源兩行各有標記時各畫一個；譯文一行時，來源任一行有標記就畫在這一行；其餘依來源的第一行標記。翻譯請求仍保留來源的 `- `（有助於理解），提示詞說明它是換人記號、不必寫在譯文中。
4. **潤飾的換人標記**：標記由模型決定，位置不符時直接採用模型給的，不檢查、不作廢。
5. **未翻譯**：翻譯回答的行含假名時，該條目保留潤飾文字並計入降級，原因為 `UNTRANSLATED`，不觸發整個片段重試（ADR-069 決策 5）。其餘品質檢查一律取消。
6. **截斷**：回答被截斷時，截斷前已完整的條目採用，其餘降級；不重試（見 WI-1475）。
7. **譯名行**：回答中的 `NAMES:` 區塊容忍任何格式，不符 `- <名字> | <中文名>` 的行忽略；只有角色表中「有名字且尚無譯名」的角色採用譯名。
8. **紀錄**：結果行與 RUN SUMMARY 列出條目層級的降級數與原因（缺少、空白、未翻譯），取代片段層級的契約違反計數；README 的驗證表、重試章節、提示詞引文與文件測試同步。預設提示詞改寫：不再要求保留 `- `、不要求條目行數相同，只要求每個序號一段譯文。
9. **重現情境**（假服務與真實資料庫，可由既有的失敗型態設計）：
   - 回答在條目前加了 `- `：標記依來源補回，來源沒有標記的條目不出現標記；
   - 回答把每條寫成「原文換行 `->` 譯文」：取譯文，不含原文與 `->`，或判為未翻譯（若取到的只有原文）；
   - 回答先抄整段原文再接譯文：依序號取第一個，若為原文則判為未翻譯；
   - 回答夾英文註解與 `<think>` 殼：忽略；
   - 回答只回部分條目：其餘條目降級，不重試；
   - 回答被截斷：已完整的條目採用；
   - 兩人條目被翻成一行：標記畫在這一行。
10. 其餘行為（條目、時間、換人資料來源、續跑、view）不變。

## 架構約束

- 不改 Engine；不新增參數；不改 schema。
- 嚴格 TDD；測試不使用 Stub 或 Mock。
- 測試範圍依 tdd-coder 定義的 §1.1，不跑全套。
- 與 WI-1474、WI-1475 都改答案解析與重試；序列執行（建議 WI-1473 先）或各自用獨立的 worktree 與分支。
- 回報時列出測試範圍與結果、被移除的失敗原因清單、jar 路徑與 sha256、提交。
