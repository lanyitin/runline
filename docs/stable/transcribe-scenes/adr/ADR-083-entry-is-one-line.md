# ADR-083 條目是一行文字：潤飾與翻譯不標換人、不分行，SRT 不畫對話破折號

本文回答：潤飾與翻譯後的條目文字是什麼形狀，換人與對話破折號是否保留。狀態：已核可（2026-10-18）。取代 [ADR-053](ADR-053-polish-with-frames-and-speaker-turns.md) 決策 1 中「分成至多兩行」與「標出換人」兩項、決策 2 至 4，以及決策 5 中「不標換人」的說法；取代 [ADR-054](ADR-054-scene-summaries-and-translation-context.md) 決策 6 中「條目含行與換人標記」與「回答須保持行數與換人標記不變」；取代 [ADR-064](ADR-064-answer-contract-violations-are-per-segment.md) 決策 2 與 [ADR-069](ADR-069-accept-what-can-be-used.md) 決策 2 中「超過兩行併入第二行」、決策 4；修訂 [ADR-071](ADR-071-html-run-report.md) 決策 5 中「換人標記照 `subtitleDialogueDash` 的呈現方式」。轉錄的分行（組成條目時至多兩行）不變。

## 背景

- ADR-053 讓潤飾以行首破折號標出新說話者，pipeline 存成換人標記，輸出 SRT 時依 `subtitleDialogueDash` 畫出對話破折號；翻譯須保留行數與換人標記，使兩份 SRT 的換人位置一致。
- **換人標記不準**：換人是小模型依文字與畫面的推斷。run 26 至 28 的失敗原因中，換人標記不符占 34%（[ADR-069](ADR-069-accept-what-can-be-used.md)）；ADR-069 放寬檢查後，潤飾的標記「位置不符時直接採用模型給的」，錯誤的標記會照樣畫成破折號，讓讀者以為換了人。
- **提示與解析因此變複雜**：潤飾提示有分行與換人的兩條規則；解析要剝除行首符號、區分破折號與箭頭（`->` 曾被當成換人）、把超過兩行的併入第二行；翻譯提示要說明 `- ` 是記號而不是譯文，回答的標記一律剝除後再依來源補回（來源兩個標記、譯文一行或兩行時各有規則）。
- **翻譯沿用來源標記的負擔**：為了兩份 SRT 換人位置一致，翻譯要依來源補畫標記、續跑要搬移行與標記、報告要以同一個函式畫破折號；這些都只為維持一項不可靠的資料。

## 決策

1. **潤飾不分行、不標換人**：潤飾提示不談分行、換人與對話破折號；每個條目的文字是一行。不可新增、刪除、合併、拆分、重排條目，不可改時間（不變）。
2. **翻譯也是一行**：送給翻譯的條目只有序號與文字，不帶換人記號；提示要求每個條目的譯文寫成一行。摘要與語境只用來理解發生的事（不再提「誰在說話」）。
3. **回答的解析**：同一序號底下若有多行，以空格接成一行，空行略過；行首的 `-`、`—` 等破折號當作一般字元保留，不解析、不補回。降級而保留上一階段文字的條目，其行同樣以空格接成一行。
4. **紀錄**：潤飾與翻譯的每個條目只寫第 1 行，換人標記不寫入（維持預設值 0）。轉錄的行（1 或 2 行）不變。schema 不變；舊 run 的兩行與換人標記保留、可查。
5. **輸出不畫破折號**：兩份 SRT 與 HTML 報告都不畫對話破折號，過長的一行由播放器自動換行。參數 `subtitleDialogueDash` 移除；送入時與其他未宣告的參數一樣被拒絕。
6. **觀測與量測**：條目 view 不再有換人欄（舊 run 的標記不顯示）；潤飾的階段結果不再有 `turns` 計數；可行性量測的換人正確率與人工判定表移除（圖片數的建議改由使用者依成本決定）。
7. **續跑**：沿用的潤飾與翻譯文字，不論是起點之前取用的或起點階段沿用的，都以一個條目一行寫進新 run（來源有多行時以空格接成一行），來源的換人標記不沿用；兩份 SRT 依這些文字重新做出，不帶來源 run 的破折號。來源 run 的資料不變。

## 取捨

- 得到：
  - 讀者不再被錯誤的破折號誤導；
  - 潤飾與翻譯的提示少了分行與換人的規則，模型專注在文字本身；
  - 解析不必處理行首符號、行數與標記補回，續跑與報告不必搬移或重畫標記。
- 失去：
  - 字幕看不出是對話還是獨白（ADR-053 的目標放棄）；
  - 分行交給播放器，斷在哪裡不再由語意決定；
  - 舊 run 的換人標記仍在紀錄中，但沒有任何輸出或 view 使用它。

## 後果

- 入口文件的目標「字幕看得出是對話還是獨白」移除；範圍外「說話者辨識」回到不做換人（不做聲紋辨識、不標出是誰、也不標出換人）。
