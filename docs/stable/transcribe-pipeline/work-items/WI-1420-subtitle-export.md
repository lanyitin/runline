# WI-1420 字幕檔輸出階段

本文回答：pipeline 最後如何把兩份字幕寫成影片旁邊的檔案，以及如何驗收。狀態：已核可（2026-10-12）。相依：WI-1412（已完成）、WI-1417（已完成）。儲存庫：runline-transcribe。

## 背景

見 [ADR-039](../adr/ADR-039-subtitle-files-beside-video.md)。

## 行為與驗收條件

1. 新增第 12 階段 `export`：`translate` 完成後，把來源語言與繁體中文字幕寫到影片所在目錄。檔名為「影片檔名去掉最後一個副檔名_語系.srt」；`movie.mp4` 得 `movie_<來源語系>.srt` 與 `movie_zh-TW.srt`，`a.b.mp4` 得 `a.b_<來源語系>.srt`。
2. 來源語系取自摘要階段的語言碼，正規化為小寫主語言碼（兩到三個英文字母；`en-US` 得 `en`，`ZH-Hant` 得 `zh`）；缺少（摘要降級）、空白或無法辨識為 `und`。繁體中文固定 `zh-TW`。來源為中文時兩個檔名不同。
3. 檔案內容與 `result` 的對應 SRT 文字逐位元組相同，UTF-8、無 BOM；以讀回檔案與資料庫比對驗證。
4. 寫入前提早檢查：`intake` 階段就確認影片所在目錄可寫，且兩個目標路徑可用（不存在，或是一般檔案；是目錄或符號連結即失敗）。不可寫時 run 在 `intake` 就失敗並指出原因，不等到轉錄之後。
5. 寫入範圍：影片所在目錄解析後（含符號連結）必須在收件根目錄內；輸出檔名只由規則 1、2 組成；以含 `..`、符號連結逃出收件根目錄、檔名含特殊字元的案例驗證，皆不得在根目錄之外寫入。
6. 原子與全有或全無：先寫同目錄暫存檔再換名；已存在的同名一般檔案被覆蓋；第二個換名失敗時移除第一個剛寫的檔；任何時刻目標路徑上不出現半成品。以在寫入中途注入失敗的案例驗證，並確認暫存檔不遺留。
7. 失敗語意：寫出失敗使 run 失敗，原因為專用分類（與既有分類並列），訊息不含收件根目錄的絕對路徑；`result` 已保存。降級的 run 照常寫出；取消、逾時或失敗於 `export` 之前，不寫任何檔案。
8. `export` 納入階段紀錄與 log（計數：寫出檔數），其計數方式比照其他階段。
9. README 與 runbook 相關小節（階段表、結果取回、失敗分類、排錯）寫成最新規則；runbook 位於 runline 儲存庫，需要改動的項目回報，由 WI-1421 處理。

## 架構約束

- 資料庫仍是完整紀錄，檔案是副本；不得因檔案存在與否改變其他階段的行為。
- 不新增參數（語系規則與命名固定）；不引入 `export` 以外的寫入位置。
- 薄 jar 約束不變（只用 JDK、core 與 Kotlin 標準函式庫）。
- 測試不使用 Stub 或 Mock；用真實檔案系統（暫存目錄）與真實 SQLite；嚴格 TDD。
