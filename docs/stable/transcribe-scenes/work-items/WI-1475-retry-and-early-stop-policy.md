# WI-1475 重試只留給服務錯誤與空手而回，及早止損以片段計數，角色表不為描述編譯名

本文回答：模型呼叫何時重試、何時止損，以及角色表怎樣才算有名字。狀態：已核可（2026-10-15）。相依：WI-1468（已完成），建議在 WI-1473、WI-1474 之後。決策見 [ADR-069](../adr/ADR-069-accept-what-can-be-used.md)。儲存庫：T。

## 行為與驗收條件

1. **重試的條件**：潤飾、摘要、翻譯的呼叫，只在下列情況重試：服務層失敗（逾時、5xx、連線、速率限制），或整個回答取不到任何條目（翻譯、潤飾）或任何標記內容（摘要）。其他情況（部分條目缺少、未翻譯、格式不符、被截斷）不重試。
2. **重試次數**：`modelRetries` 的語意為「每片段的重試次數」，預設由 2 改為 1。可以設為 0。服務層失敗沿用既有的退避參數。
3. **重試請求與第一次相同**：不附上次的原因（取消 ADR-064 決策 1 的附原因重試）；EXCHANGE 的重試紀錄照舊標示為重試。
4. **截斷**：回答被截斷時不重試；截斷前可用的內容照 WI-1473、WI-1474 採用。
5. **及早止損**：
   - 服務層失敗維持每次呼叫累計，門檻 `earlyStopFailures` 與預設不變；
   - 內容層面只在「整個片段取不到任何內容（沒有任何條目被採用）」時累計一次，片段只要取到任何一條就歸零；
   - 所以 `TRUNCATED` 不再單獨累計，也不再因兩個停不下來的片段就止損整個 run。
6. **角色表**：
   - 回答中的角色只有在名字是片中出現的專有名稱時標為有名字；描述性稱呼（例如「the woman with long dark hair」「the man」「a person in a white shirt」）一律標為無名字；
   - 翻譯請求的待翻譯名單與 `NAMES:` 的要求只包含有名字且尚無譯名的角色；
   - 摘要的全片提示詞改寫以說明這個區別，README 的引文與文件測試同步；
   - 既有 run 的角色表不轉換。
7. **紀錄**：log 與 RUN SUMMARY 標明各階段的重試次數、重試原因（服務層或空手而回）、止損時的連續失敗類型（服務層或整片段無內容）。
8. **重現情境**（假服務）：
   - 回答格式錯亂但有可取條目：不重試，呼叫次數與第一次相同；
   - 服務回 500：重試 1 次；
   - 整個回答沒有任何條目：重試 1 次，仍無則整個片段降級；
   - 連續多個片段回答都被截斷但各有可取條目：不止損；
   - 連續 5 個片段完全取不到內容：止損；
   - 描述性角色（「the man」）不出現在翻譯請求的待翻譯名單；真正的名字（「Tanaka」）出現。
9. 轉錄與其他階段的重試規則不變（ADR-059、ADR-061）。

## 架構約束

- 不改 Engine；不新增參數（`modelRetries` 預設值與語意改變，README 說明）；不改 schema。
- 嚴格 TDD；測試不使用 Stub 或 Mock。
- 測試範圍依 tdd-coder 定義的 §1.1，不跑全套。
- 部署時需處理的事：若 trigger 或 run 明確送了 `modelRetries`，行為隨之；預設值改變會影響所有未送此參數的 run。
- 回報時列出測試範圍與結果、jar 路徑與 sha256、提交。
