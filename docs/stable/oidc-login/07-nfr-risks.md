# 非功能性考量與風險

本文回答：OIDC 登入的安全威脅、失敗模式與容量，以及如何緩解。

## 安全威脅與緩解

| 威脅 | 緩解 |
|---|---|
| 登入 CSRF／授權碼注入 | state、nonce、PKCE；state 單次使用且短效 |
| Open redirect | 返回位置只接受本站相對路徑 |
| 跨站請求偽造（cookie 帶來的新風險） | `SameSite=Lax`、改狀態方法須 CSRF token 與 `Origin` 同源檢查；Bearer 請求不吃 cookie |
| 工作階段竊取 | 識別碼不透明、HttpOnly、`Secure`、資料庫只存雜湊；不放網址與 log |
| XSS 取憑證 | OIDC 登入下 JavaScript 沒有憑證（相對 token 登入的改善）；ADR-017 的 CSP 與純文字渲染維持 |
| 偽造或錯誤的 ID token | 驗簽、issuer、audience、到期、nonce；只信任探索文件宣告的金鑰 |
| 名稱冒用（改名後被他人取得舊名稱，繼承擁有權） | 名稱建立後不變、不釋放、衝突拒絕；使用者以 subject 識別 |
| 群組權限變更延遲、被停用者仍在使用 | 定期以 refresh token 重新驗證（預設 60 秒），收回即刪除工作階段；管理員可在 runline 立即停用使用者 |
| refresh token 外洩 | 加密後保存，金鑰由組態提供、不入資料庫；不出現在 log、trace、回應；工作階段刪除即一併刪除 |
| 任何 authentik 帳號進入 | 兩群組之外一律拒絕登入；authentik 端也限制 application 可見者 |
| client secret 洩漏 | 由組態或檔案提供，不入 log、trace、回應、版本庫 |

## 失敗模式與降級

- authentik 不可用：登入起點導回 Console 登入頁並帶 `login_error=provider_unavailable`（[ADR-031](adr/ADR-031-console-contract-alignment.md)）；已登入的工作階段在寬限時間內繼續有效，之後失效；token 呼叫繼續運作；Engine 啟動與就緒探測不受影響。寬限期內無法即時踢出被 authentik 收回權限的人，這是為可用性接受的取捨，管理員停用不受影響。
- 群組 claim 缺失：視為不屬於任何群組，拒絕登入並於 log 指出缺少 claim，方便維運排查。
- 資料庫不可用：登入與工作階段驗證失敗，與其他功能一致。

## 容量與效能

使用者數十人以內；每個 API 請求在工作階段認證下多一次以索引查詢的工作階段讀取（可忽略）；「最近使用時間」的更新須降頻（例如每分鐘最多一次），避免每個請求都寫入。重新驗證每個使用中的工作階段每間隔最多一次對 authentik 的呼叫（數十人約每分鐘數十次）；同一工作階段並行請求同時到期時只做一次。

## 可觀測性

登入成功、拒絕（含原因類別）、登出、名稱衝突各一筆 log（名稱與角色，不含 token 與識別碼）；計數器按結果類別；登入流程有 trace，換 token 呼叫的 span 不含機密。

## 風險

- 認證變成雙軌，路由漏掛檢查的風險：以列舉所有路由的測試驗證每個端點在兩種來源下的行為（沿用 ADR-012 的測試原則）。
- 與 ADR-017 的衝突：由 ADR-029 明確取代；ADR-012、ADR-017 的文字在工作項完成前仍描述現行行為。
- 登出只結束 runline 的工作階段，使用者仍可能在 authentik 保持登入，點登入即無提示登入。這是已接受的行為。
