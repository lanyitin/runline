# WI-1470 降級完成的 run 可以當續跑的來源

本文回答：續跑的來源 run 接受哪些狀態，降級的單位如何處理，以及續跑時的參數傳遞。狀態：已核可（2026-10-15）。相依：WI-1467、WI-1468（都已完成）。決策見 [ADR-066](../adr/ADR-066-degraded-run-can-be-resumed.md)。儲存庫：T。

## 行為與驗收條件

1. **來源狀態**：`resumeFromRun` 指向失敗、中斷、success-degraded 的 run 時通過驗證；指向完全成功（沒有降級）的 run 時，在 `intake` 以設定類失敗結束，訊息指出該 run 沒有降級、要重做請送一般 run；其餘驗證（run 存在、起點之前的階段資料完整、影片仍在且為同一支、未被保留規則清除）與訊息維持。
2. **降級單位視為未完成**：起點階段中，下列單位在續跑時重做：
   - 整個單位降級而沒有採用任何內容的（轉錄沒有取得文字的片段，潤飾、摘要、翻譯整個片段退回上一階段文字的場景片段）；
   - 部分採用的片段中，不合格而退回上一階段文字的條目（翻譯與潤飾）。
   已完成且品質沒有降級的單位照常沿用。沿用與重做的單位數照常顯示。
3. **起點之前的階段**：降級的單位照常取用，不重算；要重做它們，起點設在該階段。log 與 RUN SUMMARY 在這種情況下顯示來源 run 在起點之前階段的降級數，說明這些降級被沿用。
4. **參數**：續跑 run 沒有送出的參數，使用目前 jar 的預設值，不從來源 run 繼承（Engine 的行為）；起點之前階段的專屬參數仍取自來源 run（沿用 WI-1467）。log 的 RESUME 行列出「與目前預設值不同而被固定的參數名稱」與「續跑 run 實際採用的、與預設值不同的參數名稱」，只列名稱。
5. **文件**：README 的續跑章節寫明：來源狀態、降級單位的處理、只送要變更的參數、不要整份重送來源 run 的參數（尤其各階段的 system prompt）、完全成功的 run 不可續跑；錯誤訊息的排錯對照更新；文件測試維持相符。
6. **重現情境**（假服務與真實資料庫）：
   - success-degraded 的來源在翻譯起點續跑：降級的片段與條目重做、其餘沿用，且前面階段的模型呼叫為 0；
   - 部分條目採用的片段，採用的條目沿用，不合格條目重做；
   - 完全成功的來源被拒絕，訊息如條件 1；
   - 沒送 system prompt 參數時使用 jar 的預設值，不使用來源 run 記錄的值；
   - 起點之前階段有降級時，被取用並在 RUN SUMMARY 顯示；
   - 來源 run 前後不變。
7. 其餘行為（WI-1467 的各條件、各階段規則）不變。

## 架構約束

- 不改 Engine；不新增參數；不改 schema（如需持久化新資訊，先回報）。
- 嚴格 TDD；測試不使用 Stub 或 Mock。
- 測試範圍依 tdd-coder 定義的 §1.1，不跑全套；T 現有並行與 measurementTest 設定（WI-1469）。
- 回報時列出：判定「降級單位」的資料來源（用哪些既有紀錄判斷，不需新增欄位則說明）、README 的更新、測試範圍與結果、jar 路徑與 sha256、提交。
