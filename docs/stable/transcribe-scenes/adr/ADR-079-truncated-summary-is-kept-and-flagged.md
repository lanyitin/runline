# ADR-079 被截斷的摘要照常保存，並告知讀取它的下一層

本文回答：摘要因生成上限被截斷（`finish_reason` 為 `length`）時如何保存，以及讀取它的下一層模型如何得知它不完整。狀態：已核可（2026-10-18）。補充 [ADR-069](ADR-069-accept-what-can-be-used.md) 決策 3、6（摘要的寬鬆解析），並修訂 [06 資料模型](../06-data-model.md) 的 SEGMENT_SUMMARY 與 SCENE_SUMMARY（06 的對齊在實作完成後另行修訂）；與 stable 的採用原則沒有衝突。

## 背景

- ADR-069 決策 3：回答被截斷時，截斷前已完整的部分採用，其餘降級；決策 7：被截斷不重試。
- 摘要被截斷時照此被保存為正式摘要。run 38 場景 30 的摘要即如此：它含四個欄位，後面接著未寫完的自言自語，被存入場景摘要，並進入全片摘要第一批彙整的輸入（[報告](../summary-leak-experiment-report.md)）。
- 讀取摘要的下一層（場景彙整、全片摘要、翻譯語境）沒有任何線索知道這段是被截斷的，會把它當成完整可信的內容。

## 決策

1. **照常保存**：被截斷的摘要採用，不重試（沿用 ADR-069）。
2. **記錄被截斷**：片段摘要與場景摘要各有「被截斷」屬性，與「是否缺少」並列。判斷方式：
   - 欄位固定的層（場景層與中間彙整，四個欄位）：結束原因為截斷，且四個欄位沒有全部完整時才標為被截斷；四個欄位都完整時不標示（缺的只是欄位之後的多餘文字，依 [ADR-080](ADR-080-summary-degradation-conditions.md) 裁掉）；
   - 散文層（片段層，沒有欄位可依據）：結束原因為截斷即標為被截斷。
3. **告知下一層**：任何請求在輸入中包含被截斷的摘要時，pipeline 在該段摘要旁以一句簡短、平實的話標明「這段摘要被截斷，可能不完整」；標示由 pipeline 加上，不依賴模型是否在回答中說明。適用於：
   - 場景層以片段摘要為輸入；
   - 場景彙整與全片摘要以場景摘要為輸入；
   - 翻譯附上的場景摘要。
4. **提示的對應規範**：接收摘要的各層提示說明，帶有「被截斷」標示的輸入只可使用其中明確寫出的內容，不推測缺少的部分，也不在回答中提到截斷。
5. **可觀測**：階段結果行與 RUN SUMMARY 列出各層被截斷的摘要數；HTML 報告顯示該摘要被截斷。
6. **不計入及早止損**：摘要被截斷不累計連續失敗（與轉錄一致，[ADR-059](ADR-059-truncated-chunk-is-content-not-outage.md)）。

## 取捨

- 得到：下一層不再把殘缺的內容當成完整；使用者從報告就能找出被截斷的摘要；不增加模型呼叫。
- 失去：
  - 資料模型多一個屬性，舊 run 沒有這個屬性（視為未被截斷）；
  - 標示靠提示規範遵守，小模型可能忽略或在回答中提到「truncated」；
  - 散文層的被截斷摘要可能含殘留的自言自語，無欄位可裁，只能被標示。
