# WI-1303 digest-rss 的 view：下載了哪些、沒下載的原因

本文回答：digest-rss 在 Console 要能回答哪些問題。狀態：已核可（2026-10-11）。相依：WI-1300；實機驗收需 WI-1302。儲存庫：runline-digest-rss（若需 runline 文件對照，另回報）。

## 背景

使用者要在 Console 看到「目前為止下載了哪些」與「哪些沒下載、原因為何」。資料已由 `https://forgejo.dev.lan/runline/runline-digest-rss/src/branch/main/docs/stable/digest-rss/06-data-model.md` 的 RUN_POST、VERDICT、DOWNLOAD 記錄；runbook 第 8 節已有對應的 SQLite 查詢，可作為行為參考，不是要複製的內容。

## 行為與驗收條件

宣告以下 view，掛在 `database` 角色。第一版只含清單、處置與原因，不含引文、模型對話、封面、下載連結。

1. **下載清單**：每篇已派發的文章一列：標題、派發時間、目標服務（rqbit／streamexa）、種類、結果（成功／失敗／結果未知）、嘗試次數、錯誤摘要。依時間由新到舊。
2. **未下載與原因**：每篇文章以其最近一次 run 的處置為準，列出所有沒有成功下載者：標題、最近看到的時間、原因類別、原因說明。原因類別至少區分：
   - 不符條件（過濾）；
   - 被拒絕（引文驗證未通過，說明含拒絕原因）；
   - 擷取失敗、文字不足、整頁截圖、隔離中、讀者未處理；
   - 保留但沒有可下載的連結（feed 與頁面都沒有 torrent／magnet）；
   - 已派發但失敗；已派發但結果未知。
   原因類別以狀態欄呈現並有語氣（失敗類為負面，過濾為中性）；可用類別篩選。
3. **run 清單**：每次 run 一列：開始與結束時間、結果與結果說明、抓到／保留／過濾／下載成功／下載失敗的數量；可鑽取到下一項。
4. **某次 run 的文章**：參數為 run；每篇一列：順序、標題、處置或未處理原因、下載結果。
5. 「保留但沒有可下載的連結」必須能與「下載失敗」區分。先驗證現有紀錄是否足以區分（待確認問題 1）；若不足，在 pipeline 自己的資料模型中補記原因（結構演進須前向、冪等，於 run 開始時套用，並記錄結構版本），並在回報中說明改動。不得靠推測歸類。
6. 所有 view 的查詢只讀；不選取下載連結欄位（連結可能帶金鑰）。
7. 以 pipeline 自己建立的結構與有代表性的資料驗證每個 view 回傳正確的列與原因；涵蓋上列每一種原因類別至少一筆。測試不使用 Stub 或 Mock；`ThinJarTest` 與既有測試通過，jar 仍符合薄 jar 約束。
8. README 與 runbook 說明這些 view 取代哪些手動查詢；runbook 位於 runline 儲存庫，若需修改，回報需要修改的項目由架構師另立工作項，不在本項中改動。

## 架構約束

- view 宣告只描述資料，不在 pipeline 的 main 中新增 Engine 或 Console 相依。
- 原因類別名稱在宣告中穩定，之後改名視為破壞性變更。
- 資料保留策略不變：清除只影響體積大的原始資料，處置與原因欄位長期保留，因此歷史清單不受清除影響。
