# ADR-063 以新 run 從指定階段續跑

本文回答：失敗或中斷的 run 如何不重做已完成的工作，而從指定的階段重新開始。狀態：已核可（2026-10-15）。取代 [transcribe-pipeline 01 假設 7](../../transcribe-pipeline/01-requirements.md) 與 [07 第 40、48 行](../../transcribe-pipeline/07-nfr-risks.md) 的「不續跑」，以及 [transcribe-scenes 01](../01-requirements.md) 範圍外的「中斷後續跑」。Engine 的「中斷後不自動重跑」（pipeline-engine 04）不變。

## 背景

- run 7bbe6aff 花約 1.5 小時完成摘要，在翻譯階段觸發及早止損而失敗。前面各階段的結果都已寫入 `transcribe.db`，但現行只能重送整個 run，全部重做。
- LLM 的輸出不穩定，同一階段重做很可能成功；失敗的代價不該是整條 pipeline 的時間。
- 音訊與畫面不保存，只有文字、時間與模型回答留在資料庫。

## 決策

1. **以新 run 續跑，來源 run 不動**。續跑是 pipeline 層的功能，不改 Engine。新 run 以關聯欄位指向來源 run；來源 run 的狀態與資料不因續跑而改變。
2. **觸發**：只有手動 run 與 webhook，帶兩個參數：來源 run 與起點階段。掃描模式不自動續跑。
3. **任一階段都可當起點**。資料取用規則：
   - 起點之前的階段：取用來源 run 的結果，不呼叫模型。
   - 起點階段：以單位延續（轉錄與對齊以片段為單位；潤飾、摘要、翻譯以場景片段為單位），已完整完成的單位沿用，其餘重做。
   - 起點之後的階段：一律重新計算，不取用來源 run 的結果。
4. **音訊與畫面按需重新取得**：起點階段或之後的階段需要時，從影片檔重新抽取；來源影片須仍在收件根目錄。
5. **參數**：起點之前的階段的參數固定取自來源 run，不可覆寫（資料與參數須一致）；起點與之後階段的參數可覆寫。沿用的單位是用舊參數產生的，log 與 view 標明。
6. **驗證**：`intake` 階段檢查來源 run 存在、為失敗或中斷、起點之前各階段的資料完整、尚未被保留規則清除、影片檔仍在。任一不符以設定類失敗說明原因，不回顯路徑。
7. **續跑失敗的 run 可再續跑**。

## 取捨

- 得到：失敗不再等於重做；來源 run 的失敗證據保留；可在續跑時調整後段的參數。
- 失去：
  - 跨 run 讀取資料，需要新的關聯欄位（schema 升版，只向前遷移）。
  - 起點之後一律重算：例如從潤飾續跑，已成功的摘要與翻譯也丟棄，成本較高；沿用不受影響的單位需要依賴追蹤，第一版不做。
  - 沿用的單位用舊模型與舊參數產生，可能與覆寫後的新參數不一致；以標明緩解。
- 不採用：
  - 在同一個 run 列上重開階段：與 Engine「一次執行一個 run」的語意衝突，失敗證據會混在一起。
  - 只強化翻譯階段的耐用度：不解決已失敗的 run，放寬及早止損也浪費時間。
